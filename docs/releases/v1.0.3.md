# PersonaLink MySQL v1.0.3 发布说明

发布日期：2026-09-08

## 修复内容

Ubuntu 24.04 默认 Nginx 配置可能已经在 `http` 级别声明 `gzip on`。v1.0.2 发布脚本另行安装的 `/etc/nginx/conf.d/personalink-gzip.conf` 再次声明 gzip 时，`sudo nginx -t` 会报告 `gzip directive is duplicate`，并在发布步骤 `[8/9]` 安全停止。

v1.0.3 把该文件改为无 Nginx 指令的兼容占位文件。这样已经安装在服务器上的 v1.0.2 发布脚本仍可从新标签复制该文件并消除重复声明；实际压缩继续由项目站点 `nginx.conf` 管理。

CI/CD 使用的 GitHub 官方 checkout、Node.js 设置和构建产物上传组件也已更新到 Node.js 24 运行时版本，消除旧 Action 的 Node.js 20 弃用提示。

## 数据安全

- 没有数据库结构变更，不需要建表或迁移。
- 不执行 `db:migrate-json`、`db:schema`、`DELETE`、`DROP` 或 `TRUNCATE`。
- 2026-09-08 生产现场从旧版升级至 v1.0.2 后，升级前后 11 项数据库清单一致：7 个班级、89 个账号、88 名学生、50 份已存头像及 1,505,310 字节头像数据全部保留。
- 照片墙列表实测 HTTP 200、37,509 字节、0.022 秒，低带宽修复已生效。

## 从 v1.0.2 升级

在低使用时段逐行执行：

```bash
# 进入项目并确认没有服务器本地代码修改。
cd /srv/personalink
git status --short

# 获取固定标签；发布脚本会先备份并比对 MySQL。
git fetch --tags origin
sudo /usr/local/sbin/deploy-personalink-release v1.0.3
```

## v1.0.2 现场失败后的处理

如果已经看到 gzip duplicate 错误，可恢复地停用旧附加文件后完成当前服务启动：

```bash
# 改名保留旧文件，不删除数据或配置。
sudo mv /etc/nginx/conf.d/personalink-gzip.conf /etc/nginx/conf.d/personalink-gzip.conf.disabled

# 配置通过后再重启后端和重载 Nginx。
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl restart personalink
sudo systemctl reload nginx
curl -fsS http://127.0.0.1:3003/health && echo
curl -fsS http://127.0.0.1:3003/api/version && echo
```
