# PersonaLink MySQL v1.0.4 发布说明

发布日期：2026-09-08

## 主要变化

- 新增只读生产巡检脚本 `scripts/check-production.sh`。
- 发布时自动安装为 `/usr/local/sbin/check-personalink`。
- 一次检查 `personalink`、Nginx、MySQL、Nginx 语法、运行版本、数据库清单以及本机和公网照片墙响应。
- Ubuntu 部署教程收录真实的旧版照片墙超时、gzip duplicate、安全恢复和零丢数据升级过程。
- 当前站点继续使用 HTTP；本版本不配置或强制启用 HTTPS。

## 数据影响

没有数据库结构和业务数据变更，不需要运行任何迁移命令。部署仍会先生成 MySQL 四件套备份，并比较升级前后 11 项数据清单。

禁止在已有生产数据的服务器执行：

```bash
npm run db:migrate-json
npm run db:schema
```

## 部署

```bash
# 进入项目并确认工作区无输出。
cd /srv/personalink
git status --short

# 获取固定版本并执行安全发布。
git fetch --tags origin
sudo /usr/local/sbin/deploy-personalink-release v1.0.4
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`git` 管理版本；`status` 查看改动；`diff` 查看逐行差异；`add` 选择待提交文件；`commit -m` 创建本地版本并写说明；`push` 发到远端；`clone` 下载仓库，`--branch` 选择分支，`--single-branch` 只取该分支历史；`remote` 管理远端别名，`fetch` 只取回记录。命令中的 `.` 表示当前目录，`--` 后面是文件路径。推送前用 `git remote -v` 核实 origin 是自己的仓库。

`cd` / `Set-Location` 切换终端当前目录；含空格的路径用引号包起来。CMD 的 `/d` 同时切换盘符；PowerShell 用 `Set-Location "路径"`，不加 `/d`。
