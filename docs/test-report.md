## 6. 安全性说明

旧报告中的“密码加密存储”“会话管理”和“SQL 注入防护”表述不准确，现修正如下：

- 当前教学数据保存在 `backend/db.json`。
- 注册用户密码目前以演示方式写入数据文件，代码中也明确注明生产环境应加密；不能把它视为安全的密码存储。
- 前端登录状态保存在浏览器 `localStorage` 中，当前没有完整的 Session/JWT 认证体系。
- 项目使用 JSON 文件，不涉及 SQL 查询，因此不能据此宣称已经完成 SQL 注入防护。
- 部分接口会在响应中移除密码字段，但这不等于数据库和传输链路已经安全。

因此，本项目适合学习和本地演示，不应直接暴露到公网作为生产系统。正式上线前应增加密码哈希、可靠的 Session/JWT、正式数据库、HTTPS、环境变量、输入校验、限流、日志、备份和权限审计。

## 7. 已知问题与改进建议

### 已知问题

1. 历史 API 记录与当前根路径实现不一致，需要重新测试。
2. 历史性能数据的内容大小测量方法不够明确，部分值可能是固定显示值。
3. JSON 文件不适合多人并发写入、事务处理和生产级备份恢复。
4. 演示账号和固定管理员密码不适合公开部署。

### 建议

1. 为 `GET /` 保留简短健康检查响应，并在测试中记录状态码和响应时间。
2. 使用浏览器 Performance、Network 和 Memory 面板重新采集性能数据。
3. 增加自动化 API 测试和前端关键流程测试。
4. 增加分页、输入校验、细粒度权限、统一错误码和更友好的错误提示。
5. 迁移到正式数据库，使用密码哈希和可靠登录会话。
