# 同一个工程如何进入下一课

Windows CMD/PowerShell通用，位置自己的项目根目录。先关闭网页和API终端；保留已完成的个人代码。

```text
git status
git add .
git commit -m "保存进入下一课之前的成果"
```

status查看当前变化，add暂存，commit保存。本来没有变化时nothing to commit正常。确认工作区干净后，按下一课PPT使用git apply --check检查准确的补丁路径，然后git apply应用。

补丁由上一课完整参考成果生成，只改新增架构和下一课任务位置，不包含.env、数据库、依赖目录或自己的额外文件。个人改动触及相同行时可能冲突，因此检查失败必须停止，不使用覆盖复制解决。

失败时：VS Code同时打开个人工程和下一课starter；终端错误指出哪个文件、哪一行不匹配。先git diff自己的提交了解个人变更，再按补丁（可在VS Code打开.patch）逐个移植新增文件与代码。复制新增文件前确认个人工程没有同名文件；已有文件逐段修改。保留自己的文章、成员资料、主题和.env。教师用自己的副本演示这一步。

应用成功后npm.cmd ci重新安装，运行网页、完成两项任务、测试、构建，再commit和push。不要复制下一课的.git（资源本身不含.git）。补丁第一次应用成功后，不重复应用同一补丁。

新项目第12、14、15课各建立自己的p3-work/p4-work/p5-work，不对博客仓库反复初始化。同一项目每课使用同一仓库与同一部署网址。
