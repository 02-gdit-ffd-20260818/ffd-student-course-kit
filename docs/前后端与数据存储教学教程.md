# 从页面到数据：PersonaLink 前后端与数据存储教学教程

这份教程不要求你预先懂 Vue 或 Node.js。目标是看懂：用户点击“注册”后，数据怎样从页面到后端，再写入 `db.json`，最后怎样回到页面。

## 1. 先用一句话区分前端、后端与数据库

| 部分 | 在哪里运行 | 主要职责 | 本项目对应内容 |
| --- | --- | --- | --- |
| 前端 | 用户浏览器 | 显示界面、收集输入、发起请求、展示结果 | `frontend/`，Vue 3 + Vite |
| 后端 | Node.js 进程 | 接收请求、校验规则、读写数据、返回结果 | `backend/`，Express |
| 数据存储 | 文件或数据库服务 | 长期保存用户、班级等业务数据 | `backend/db.json` |

前端不是“数据库界面”，后端也不是“看得见的页面”。前端负责体验，后端负责业务规则和数据。它们通过 HTTP 请求交换 JSON 数据。

```text
浏览器中的 Vue 页面
        |  HTTP 请求（JSON）
        v
Node.js + Express 后端
        |  读取 / 写入
        v
backend/db.json
```

## 2. 本项目用了哪些前端技术

### Vue 3：把页面拆成组件

`frontend/src/views/` 是页面，例如 `Login.vue`、`Register.vue`、`PhotoWall.vue`。一个 `.vue` 文件通常由三部分组成：

- `<template>`：HTML 结构，例如输入框、按钮、列表。
- `<script setup>`：数据与事件处理，例如点击注册时调用函数。
- `<style scoped>`：只作用于当前组件的样式。

例如注册页用 `v-model="form.email"` 把输入框和 JavaScript 变量双向绑定：用户输入邮箱，`form.email` 自动更新；代码改 `form.email`，输入框也会更新。

### Vite：前端开发与构建工具

`frontend/package.json` 中：

```json
"dev": "vite",
"build": "vite build"
```

`npm run dev` 启动开发服务器，默认端口是 `3000`；`npm run build` 把 Vue 代码打包成浏览器可以直接加载的静态文件，输出到 `frontend/dist`。

### 读懂 npm 命令：依据是 `package.json`

> **`ci` = clean install；`dev` = development。** 完整的命名缘由、历史约定和学生排错卡片见 npm 命令词典与命名故事。

`npm start`、`npm run dev` 不是两种“前后端专用语法”，而是执行当前目录 `package.json` 中定义的脚本。`start` 是 npm 允许省略 `run` 的惯例写法，所以下面两句等价：

```bash
npm start
npm run start
```

本项目的前端定义了 `dev`、`build`、`preview`，所以开发时执行 `npm run dev`；后端定义了 `start: node server.js` 和 `dev: nodemon server.js`，所以普通启动执行 `npm start`。`nodemon` 会监视后端文件并自动重启，适合频繁修改接口时使用 `npm run dev`。

`npm ci` 中的 `ci` 是 **clean install**。它严格按 `package-lock.json` 安装并重建依赖目录，适合课堂、CI、测试和部署；若你正在添加依赖，例如 `npm install axios`，才使用 `npm install`，因为它会更新 `package.json` 和锁文件。脚本名称可以自定义，但必须在 `package.json` 中定义，不能脱离配置任意使用。

### Vue Router：切换单页应用页面

`frontend/src/router/index.js` 定义 `/login`、`/home`、`/photo-wall` 等路径。页面切换发生在浏览器内，不代表每次都向后端下载一张新 HTML 页面。

### Pinia：管理多个页面共享的状态

`frontend/src/stores/user.js` 保存当前用户、登录状态和用户相关操作。登录成功后，`setUser()` 既更新内存中的状态，也写入浏览器的 `localStorage`，因此刷新页面后还能恢复登录显示。

> `localStorage` 是浏览器本地存储，不是项目数据库。它只保存该浏览器的数据，不能代替后端的用户数据。

### Axios：由前端发送 HTTP 请求

`frontend/src/utils/api/request.js` 创建了统一的 Axios 客户端：设定 API 基地址、10 秒超时、JSON 请求头，并统一处理成功与失败结果。业务页面不需要重复写 `fetch` 或完整地址，只通过封装函数调用即可。

## 3. 本项目用了哪些后端技术

### Node.js：让 JavaScript 运行在浏览器之外

浏览器中的 JavaScript 不应直接随意读写服务器文件；Node.js 让 JavaScript 能在服务器/本机进程中运行。`backend/server.js` 是启动入口，默认监听 `3003` 端口。

### Express：把 URL 对应到业务函数

Express 用“路由”处理不同请求：

```js
app.use('/api/users', userRoutes)
app.use('/api/classes', classRoutes)
app.use('/api/photowall', photoWallRoutes)
```

这表示访问 `/api/users/register` 时，Express 会交给 `backend/routes/users.js` 处理；班级、照片墙、同义词也各自分文件，避免所有代码堆在 `server.js`。

### 中间件：请求到路由前的公共处理

`server.js` 中的 `express.json({ limit: '10mb' })` 会把 JSON 请求体解析到 `req.body`。`cors()` 允许浏览器跨来源请求；`adminAuth` 则是管理员接口的教学验证中间件。

### 业务规则必须由后端复核

注册页虽然在前端要求选择班级，但 `POST /api/users/register` 仍会检查 `classId` 是否为空、班级是否存在、邮箱是否重复。原因是前端只能改善体验；请求可以被浏览器开发者工具或其他程序伪造，核心规则不能只写在前端。

## 4. 前端如何连接后端

严格说，前端不会“连接到一个后端程序对象”，而是对后端 URL 发送 HTTP 请求；后端返回 HTTP 响应。

### 开发环境中的地址

`frontend/src/config/api.js` 的真实规则是：

```js
// 本机浏览器访问时
API_BASE_URL = 'http://localhost:3003/api'
```

因此 `userService.loginUser(email, password)` 最终请求：

```text
POST http://localhost:3003/api/users/login
Content-Type: application/json

{ "email": "admin@system.com", "password": "admin123" }
```

`frontend/vite.config.js` 还配置了 `/api` 到 `http://localhost:3003` 的开发代理。这对直接写相对地址的请求有效；当前 API 配置在本机已直接使用 `3003`，两种方式共同说明开发时前端 `3000`、后端 `3003` 是两个独立服务。

### 前端请求的四个步骤

以注册为例：

```text
Register.vue 的 handleRegister()
  -> userStore.register(form)
  -> userService.registerUser(form)
  -> request.js 的 post('/users/register', form)
  -> Axios POST 到 /api/users/register
```

Axios 收到成功响应后，`request.js` 只返回 `response.data`，页面不必每次写 `response.data.data`。失败时，拦截器把网络错误或后端的 `message` 转成页面可显示的错误。

## 5. 后端如何“连接前端”

后端通常不会主动打开或控制浏览器。常见的请求/响应模式是：**前端先请求，后端根据请求返回数据**。

```text
前端：POST /api/users/register + 表单 JSON
后端：验证 -> 写入数据 -> HTTP 201 + 用户 JSON
前端：收到 JSON -> 更新 Pinia -> router.push('/profile')
```

在本项目中，`res.json(...)` 就是后端把 JSON 回给前端的动作；`res.status(400).json({ message: '...' })` 表示规则不通过，前端应显示错误，不应当作成功。

如果将来需要后端主动推送消息，可以使用 WebSocket、SSE 或轮询，但这些技术当前项目没有使用。

## 6. 数据库如何连接：本项目的真实情况

本项目**没有 MySQL、MongoDB、SQLite 等独立数据库服务**。当前用的是 JSON 文件存储，代码位于 `backend/db.js`：

```text
connectDB()
  -> fs.readFileSync('backend/db.json')
  -> JSON.parse(...) 得到 data
  -> 路由修改 data.users / data.classes
  -> db.write() 用 fs.writeFileSync(...) 写回文件
```

所以“连接数据库”在本项目里更准确地说是“读写 JSON 数据文件”。`db.json` 主要包含：

- `users`：用户、密码、班级 ID、资料、头像等。
- `classes`：班级名称、教师、描述等。
- `synonymGroups`：同义词组。

### 真实注册写入流程

1. 后端路由读取 `req.body` 中的姓名、邮箱、密码和 `classId`。
2. `connectDB()` 读取当前 `db.json`。
3. 检查邮箱是否重复、班级是否存在。
4. 用 `uuid` 创建用户 ID，追加到 `data.users`。
5. 调用 `await db.write()` 将整个 JSON 写回磁盘。
6. `formatUserData()` 移除 `password`，再将安全的用户信息返回给前端。

## 7. 把整条链路走一遍：管理员新增用户

```text
管理员在 UserManagement.vue 填写姓名、邮箱、班级
  -> userStore.createUserByAdmin()
  -> userService.createUserByAdmin()
  -> POST 请求携带管理员教学凭据和用户资料
  -> routes/users.js 的 POST /admin/create
  -> adminAuth 校验 -> connectDB() -> 写入 users -> db.write()
  -> formatUserData() 去除密码 -> 返回 201 JSON
  -> Store 刷新用户列表 -> Vue 自动更新用户卡片
```

这就是“前端调用后端、后端处理数据、后端返回前端”的完整闭环。照片墙、班级管理和同义词管理都遵循同一思路，只是 URL、数据和规则不同。

## 8. 部署后地址为什么会变化

开发时用 `localhost:3000` 和 `localhost:3003`。部署后，前端的 `VITE_API_BASE_URL` 可以配置为后端公开地址；未配置时，`api.js` 会使用当前网站同域的 `/api`，适合 Nginx 反向代理。

```text
浏览器 -> https://example.com
          /api/users/login
              -> Nginx 转发 -> Node.js:3003
```

GitHub Pages 只能部署静态前端，不能运行 `server.js` 或写入 `db.json`，所以不能单独承载这个项目的完整功能。详细部署边界见 [GitHub 部署指南](./GitHub部署指南.md)。

## 9. 当前项目的安全与扩展方向

为了教学可读性，当前实现有明确边界：密码和管理员验证仅适合演示，JSON 文件不适合高并发，照片墙班级限制还不是 Token 级后端授权。

当项目需要多人真实使用时，可按顺序升级：

1. 使用 bcrypt 哈希密码；不再保存明文密码。
2. 登录成功后签发 Session 或 JWT；每次请求在后端验证身份。
3. 在照片墙、资料等路由中根据令牌内的用户和班级做授权，而不是信任浏览器传参。
4. 将 JSON 文件替换为 MySQL/PostgreSQL/MongoDB 等数据库；通过连接字符串、连接池和 ORM/查询语句访问。
5. 增加环境变量、HTTPS、输入校验、日志、限流和备份。

## 10. 建议的学习顺序

1. 启动前后端，先亲自注册一个测试用户。
2. 打开浏览器开发者工具 Network，观察 `/api/users/register` 请求和响应。
3. 对照 `Register.vue`、`stores/user.js`、`utils/api/userService.js`、`routes/users.js` 阅读。
4. 打开 `backend/db.json`，找到刚注册的数据；理解它是如何被写入的。
5. 再阅读 `PhotoWall.vue` 与 `routes/photowall.js`，练习追踪另一条请求链路。

完成后，你应该能回答：页面为何需要 Store、为什么后端还要验证、HTTP 请求是什么、以及本项目的“数据库”实际是什么。
