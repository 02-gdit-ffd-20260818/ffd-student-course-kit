# PersonaLink 功能说明

本文只记录当前代码已经实现的能力和边界，不把规划当成功能。

## 用户与资料

| 功能 | 使用者 | 实现位置 |
| --- | --- | --- |
| 注册、登录、退出、资料编辑与头像保存 | 普通用户 | `Register.vue`、`Login.vue`、`Profile.vue`、`routes/users.js` |
| 注册时选择班级 | 新注册用户 | 前端 `required`；后端 `POST /api/users/register` 二次校验 |
| 用户搜索、详情查看 | 登录用户 | `Search.vue`、`UserDetail.vue`、`POST /api/users/search` |
| 班级内照片墙 | 普通用户 | `PhotoWall.vue` 请求 `GET /api/photowall/class/:classId` |

照片墙在正常 UI 流程中只加载当前登录用户的 `classId` 对应成员；未分配班级的用户会看到提示而非其他班数据。悬停图片会放大卡片及图片本身，且不再覆盖白色高光层。

## 管理员

管理员账号为教学数据中的 `admin@system.com / admin123`。管理员可在页面中：

- 新建、编辑、删除空班级；有成员的班级不能删除。
- 添加用户（姓名、邮箱、班级必填；初始密码 `123456`）。
- 删除普通用户。
- 将普通用户密码强制重置为 `123456`。
- 查看全部照片墙或按班级筛选；管理同义词组。

新增用户、重置密码分别对应 `POST /api/users/admin/create` 和 `PUT /api/users/admin/reset-password/:email`。

## 数据与已知边界

- 数据写入 `backend/db.json`；重启服务后数据仍在，但不适合并发或生产数据。
- 密码是教学用明文/演示兼容逻辑，管理员校验也不是 Token 鉴权。
- 因此“照片墙按班显示”是当前应用界面的访问规则，不是抵御恶意直接调用 API 的安全隔离。生产环境须加入 HTTPS、密码哈希、登录令牌、后端授权校验和数据库。
- 图片头像以 Base64 写入 JSON，适合少量教学数据，不适合大文件或大量用户。
