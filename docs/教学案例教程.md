# PersonaLink 教学案例教程

> 看见 `npm ci`、`npm start`、`npm run dev` 时不要死记：先看 npm 命令词典与命名故事，理解 **ci = clean install**、**dev = development** 和 `package.json` 脚本。

这份教程帮助初学者理解 PersonaLink 的代码组织方式。建议先根据 [GitHub 拉取与部署指南](./GitHub部署指南.md) 启动前后端，再边操作边阅读；只看目录名称而不运行项目，通常不容易建立整体认识。

## 1. 先启动项目

项目需要两个终端：一个运行后端，一个运行前端。下面命令从项目根目录开始执行。

### 终端一：后端

```bash
# 进入后端代码目录
cd backend

# 按锁文件安装依赖；ci = clean install，适合首次安装和部署
npm ci

# 启动 Express 服务，默认地址为 http://localhost:3003
npm start
```

### 终端二：前端

```bash
# 新开一个终端后，从项目根目录进入前端目录
cd frontend

# 按锁文件安装前端依赖
npm ci

# 启动 Vite 开发服务器，默认地址为 http://localhost:3000
npm run dev
```

这里的几个命令可以这样理解：`cd` 是切换目录，`npm ci` 是根据 `package-lock.json` 安装依赖，`npm start` 和 `npm run dev` 是执行各自 `package.json` 中定义的脚本。代码块里的 `#` 行只是说明文字。

## 2. 一次请求是怎样完成的

以“用户登录”为例，完整链路如下：

```text
用户填写表单
  -> Login.vue 页面收集邮箱和密码
  -> userStore.login() 更新登录状态
  -> userService.loginUser() 组织 API 请求
  -> request.js / Axios 发送请求
  -> Express 的 /api/users/login 路由处理
  -> backend/db.js 读取或写入 backend/db.json
  -> 后端返回 JSON
  -> Store 保存结果，页面重新渲染
```

理解这条链路后，遇到问题可以按顺序排查：页面有没有发请求、请求地址是否正确、后端路由是否存在、数据文件是否能读取、响应状态码是什么。

## 3. 前端阅读方法

### 3.1 入口和页面：`frontend/src/main.js`、`frontend/src/App.vue`、`frontend/src/views`

`main.js` 是 Vue 应用入口，通常负责创建 Vue 实例、注册 Pinia 和路由。`App.vue` 是页面外层容器。具体页面放在 `views` 目录，例如：

- `Login.vue`：登录表单，收集邮箱和密码。
- `Register.vue`：注册表单，并加载班级列表。
- `Home.vue`：登录后首页。
- `PhotoWall.vue`：用户照片墙。
- `Search.vue`：用户搜索。
- `Classes.vue`、`UserManagement.vue`、`SynonymManagement.vue`：管理员功能。

阅读页面时，先找模板中的按钮和表单，再找它们绑定的 `@click`、`@submit` 或方法，最后沿着方法调用找到 Store 和 Service。

### 3.2 状态层：`frontend/src/stores`

Pinia Store 用来保存跨页面需要共享的数据：

- `user.js`：当前用户、登录、用户查询和用户管理。
- `class.js`：班级列表和班级管理。
- `synonym.js`：同义词管理。

例如，登录成功后用户信息会进入 `user.js`，路由守卫和其他页面就可以读取登录状态。修改 Store 时要注意：状态改变可能会同时影响导航、权限和页面显示。

### 3.3 请求层：`frontend/src/utils/api`

`request.js` 统一封装 Axios，`userService.js`、`classService.js` 和 `synonymService.js` 按业务拆分接口。页面不直接拼接请求地址，便于维护和测试。

开发环境中的 Vite 会把前端的 `/api` 请求代理到 `http://localhost:3003`，配置位于 `frontend/vite.config.js`。因此页面代码通常只需要请求 `/api/...`，不需要把 `localhost:3003` 写死在每个组件中。

### 3.4 路由层：`frontend/src/router/index.js`

路由定义页面地址，例如 `/login`、`/home`、`/photo-wall` 和 `/search`。全局导航守卫检查登录状态和管理员权限：

- 未登录用户不能直接访问需要登录的页面。
- 普通用户不能访问管理员页面。
- 登录后访问根路径 `/` 会跳转到登录页。

后端仍然必须再次校验权限，不能只相信前端的路由守卫，因为浏览器中的前端代码和请求都可以被用户修改。

## 4. 后端阅读方法

### 4.1 服务入口：`backend/server.js`

`server.js` 完成几件事：

1. 创建 Express 应用。
2. 注册 CORS、JSON 请求体解析等中间件。
3. 挂载 `/api/users`、`/api/classes`、`/api/photowall` 和 `/api/synonyms` 路由。
4. 连接教学数据文件。
5. 在 `3003` 端口监听请求。

### 4.2 路由：`backend/routes`

建议从 `backend/routes/users.js` 开始，重点观察注册、登录、查询和删除用户的流程。路由通常按以下顺序处理请求：读取参数 → 校验输入 → 读取数据 → 执行业务逻辑 → 返回状态码和 JSON。

### 4.3 数据：`backend/db.js` 和 `backend/db.json`

`db.js` 使用 Node.js 文件 API 读写 `db.json`。这种方式安装简单、适合课堂演示，但不适合多人并发和正式生产环境。修改用户、班级或同义词前，建议先复制备份 `backend/db.json`。

可以用下面的命令查看后端是否正常：

```bash
# 请求后端根路径；成功时会返回表示服务运行中的 JSON
curl http://localhost:3003/

# 请求班级列表；成功时会返回 JSON 数据
curl http://localhost:3003/api/classes
```

## 5. 推荐课堂练习

建议从小改动开始，每完成一个练习就重新运行前端和后端验证：

1. 增加用户手机号字段，贯通注册、更新和详情接口。
2. 增加修改密码接口。
3. 为用户列表增加分页。
4. 使用 bcrypt 替换当前演示密码校验。
5. 增加统一错误码和参数校验。
6. 为后端接口补充自动化测试。
7. 将 JSON 数据替换为 SQLite、MySQL 或 PostgreSQL。
8. 为前端补充加载、空数据和错误状态。

练习时建议遵循“先后端接口，再前端 Service，再 Store，最后页面”的顺序，并在浏览器 Network 面板中确认请求和响应。

## 6. 常见问题

### 6.1 端口占用

如果看到 `EADDRINUSE`，说明 `3000` 或 `3003` 已被其他进程占用。Windows PowerShell 可以执行：

```powershell
# 查找占用 3003 端口的进程；最后一列通常是 PID（进程编号）
netstat -ano | findstr :3003

# 结束指定 PID；将 <进程号> 换成上一步查到的数字
taskkill /PID <进程号> /F
```

Linux 可以执行：

```bash
# 查看谁正在监听 3003 端口
ss -lntp | grep 3003

# 结束指定进程；将 <进程号> 换成上一步查到的数字
kill <进程号>
```

### 6.2 登录失败

确认后端终端仍在运行，并使用 `admin@system.com / admin123`。然后打开浏览器开发者工具的 Network 面板，检查 `/api/users/login` 的请求地址、请求体、响应状态码和错误信息。

### 6.3 页面能打开但 API 报错

先确认后端 `3003` 端口可访问，再检查 `frontend/vite.config.js` 中的代理目标是否仍是 `http://localhost:3003`。如果是 Nginx 部署，还要检查 Nginx 的 `/api/` 反向代理和 PM2 日志。

## 7. 安全提醒

这是教学项目。真实项目中应使用密码哈希、正式数据库、可靠的登录会话、输入校验、HTTPS、日志和备份，并避免在公开文档中传播演示账号密码。

## 8. 本轮功能的代码阅读路线

1. 从 `Register.vue` 的班级下拉框和 `required` 开始，再看 `users.js` 的 `POST /register`；理解为什么前后端都验证班级。
2. 阅读 `UserManagement.vue` → `stores/user.js` → `utils/api/userService.js` → `routes/users.js`，追踪管理员添加用户和重置密码。
3. 阅读 `PhotoWall.vue` → `photoWallService.js` → `routes/photowall.js`，观察普通用户如何按 `classId` 请求照片墙数据。
4. 阅读 `UserCard.vue` 的 hover CSS，比较图片缩放与已移除的白色高光层；性能原因见 [性能优化指南](./performance-optimization-guide.md)。
