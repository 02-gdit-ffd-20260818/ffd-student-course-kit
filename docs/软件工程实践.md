# PersonaLink 软件工程实践

> 团队脚本约定、`ci` 与 `dev` 的词义及历史背景见 npm 命令词典与命名故事。

## 1. 需求分析

项目定位为前后端协作教学示例：用户按班级建立资料、展示同班照片，管理员维护班级和用户。关键约束是数据保存在本地 JSON，不能将其描述为生产级权限系统。

本轮需求落为可验收规则：注册必须选有效班级；普通用户在照片墙只由其班级加载数据；管理员可增删班级、增删用户、重置普通用户密码；图片悬停时细节更清晰且无白色遮挡。

## 2. 功能设计

```text
Vue 页面 -> Pinia Store -> Axios API Service -> Express Route -> db.json
```

- 注册：`Register.vue` → `userStore.register` → `POST /users/register`。
- 管理用户：`UserManagement.vue` → `createUserByAdmin/resetUserPassword` → 管理员 API。
- 班级照片墙：`PhotoWall.vue` → `photoWallService` → `/photowall/class/:classId`。
- 视觉：`UserCard.vue` 管理图片缩放；全局样式提供轻量按压、焦点和减少动画支持。

## 3. 实现取舍

前端和后端均校验注册班级，避免只靠 UI。管理员操作沿用了项目已有 `adminAuth` 教学验证方式；这降低了示例复杂度，但不提供生产级安全。性能相关动画使用 `transform`、`opacity`、`requestAnimationFrame`，避免频繁布局计算。

## 4. 测试策略

静态验证：`node --check backend/routes/users.js` 与 `npm run build`。功能回归：按 [端到端测试计划](./test-plan.md) 在浏览器执行。修改数据写入接口时，使用测试副本或记录并恢复 `backend/db.json`。

## 5. CI/CD 建议

当前仓库未发现 GitHub Actions 工作流，因此尚未具备自动 CI/CD。推荐逐步加入：

1. PR/推送触发 `npm ci`、后端语法检查和 `npm run build`。
2. 构建通过后上传 `frontend/dist` 作为构建产物。
3. 静态演示可部署 Pages；完整系统须分别部署前端与可运行 Express 的后端。
4. 通过 Git tag（如 `v1.0.0`）和 GitHub Release 固定可回退版本。
