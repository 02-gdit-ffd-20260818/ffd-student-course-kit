# 第 18 次课教师指南：工程答辩

每组现场证明软件“可改、可测、可发、可恢复”。学生必须从仓库、测试、CI、生产 URL 和 Release 之间建立可追溯关系，而不是背诵命令。

## 抽签任务池

1. 文案或样式最小修改，并补一条组件断言。
2. 给输入增加一个边界规则，并补正常/边界/失败测试。
3. 修改项目清单或 Adapter 字段，同时保持旧数据兼容。
4. 模拟外部依赖失败，展示 fallback 且不破坏现有状态。

学生复述验收后新建分支，展示修改前测试、关键 diff、修改后测试和 commit。禁止直接改 main、删除测试或关闭 CI。

## 评分核对（100）

- Issue → 分支 → commit → CI → Release 可追溯：20。
- 干净 clone、`npm ci`、测试与构建可复现：20。
- 正常/边界/失败测试解释准确：20。
- 现场最小修改与 diff 质量：20。
- 健康检查、日志脱敏、回滚与数据恢复判断：15。
- Agent 建议的采纳/拒绝依据：5。

## 故障提问顺序

先问“预期是什么、实际输出是什么”，再问“失败属于构建、前端、API、数据库还是部署”，最后要求学生说下一条最小验证命令。现场没有修完不自动判零，关键看证据、排查顺序和风险控制。
