# 第 15 次课｜P5 v1.0-v1.2｜音乐适配器与播放队列操作手册

> 本课成果：先用 Mock 数据打通搜索、选曲、入队、播放、下一首，再将真实音乐服务接到同一适配器接口。

## 先学知识点

| 知识点 | 小白理解 | 本课用在哪里 |
|---|---|---|
| Adapter | 用统一接口包住不同数据源 | Mock 与真实服务可切换 |
| 播放队列 | 按顺序保存待播放歌曲 | 上一首、下一首、删除 |
| 播放状态机 | 播放器只有规定状态 | idle/loading/playing/paused/error |
| 频率限制 | 避免短时间请求太多 | 输入防抖和错误提示 |
| 合规 | 音频、封面和元数据必须有合法来源 | 不抓取、不绕过限制 |

先做 Mock 是为了先验证页面与业务逻辑；更换真实服务时，不应重写整个页面。

## 分步操作

1. 阅读 Adapter 约定：至少包含 `search(keyword)` 和 `getTrack(id)`。
2. 先使用 `MockMusicAdapter`，不要一开始就申请真实 API。
3. 输入关键词，展示 loading、结果、空结果和错误四种状态。
4. 点击搜索结果加入队列；实现去重、删除、清空和下一首。
5. 音频元素监听 `play/pause/ended/error`，由事件更新页面状态。
6. 为搜索输入加 300ms 防抖，限制重复请求。
7. 最后接真实服务，只替换 Adapter；记录来源、许可、限流与失败策略。

## 跟做代码

将以下代码保存为 `queue-demo.mjs`，它不依赖浏览器，可先验证队列逻辑：

```js
const queue = []
let currentIndex = -1

function addTrack(track) {
  if (queue.some(item => item.id === track.id)) return false
  queue.push(track)
  if (currentIndex === -1) currentIndex = 0
  return true
}

function nextTrack() {
  if (queue.length === 0) return null
  currentIndex = (currentIndex + 1) % queue.length
  return queue[currentIndex]
}

addTrack({ id: 1, title: '晨光', url: '/audio/morning.mp3' })
addTrack({ id: 2, title: '晚风', url: '/audio/evening.mp3' })
addTrack({ id: 1, title: '晨光', url: '/audio/morning.mp3' })

console.log('队列长度应为 2：', queue.length)
console.log('当前歌曲：', queue[currentIndex])
console.log('下一首：', nextTrack())
```

运行：

```powershell
# 运行当前目录的队列演示脚本，观察入队、限流和顺序播放结果。
node queue-demo.mjs
```

然后在 Vue 页面中将队列绑定给音频元素：

```vue
<audio
  v-if="currentTrack"
  :src="currentTrack.url"
  controls
  @ended="playNext"
  @error="playerState = 'error'"
></audio>
<p v-else>队列为空，请先添加歌曲。</p>
```

看到队列长度为 2、能切到“晚风”，说明基础逻辑通过。

## 常见故障

- **音频不能自动播放**：浏览器通常要求用户先点击，不要强制绕过。
- **下一首索引越界**：用队列长度取模，空队列先返回。
- **真实 API 改字段导致页面崩溃**：在 Adapter 内转换为统一字段。
- **频繁出现 429**：增加防抖、缓存和友好重试，不连续轰炸接口。
