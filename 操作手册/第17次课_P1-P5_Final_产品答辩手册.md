# 第 17 次课｜P1-P5 Final｜产品答辩操作手册

> 本课成果：用真实任务、可访问产品和用户证据说明“为谁解决了什么问题”，并演示正常、空和失败三种状态。

## 先学知识点

| 知识点 | 小白理解 | 答辩中怎么证明 |
|---|---|---|
| 用户 | 有具体场景和目标的人 | 用户画像与任务描述 |
| 痛点 | 阻碍用户完成目标的问题 | 访谈原话或观察记录 |
| 价值 | 使用前后发生的可验证变化 | 时间、步骤、成功率对比 |
| 用户任务 | 用户从开始到结果的一条完整路径 | 现场操作生产 URL |
| 证据 | 别人可以复核的材料 | 数据、截图、链接、记录 |
| 失败恢复 | 出错后用户知道原因和下一步 | 错误提示、重试、降级 |

不要用“使用了 Vue/AI”代替产品价值。技术是实现手段，用户变化才是答辩主线。

## 课前准备

1. 按“用户—问题—价值—任务—证据—下一版”准备不超过 5 页材料。
2. 用非本组账号、手机网络走一遍主任务。
3. 准备生产 URL、备用录屏、用户反馈和验收对照。
4. 每位成员明确自己讲解的一段和可回答的贡献。

## 分步操作

1. 用 30 秒说明具体用户、场景、问题和可验证价值。
2. 用生产 URL 完成一条真实任务，让观众看到输入、处理和结果。
3. 主动演示空状态和失败状态，说明如何恢复。
4. 展示至少两条真实反馈：一条导致了修改，一条被拒绝并说明理由。
5. 对照验收标准逐条给出证据，不说无证据的“已优化”。
6. 每位成员说明自己的贡献、关键取舍和下一版假设。
7. 答辩后记录问题、证据缺口和 Backlog，不在现场直接改生产数据。

## 跟做代码

新建 `check-demo-urls.mjs`，答辩前一次检查全部演示地址：

```js
const demoUrls = [
  { name: 'P1 门户', url: 'https://example.com/' },
  { name: '健康检查', url: 'https://example.com/health' }
]

let failed = false
for (const item of demoUrls) {
  try {
    const response = await fetch(item.url, { redirect: 'follow' })
    console.log(`${response.ok ? 'PASS' : 'FAIL'} ${item.name}: ${response.status}`)
    if (!response.ok) failed = true
  } catch (error) {
    console.error(`FAIL ${item.name}: ${error.message}`)
    failed = true
  }
}
if (failed) process.exitCode = 1
```

将示例地址替换为自己的生产地址并执行：

```powershell
# 运行当前目录的生产 URL 检查脚本，确认答辩入口可匿名访问。
node check-demo-urls.mjs
```

再按下面的口述脚本演练，不要逐字背诵：

```text
我们的用户是……，在……场景中需要……。
原来要经过……步，现在通过本产品可以……。
下面现场完成一次真实任务，并展示失败后如何恢复。
证据是……；尚未完成的是……；下一版将验证……。
```

## 检查与提交

- 生产 URL 可用，主任务 3 分钟内完成。
- 正常、空、失败状态都有真实演示或带时间的备用证据。
- 反馈已脱敏，并能对应到具体改动或取舍。
- 提交产品答辩记录、任务脚本、反馈、验收对照和下一版 Backlog。

## 常见故障

- **现场网络故障**：展示事先录制且带时间的备用证据，同时如实说明故障。
- **演示超时**：只保留一条完整主任务，其他功能用证据索引回答。
- **回答变成技术汇报**：重新回到“用户为何需要、使用后有何变化”。
- **没有失败场景**：提前准备一个可恢复的输入错误，不破坏生产数据。
