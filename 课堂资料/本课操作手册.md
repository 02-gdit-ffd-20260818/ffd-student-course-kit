### 这一课要建立的三条核心观念

> **① 用户传上来的东西，声明的和实际的可能不是一回事。**

把 `virus.exe` 改名成 `photo.png`，浏览器会老老实实声明它是 `image/png`。
**只查扩展名和 MIME 是不够的，要读文件开头的字节。**

> **② 同一份代码，在不同的部署环境下能力是不一样的。**

Netlify、Vercel 这类平台的服务器是**用完即弃**的，
你传上去的文件下一次请求可能就找不到了。
只有部署在自己的服务器上，才有可持久化的磁盘。

> **③ 没有验证过恢复流程的备份，等于没有备份。**

这句话在真实事故里被反复印证——
**很多团队是在需要恢复的那一刻，才发现备份脚本半年前就坏了。**

## 2. 生成本机配置

**Windows CMD**

```bat
if not exist .env copy .env.example .env
findstr /B /C:"PORT=" /C:"DATABASE_PATH=" /C:"SESSION_SECRET=" /C:"ADMIN_USERNAME=" /C:"ADMIN_PASSWORD=" /C:"MEDIA_PATH=" /C:"BACKUP_PATH=" .env
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`findstr` 在文件中查找文字；`/B` 只匹配行首；每个 `/C:"字段="` 是一个完整查找词，多个 `/C` 表示任意一个匹配就显示；最后的 `.env` 是要读取的文件。`/R` 表示用正则表达式，`^` 是行首，`[A-Z_]` 是大写字母或下划线，`*` 是重复零次或多次。输出只用于本机检查，含密钥的行不要截图或发给别人。

`copy`（CMD）/ `Copy-Item`（PowerShell）把第一个路径的文件复制到第二个路径。只在目标配置尚不存在时复制模板；已有 .env 时直接打开并检查所需项，避免覆盖已经填写的值。
<!-- COMMAND_HELP:END -->


**Windows PowerShell**

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' }
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`Test-Path -LiteralPath 路径` 检查这个原样路径是否存在，返回 True 或 False；`-not` 取反。`if (...) { ... }` 只在条件成立时执行花括号里的操作，因此这里已有 .env 就不再覆盖。

`Get-Content` 逐行读取文件；`|` 把读取结果交给右边；`Where-Object` 只保留条件成立的行；`$_` 代表正在检查的那一行；`-match` 表示正则匹配；`^[A-Z_]+=` 表示行首是一个或多个大写字母/下划线，紧接等号。
<!-- COMMAND_HELP:END -->


能看到英文配置行就说明复制成功；这样不会触发 CMD 的 UTF-8 中文乱码。
在 `.env` 中确认 `SESSION_SECRET`、`ADMIN_USERNAME`、`ADMIN_PASSWORD` 有真实值，
并确认 `MEDIA_PATH`、`BACKUP_PATH` 不是空行。不要把真实值写进 `.env.example`。

|---|---|---|---|

**前端怎么找到后端的？** 看 `vite.config.js` 里的 `server.proxy` 配置：
前端把 `/api` 开头的请求**转发**到 3000。
所以你在浏览器里看到的地址始终是 5173，但 `/api/...` 的请求实际上是后端在回应。
这样浏览器认为前后端同源，不会有跨域问题。

> 只开后端，浏览器根本打不开页面。改后端代码时 `--watch` 会自动重启，
> 改前端代码 Vite 会自动刷新，都不用手动重启。

### 启动之后先确认这三件事

1. **终端里出现了上面说的那行提示**，而不是一串红色报错。
2. **浏览器真的能打开页面**，不是"无法访问此网站"。
3. **这些终端要一直开着。** 关掉哪个，哪一半功能就没了。
   要执行别的命令**请再开一个新终端**，不要在跑着服务的终端里敲。

**停止服务**：在跑着它的那个终端里按 `Ctrl + C`。
按一次没反应就再按一次，Windows 上偶尔会问 `终止批处理操作吗(Y/N)?`，输 `Y` 回车。

**改了代码要不要重启？**

|改什么|要不要手动重启|
|---|---|
|前端代码（页面、组件、样式）|**不用**，保存后浏览器自动刷新|
|后端代码|**不用**，`--watch` / `nodemon` 会自动重启|
|`.env` 里的配置|**要**，环境变量只在启动时读一次|
|`package.json` 的依赖|**要**，而且要先 `npm install`|

### 启动不起来怎么办

|终端里报什么|原因|处理|
|---|---|---|
|`'npm' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**，再 `node -v` 确认|
|`Cannot find module`|依赖没装，或者不在工程目录里|先确认当前目录对不对，再 `npm install`|
|`EADDRINUSE` 端口被占用|**多半是上一次的服务没关**|找到那个终端按 `Ctrl+C`；或者换个端口|
|`npm ci` 报 lock 文件对不上|`package.json` 改过但没更新 lock|先 `npm install` 生成新的 lock，再提交|
|装依赖卡住不动|npm 源慢|`npm config set registry https://registry.npmmirror.com` 再重试|
|页面能打开但数据是空的|**后端没起来**|F12 → Network，看那条请求是红的还是 200|
|一片空白，Console 全是红字|前端代码有错|从 **第一条**报错开始看，不要直接翻到最后|

### TODO 04 · 生产环境的配置要单独一份

**难度**：中等


**为什么做这个**
本机开发和线上服务器用的是**两套完全不同的配置**：

|配置项|本机|线上|
|---|---|---|
|数据库路径|`./var/blog.sqlite`|服务器上的持久化目录|
|`SESSION_SECRET`|本机专用随机值|**服务器专用的另一组真随机值**|
|端口|3000|由 Nginx 反代|
|管理员密码|好记就行|**必须是强密码**|

**涉及的知识点**

`.env.example` 是**模板**，它进 Git；`.env` 存真实值，**永远不进 Git**。

生成一个真随机密钥：

```bat
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

**把命令逐段读懂**：`node` 是在终端运行 JavaScript；`-e` 表示直接执行引号内代码；
`require('node:crypto')` 加载 Node 自带密码学模块；`randomBytes(32)` 生成 32 字节安全随机数据；
`toString('base64url')` 把它变成约 43 个可复制字符；`console.log` 只负责打印。
命令不会自动修改任何文件：要把输出复制到自己的 `.env`，不要放进 `.env.example` 或 Git。

**这个文件是模板，永远不要往里填真实密钥。**
真实值只写在服务器上那份 `.env` 里，而 `.env` 在 `.gitignore` 里。

> **一旦真密钥进了 Git 历史，删掉也没用**——历史里还在，
> 任何克隆过仓库的人都有。**必须去作废重发。**

### 已写好 · 光看声明的类型不算数

**为什么做这个**
**这是本课最重要的一个安全观念。**

TODO 02 检查的是浏览器**声明**的 MIME 类型。但声明是可以伪造的——
把 `virus.exe` 改名成 `photo.png`，浏览器会老老实实说它是 `image/png`。

**涉及的知识点：魔数（magic number）**

文件开头的几个字节是格式的"指纹"，**这个骗不了人**：

|格式|开头的字节|
|---|---|
|PNG|`89 50 4E 47 0D 0A 1A 0A`|
|JPEG|`FF D8 FF`|
|WebP|`RIFF` + 4 字节 + `WEBP`|
|WAV|`RIFF` + 4 字节 + `WAVE`|
|OGG|`OggS`|
|MP3|`ID3` 或 `FF Ex`|
|MP4|第 5—8 字节是 `ftyp`|
|WebM|`1A 45 DF A3`|

上面那一大段 `if / else if` 就是在读这些字节。
最后 已写好的代码 要补的那道判断是：
**认出来的大类，必须和声明的 MIME 前缀一致**。

**整个流程的顺序也很关键：**

```text
① 先落到临时目录 .incoming
② 读文件头，确认真实格式
③ 和声明的类型对比，不一致就拒绝并删掉
④ 确认没问题，才改名挪到公开目录
```

### 已写好 · 一致快照、摘要验证和无损恢复

备份代码已提供，不是新增 TODO。先停止后端，并关闭 Navicat 等写入工具，避免数据库、媒体与配置在备份过程中互相不一致。

在工程根目录执行（Windows CMD/PowerShell 相同）：

```text
npm run db:backup -- --confirmed-stopped
```

第一个 `--` 把后续参数交给脚本；`--confirmed-stopped` 表示你已经停止所有写入，不是“自动帮你停止后端”。脚本读取 `.env` 中的 DATABASE_PATH、MEDIA_PATH、BACKUP_PATH 和 CONFIG_ENV_PATH。

SQLite 执行 `VACUUM INTO` 生成包含已提交 WAL 数据的一致快照；不要分别复制正在使用的主库和 WAL。新备份目录含 `database/blog.sqlite`、可用的 media 和 .env，以及 `manifest.json` 摘要清单。配置可能含密钥，整个目录不能进 Git 或网站公开目录。

记下终端打印的真实备份目录，再独立验证（替换中文占位路径）：

```text
npm run db:backup -- --verify "实际备份目录"
```

`--verify` 只读取指定备份，逐项比较 SHA-256，再检查 SQLite 完整性；不重新备份、不覆盖原数据。必须看到 PASS。SHA-256 是内容指纹，不是加密，也不能替代备份访问权限。

**恢复演练不删除原库**：用文件管理器把已验证备份中的 `database/blog.sqlite` 复制到一个全新的练习目录，例如 `var/restore-drill-日期/blog.sqlite`；媒体也复制到该新目录。保留原 `.env` 的本机副本，编辑 DATABASE_PATH 和 MEDIA_PATH 指向新目录，再启动后端，检查原账号、文章和媒体。完成后停止后端，改回原路径。不要把旧 WAL 文件拼到新快照旁边。

**故障演练只用备份副本**：把整个备份目录复制到另一个新目录，在副本中用编辑器修改一个媒体文件，再对副本运行 `--verify`，应报告摘要不匹配。原备份和原库保持不动。新建备份成功不能证明旧备份没损坏。


## 5. 部署到 Ubuntu 服务器

> 这一节需要一台 Ubuntu 服务器。没有的话看教师演示，
> 完整步骤另见同目录的 `Ubuntu部署实操.md`。

**部署的整体结构：**

```text
公网用户 ──▶ Nginx（80/443）──▶ Node 进程（127.0.0.1:3000）──▶ SQLite 文件
                  │
                  └──▶ 静态文件（dist/）和上传的媒体（var/media/）
```

**为什么要 Nginx 挡在前面？**

|Nginx 负责|Node 负责|
|---|---|
|监听 80/443，处理 HTTPS 证书|业务逻辑和数据库|
|直接返回静态文件（快得多）|只处理 `/api/` 请求|
|限流、压缩、安全响应头|——|

**Node 进程只监听 `127.0.0.1`**，不对外网开放。
这样即使 Node 有漏洞，外面也够不着——**只有 Nginx 能访问它**。

**为什么要 systemd？** 让服务开机自启、崩溃自动重启。
用 `npm run start:api` 手动跑的话，你一关 SSH 窗口进程就没了。

关键命令（在服务器上执行）：

```bash
# 查看服务状态
sudo systemctl status ffd-blog

# 重启服务（改了代码或 .env 之后）
sudo systemctl restart ffd-blog

# 看日志（-f 持续跟着输出）
sudo journalctl -u ffd-blog -f

# 检查 Nginx 配置有没有语法错误，再重载
sudo nginx -t && sudo systemctl reload nginx
```

**上线之后立刻做两件事：**

1. **跑验证脚本**：

```bash
LIVE_BASE=https://你的域名 npm run verify:live
```

2. **手机真机打开一次**。模拟器和真机有差别，这一步不能省。

## 常见问题

### 上传

|现象|原因|处理|
|---|---|---|
|上传返回 404|请求路径或前端代理不正确|检查请求是否到达 `/api/media/upload`，以及后端端口|
|上传返回 503|TODO 01 未完成，或未进入 SQLite 上传分支|先核对 `if` 条件、保存代码及后端重启结果|
|上传返回 403|不是管理员账号|用 `.env` 里那个管理员登录|
|所有文件都被拒|TODO 02 的 `accept` 还是空集合|补全九种 MIME 类型|
|真的图片也提示"格式与声明不一致"|文件头判断分支写漏了|对照魔数表逐个检查|
|图片传上去了但显示不出来|静态文件服务没注册|TODO 01 的 `if` 块里两条都要有|
|`var/media/.incoming` 堆了一堆文件|`finally` 里的清理没执行|检查 `save` 函数的 try/finally|

### 备份与恢复

|现象|原因|处理|
|---|---|---|
|备份报"逐字节校验失败"|正常现象（如果你故意改坏了）|说明校验在工作|
|恢复后数据还是没有|复制的是旧备份，或文件名不对|确认复制的是最新那份，DATABASE_PATH 必须指向刚恢复的新文件，原库保持不动|
|恢复时文件被占用|仍有连接|停后端并关闭 Navicat；恢复到全新目录，不删除原库|
|恢复后少了最近几条数据|只备份了主文件，漏了 `-wal`|核对快照时间；不要把旧 WAL 拼接到恢复库|

### 部署

|现象|原因|处理|
|---|---|---|
|公网打不开，但服务器上 curl 能通|Nginx 没配好，或防火墙挡了|`sudo nginx -t` 检查配置；`sudo ufw status` 看防火墙|
|502 Bad Gateway|Node 进程没起来|`sudo systemctl status ffd-blog` 看状态和报错|
|改了 `.env` 不生效|服务没重启|`sudo systemctl restart ffd-blog`|
|`verify:live` 报数据库不是 SQLite|服务器上的 `.env` 配错了|检查 `DATABASE_PATH`|
|上传的图片重启后没了|部署在了无持久化磁盘的平台上|见 TODO 01 的说明|
