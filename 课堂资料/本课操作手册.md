### 401 和 403 的区别（本课考点）

|状态码|意思|典型场景|前端该怎么办|
|---|---|---|---|
|`401`|**我不知道你是谁**|没登录、令牌无效、令牌过期|跳登录页|
|`403`|**我知道你是谁，但你不能干这个**|普通用户想删别人的评论|提示"没有权限"，**跳登录页毫无意义**|

**用错了前端就会做错事。** 一个登录了的用户收到 401 被踢去重新登录，
登完回来还是不能做那件事——因为问题从来不是"没登录"。

### 一个最小例子：中间件怎么把门

```js
function signed(req, res, next) {
  if (!req.user) return fail(res, 401, '请先登录')
  next()                    // 放行，交给下一环
}

app.post('/api/articles/:id/comments', signed, handler)
//                                      ↑ 先过这道门，过了才到 handler
```

`next()` 是"放行"。不调用它，请求就停在这里——
所以**每个分支要么 return 一个响应，要么调 `next()`**，两者必居其一。

### 这一课要建立的核心观念

> **前端藏起来是体验，后端挡住才是安全。**

把删除按钮藏掉，用户不会误点——这是好体验。
但按钮藏了，接口还在，任何人用一行 `curl` 就能调。
**真正的防线永远在服务器上。**

本课五个任务里，TODO 05 做的是前端拦截，其余六个都在后端。
这个比例本身就说明了问题。

## 2. 生成本机配置

**Windows CMD**

```bat
if not exist .env copy .env.example .env
findstr /B /C:"PORT=" /C:"DATABASE_PATH=" /C:"SESSION_SECRET=" /C:"ADMIN_USERNAME=" /C:"ADMIN_PASSWORD=" .env
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`findstr` 在文件中查找文字；`/B` 只匹配行首；每个 `/C:"字段="` 是一个完整查找词，多个 `/C` 表示任意一个匹配就显示；最后的 `.env` 是要读取的文件。`/R` 表示用正则表达式，`^` 是行首，`[A-Z_]` 是大写字母或下划线，`*` 是重复零次或多次。输出只用于本机检查，含密钥的行不要截图或发给别人。

`copy`（CMD）/ `Copy-Item`（PowerShell）把第一个路径的文件复制到第二个路径。只在目标配置尚不存在时复制模板；已有 .env 时直接打开并检查所需项，避免覆盖已经填写的值。
<!-- COMMAND_HELP:END -->


**Windows PowerShell**

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' }
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`Test-Path -LiteralPath 路径` 检查这个原样路径是否存在，返回 True 或 False；`-not` 取反。`if (...) { ... }` 只在条件成立时执行花括号里的操作，因此这里已有 .env 就不再覆盖。

`Get-Content` 逐行读取文件；`|` 把读取结果交给右边；`Where-Object` 只保留条件成立的行；`$_` 代表正在检查的那一行；`-match` 表示正则匹配；`^[A-Z_]+=` 表示行首是一个或多个大写字母/下划线，紧接等号。
<!-- COMMAND_HELP:END -->


能看到英文配置行就说明复制成功；这样不会触发 CMD 的 UTF-8 中文乱码。
在 `.env` 中确认 `SESSION_SECRET`、`ADMIN_USERNAME`、`ADMIN_PASSWORD` 三项都有真实值。
如果没有密钥，用下面命令生成后粘贴；不要改 `.env.example`，也不要把 `.env` 提交到 Git。

```bat
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

**把命令逐段读懂**：`node` 是在终端运行 JavaScript；`-e` 表示直接执行引号内代码；
`require('node:crypto')` 加载 Node 自带密码学模块；`randomBytes(32)` 生成 32 字节安全随机数据；
`toString('base64url')` 把它变成约 43 个可复制字符；`console.log` 只负责打印。
命令不会自动修改任何文件：要把输出复制到自己的 `.env`，不要放进 `.env.example` 或 Git。

**前端怎么找到后端的？** 看 `vite.config.js` 里的 `server.proxy` 配置：
前端把 `/api` 开头的请求**转发**到 3000。
所以你在浏览器里看到的地址始终是 5173，但 `/api/...` 的请求实际上是后端在回应。
这样浏览器认为前后端同源，不会有跨域问题。

> **两个终端都要开着。** 只开前端，页面能打开但一片空白、Console 里全是请求失败；
> 只开后端，浏览器根本打不开页面。改后端代码时 `--watch` 会自动重启，

**改了代码要不要重启？**

|改什么|要不要手动重启|
|---|---|
|前端代码（页面、组件、样式）|**不用**，保存后浏览器自动刷新|
|后端代码|**不用**，`--watch` / `nodemon` 会自动重启|
|`.env` 里的配置|**要**，环境变量只在启动时读一次|
|`package.json` 的依赖|**要**，而且要先 `npm install`|

### 启动不起来怎么办

|终端里报什么|原因|处理|
|---|---|---|
|`'npm' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**，再 `node -v` 确认|

### TODO 02 · `admin`：再问"是不是管理员"

**难度**：简单


**为什么做这个**
登录了不等于什么都能干。普通用户不该能删文章、改文章。

**涉及的知识点**

```js
function admin(req, res, next) {
  if (!req.user) return fail(res, 401, '请先登录')
  if (req.user.role !== 'admin') return fail(res, 403, '仅管理员可管理文章')
  next()
}
```

**两个判断，两种状态码，顺序不能反：**

|情况|状态码|为什么|
|---|---|---|
|没登录|`401`|我不知道你是谁——你该去登录|
|登录了但不是管理员|`403`|我知道你是谁，你就是不能干这个——**去登录也没用**|

**角色从哪来？** `req.user.role` 来自令牌。令牌是服务器签的，用户改不了。
第 07 课那个"改坏令牌就变游客"的实验，验的就是这件事。

**为什么普通注册的用户一定是 `reader`？**
第 07 课 TODO 01 在建表时写了 `DEFAULT 'reader'`，
注册接口的 INSERT 里根本没有 `role` 这一列，所以只能是默认值。
**想成为管理员，只有首次建库时用环境变量创建这一条路。**
这是"约束 + 代码"配合的一个完整例子。

### TODO 03 · 只能删自己的评论

**难度**：简单


**为什么做这个**
**这是本课最能体现"授权"的一步。**

`signed` 和 `admin` 判断的是"你是什么身份"。
但这里要判断的是"**这个东西是不是你的**"——同样是登录用户，
张三能删张三的评论，不能删李四的。这叫**基于归属的授权**。

**涉及的知识点**

```js
if (!c) return fail(res, 404, '评论不存在')
if (Number(c.user_id) !== Number(req.user.sub) && req.user.role !== 'admin')
  return fail(res, 403, '只能删除自己的评论')
```

**`Number(...)` 这层转换绝对不能省。**

令牌里的 `sub` 和数据库里的 `user_id`，一个可能是字符串 `"3"`，一个是数字 `3`。
`"3" !== 3` 永远成立——结果就是**所有人都删不了自己的评论**。

这个 bug 特别隐蔽：功能"看起来在工作"（确实挡住了别人），
只是顺便把本人也挡住了。**凡是要比较两个来源的值，先统一类型。**

**管理员为什么能删所有人的？** 内容治理需要——
有人发了违规内容，管理员要能处理。这是产品决定，不是技术决定。

### TODO 04 · 编号只能是正整数

**难度**：简单


**为什么做这个**
地址栏里的编号是用户可以随便改的。
填 `abc`、填 `-1`、填一个 20 位的数字，后端会怎样？

不校验的话，`Number('abc')` 得到 `NaN`，拿去查数据库可能抛异常——
**用户乱填导致 500，这是我们的 bug，不是用户的错。**

**涉及的知识点：`app.param`**

```js
app.param('id', (req, res, next, value) => {
  if (!/^[1-9][0-9]*$/.test(value) || !Number.isSafeInteger(Number(value)))
    return fail(res, 400, '编号格式不正确')
  next()
})
```

`app.param` 是 Express 的一个便利功能：
**凡是路径里带 `:id` 的接口，都会先经过这里**，不用在每个接口里各写一遍。

本项目有六七个接口带 `:id`，写一处全覆盖。

|判断|挡住什么|
|---|---|
|`/^[1-9][0-9]*$/`|非数字、负数、`0`、以 0 开头的数字|
|`Number.isSafeInteger(...)`|大到超出安全范围的数字|

**为什么要查"安全整数"？** JavaScript 的数字超过 2^53 就会丢精度：

```js
9007199254740993 === 9007199254740992   // true —— 两个不同的数字变成相等了
```

传一个超长数字进来，`Number(...)` 得到的值和你以为的不是一回事。

**改哪里**：`server/blog-app.js` 的 `app.param('id', ...)`，TODO 04 的位置。

### TODO 05 · 前端也要挡一道（体验层）

**难度**：中等


**为什么做这个**
前六个任务都在后端。**后端是安全，前端是体验。**

想象一个普通用户手滑点进了 `/admin/articles`：

**能用，但很难看**。前端提前拦住，直接弹回首页，体验好得多。

**涉及的知识点：路由守卫**

```js
router.beforeEach(to => {
  if (!to.meta.requiresAuth) return true                 // 不需要登录的页面，放行
  if (!getAccessToken())
    return { name: 'login', query: { redirect: to.fullPath } }   // 没令牌 → 去登录

    ? true                                               // 是管理员 → 放行
    : { name: 'home' }                                  // 不是 → 回首页
})
```

`beforeEach` 是"每次跳转之前都先问一下"。
返回 `true` 放行，返回一个路由对象就是"改去那里"。

**`query: { redirect: to.fullPath }` 这一段是个贴心设计**：
把用户原本想去的地址记下来，登录成功后自动跳回去。
没有它，用户登完发现自己在首页，还得再点一遍。

### 已写好 · 挡住暴力破解

**为什么做这个**
密码存成摘要（第 07 课）解决的是"**数据库被偷之后**"的问题。
但还有另一种攻击完全不需要偷数据库：**在线撞库**——
写个脚本对着登录接口一秒试几百个密码。

**涉及的知识点：滑动窗口限流**

```js
if (!a || now - a.time > 600000) a = { time: now, count: 0 }   // 超过 10 分钟重新计数
a.count++
attempts.set(key, a)
if (a.count > 40) return fail(res, 429, '操作过于频繁，请稍后重试')
```

|部分|说明|
|---|---|
|`key = req.ip`|按来源 IP 计数|
|`600000`|10 分钟（毫秒）。超过就重新开始数|
|`40`|10 分钟内最多 40 次|
|`429`|Too Many Requests|

它挂在 `app.use('/api/auth', ...)` 上，**注册和登录都受它保护**。

**这个实现有明确的边界，要讲清楚：**

|局限|后果|
|---|---|
|存在内存的 `Map` 里|**后端一重启就清空**|
|按 IP 计数|同一个学校/公司出口 IP 相同，会互相影响|
|多台服务器各记各的|部署两台，攻击者的次数就被分摊了|

**够课堂用，但不是生产级方案。** 真实项目会用 Redis 之类的共享存储，
并且按"IP + 账号"双维度计数。

**知道一个方案的边界在哪，比只会用它更重要。**

### 已写好 · 给每个响应加上安全头

**为什么做这个**
这是两行代码就能消除两类风险的事，几乎没有理由不做。

**涉及的知识点**

```js
res.set('Cache-Control', 'no-store')
res.set('X-Content-Type-Options', 'nosniff')
```

|响应头|防什么|
|---|---|
|`Cache-Control: no-store`|这些接口返回的是**和当前登录用户有关**的数据。被浏览器或中间的代理缓存下来，**换个人登录可能看到上一个人的数据**|
|`X-Content-Type-Options: nosniff`|禁止浏览器"猜"内容类型。不加的话，一个内容像 HTML 的文件可能被当成 HTML 执行|

第二个的实际场景：用户上传了一个叫 `a.txt` 但内容是 `<script>...</script>` 的文件，
浏览器"聪明地"认为这是 HTML 并执行了它——脚本就在你的域名下跑起来了。
`nosniff` 的意思是"**我说是什么就是什么，别猜**"。

**这两行写在全局中间件里，一次生效于所有接口。**
安全措施**能放在统一入口就不要分散**——分散了迟早漏掉一个。

|管理员也被 403 挡住|`.env` 里的管理员没建成功|`db:inspect` 看 users 表里有没有 role='admin' 的行|
|**自己的评论也删不掉**|忘了 `Number(...)` 转换|`"3" !== 3` 永远成立，两边要统一类型|
|普通账号能删别人评论|TODO 03 的条件写反了|应该是"不是自己的 **且** 不是管理员"才拒绝|
|401 和 403 返回成了同一个|`admin` 里少写了一个判断|两个 if 都要有，顺序是先 401 后 403|

### 限流与校验

|现象|原因|处理|
|---|---|---|
|429 一直不出现|上限没改小，或后端没重启|临时改成 3，看终端有没有打印重启|
|429 出现后一直不消失|窗口是 10 分钟|重启后端立刻清空（它存在内存里）|
|非法编号返回 500|TODO 04 没做|`app.param` 里补上校验|
|正常编号也被 400 挡住|正则写错了|`/^[1-9][0-9]*$/`，注意 `0` 是不允许的|

### 前端

|现象|原因|处理|
|---|---|---|
|路由守卫不生效|`to.meta.requiresAuth` 没配|看 `src/router.js` 里那条路由的 meta|
|登录后没跳回原页面|`query.redirect` 没传，或登录页没读它|两处都要检查|
|普通账号进了后台但全是报错|TODO 05 没做|前端守卫只是体验，后端已经挡住了，但要补上|
