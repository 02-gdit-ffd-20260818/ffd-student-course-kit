## 开课前先讲这些概念

|知识点|小白要理解的话|本课在哪里用到|
|---|---|---|
|`ref(值)`|**单个**会变的值。JS 里要写 `.value`，模板里不用|`themeId`、`message`、`status`|
|`reactive(对象)`|**一整组**会变的值，不用写 `.value`|`form`|
|`computed(() => …)`|**由别的数据算出来**的值，自己不存数据|`theme`、`canSubmit`、`cardFace`|
|`v-model`|表单控件和数据**双向**绑定|输入框、文本域|
|`v-for`|按数组渲染出一批元素|六个场景按钮、13 个色块|
|`:属性`|`v-bind` 缩写，值是 **JS 表达式**|`:style`、`:aria-pressed`|
|`{{ }}`|把数据插进页面，**默认会转义 HTML**|到处都是|

### 最容易出错的一条

> **`ref` 在 `<script>` 里要写 `.value`，在 `<template>` 里不用写。**

```js
themeId.value = 'forest'   // script 里，必须带 .value
```

```html
{{ themeId }}              <!-- template 里，不带 -->
```

漏了 `.value` 不会报错，只是**赋值赋到了一个包装对象上，界面纹丝不动**——
这是新手最常卡住的地方。

### `ref` 还是 `reactive`？

|  |用哪个|
|---|---|
|一个孤零零的值（当前选中的卡面 id、加载状态）|`ref`|
|一组一起用的值（表单的四个字段）|`reactive`|

本项目里 `form` 用 `reactive` 是因为它的四个字段总是一起出现；
`themeId` 用 `ref` 是因为它就一个值。**没有绝对标准，保持一致就好。**

### 这一课要建立的核心观念

> **改数据，不要改页面。**

传统写法是"点按钮 → 找到那个 DOM 元素 → 改它的 class 和样式"。
Vue 的写法是"点按钮 → 改一个变量"，页面自己跟着变。

本课六个 TODO 里有五个都在演示这条链路：

```text
点击 → 改变量 → computed 重算 → 模板重新渲染 → 你看到变化
```

**任何一个 TODO 做完之后页面没变化，就沿着这条链路倒着查。**

### TODO 01 · 把场景图标显示出来

**难度**：极简单


**为什么做这个**
六个场景按钮光有文字太素。更重要的是借这个任务讲清**数据驱动**。

**涉及的知识点**

```html
<button v-for="item in OCCASIONS" :key="item.id" …>
  <span class="glyph">{{ item.icon }}</span>{{ item.id }}
</button>
```

```js
const OCCASIONS = [
  { id: '生日', icon: '✦' },
  { id: '毕业', icon: '✧' },
  …
]
```

|部分|说明|
|---|---|
|`v-for="item in OCCASIONS"`|数组里有几项就渲染几个按钮|
|`:key="item.id"`|**给每一项一个稳定的身份**，Vue 靠它判断哪些元素能复用|
|`{{ item.icon }}`|把这一项的图标插进去|

**`:key` 千万不要用数组下标。** 列表顺序一变，下标全对不上，
Vue 会复用错元素——表现出来就是"输入框里的内容跳到了别人那一行"。

**改哪里**：`src/App.vue` 的模板，TODO 01 的位置。


**具体怎么做（先判断任务类型）**

1. 先读上面的“改哪里”和本任务已有的代码/命令示例，确认这是**修改代码**还是**执行操作**。
2. 修改代码：在指定文件用 `Ctrl+F` 搜 `TODO 01`；如果代码里没有这个锚点，就按“改哪里”给出的函数、选择器或属性定位，**不要继续盲搜**。
3. 执行操作：严格按本任务编号步骤做，不需要寻找代码锚点；例如浏览器检查、故意制造错误、恢复文件都属于操作型任务。
4. 只动“改哪里”圈定的范围；看到“后续预留，本课不要修改”立即停下。然后运行“自己验证”，结果完全一致才算完成。
5. 仍卡住时再对照 `教师答案/p4-lesson-01/本课改动.patch（精确改动）和 完整答案文件/（完成态）`：代码任务搜索同一文件/函数，操作任务核对预期现象；不要整文件覆盖。

> `TODO 01` 只表示本课第 01 项任务。正文提到其他编号时只是说明知识联系，不表示要在这里同时完成另一项任务。



**操作前 / 操作后**

- 操作前：按钮上只有"生日""毕业"几个字。
- 操作后：**每个按钮前面多一个小符号（✦ ✧ ❖ ❀ ⌂ ○）。**

1. 保存 → 六个按钮都有了图标。

### TODO 05 · 让卡面切换真正生效

**难度**：简单


**为什么做这个**
这是整个 Vue 的基本盘：**点一个按钮 → 一个变量变了 → 界面跟着变**。
不把这条链路走通，后面六个都是空的。

**涉及的知识点**

```js
export function findTheme(id) {
  return themes.find(theme => theme.id === id) ?? themes[0]
}
```

|部分|说明|
|---|---|
|`themes.find(...)`|数组方法，返回**第一个**满足条件的元素，找不到返回 `undefined`|
|`theme => theme.id === id`|箭头函数。对每一项问一次"是不是它"|
|`?? themes[0]`|**空值合并**。左边是 `null`/`undefined` 时才取右边|

**`??` 和 `||` 不一样，这个差别很重要**：

```js
0 || 1     // → 1    （0 被当成"假"）
0 ?? 1     // → 0    （0 不是 null/undefined，所以取左边）
'' || 'x'  // → 'x'
'' ?? 'x'  // → ''
```

**`||` 会把 0 和空字符串也当成"没有"**，这是无数 bug 的来源。
"只在 null/undefined 时兜底"就用 `??`。

### 已写好 · 把卡面样式算出来

**为什么做这个**
**这是本课视觉变化最大的一步。** 做完之后那块白板子才真的像一张贺卡。

**涉及的知识点**

```js
const cardFace = computed(() => ({
  background: `linear-gradient(158deg, ${theme.value.colors[0]}, ${theme.value.colors[1]})`,
  color: theme.value.ink,
  boxShadow: theme.value.light ? '…浅色的阴影…' : '…深色的阴影…',

```

三个知识点：

1. **绑定一个样式对象**。模板里写 `:style="cardFace"`，

2. **模板字符串**。反引号里用 `${...}` 插值：

```js
`linear-gradient(158deg, ${a}, ${b})`   // 清楚
'linear-gradient(158deg, ' + a + ', ' + b + ')'   // 一样的意思，但难读
```

3. **`158deg` 是渐变方向**。0deg 从下往上，90deg 从左往右。

## 6. Git 提交与推送

### 第一步：先看清楚自己改了什么

```bat
git status
git diff
```

确认列表里**没有**这几样：`node_modules/`、`.env`、`dist/`。
它们都在 `.gitignore` 里，正常不会出现；出现了说明 `.gitignore` 出了问题，
**先解决再提交**——`.env` 里有密钥，一旦进了 Git 历史，删掉也没用。

### 第二步：提交

**Windows CMD**

```bat
REM . 表示"当前目录下所有改动"
git add .
git commit -m "P4第1课：卡面系统、表单交互与可访问的选中态"
git log -1 --oneline
```

**Windows PowerShell**

```powershell
git add .
git commit -m "P4第1课：卡面系统、表单交互与可访问的选中态"
git log -1 --oneline
```

### 第三步：推送到你自己的仓库

```bat
git push origin main
```

**推送报 `'origin' does not appear to be a git repository` 怎么办？**

走路线 B 的同学，`origin` 已经被改名成 `template`
（那是全班共用的模板仓库，**不能推**）。
先到 GitHub 新建一个空仓库 `p4-card-学号`（**不要**勾选 "Add a README file"），然后：

**Windows CMD**

```bat
REM 把你自己的仓库地址登记成 origin
git remote add origin https://github.com/你的用户名/p4-card-学号.git
git branch -M main

REM -u 的意思是"记住这个对应关系"，以后直接 git push 就行
git push -u origin main

REM 确认一下现在有哪几个远程仓库
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p4-card-学号.git
git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。
`git remote -v` 应该看到：**`origin` 指向你自己的仓库，`template` 指向公共模板仓库**。

## 常见问题

### 页面没反应

|现象|原因|处理|
|---|---|---|
|改了代码页面不变|文件没保存|`Ctrl+S`；Vite 会自动刷新，不用手动刷|
|赋值了但界面不动|**script 里漏写 `.value`**|`themeId.value = 'x'`，不是 `themeId = 'x'`|
|页面整个白了|某处访问了 undefined 的属性|**F12 → Console 看红色报错**，按提示的行号去找|
|`{{ }}` 原样显示在页面上|写在了 `<script>` 里，或者标签写错了|`{{ }}` 只在 `<template>` 里有效|

### 启动与工具

|现象|原因|处理|
|---|---|---|
|`'npm' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**|
|`Port 5173 is in use`|上次的服务还开着|关掉那个终端；或者让 Vite 自动换一个端口|
|`npm ci` 报版本不够|Node 不是 24|`node -v` 确认|
|装依赖卡住不动|网络问题|换国内镜像（第 3 节）|

### 样式

|现象|原因|处理|
|---|---|---|
|`:style` 不生效|属性名写成了 `box-shadow`|对象里要用驼峰 `boxShadow`|
|深色卡面上文字看不清|`color: theme.value.ink` 没写|已写好的代码 的第二行|
|高亮样式不出现|`aria-pressed` 前面漏了冒号|不加冒号就成了写死的字符串|
