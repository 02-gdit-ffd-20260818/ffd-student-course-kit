## 开课前先讲这些概念

学生动手之前，先把这几个词讲清楚。每个只讲到"能用自己的话解释"为止，不展开。

|知识点|小白要理解的话|本课在哪里用到|
|---|---|---|
|响应式|同一份代码，在手机、平板、电脑上都好用，**不是做三个网站**|全课|
|视口（viewport）|屏幕上"当前能看见"的那块区域。响应式判断的都是它的宽度|TODO 05、06|
|Grid 布局|二维网格。你规定有几行几列，子元素自动往格子里填|TODO 01、02|
|`fr` 单位|份额。`1fr` 表示"占剩余空间的 1 份"，两列都是 1fr 就各占一半|TODO 02|
|`gap`|网格单元之间的间隙。**只在 grid / flex 下有效**，block 下会被忽略|TODO 01|
|媒体查询|`@media (max-width: 640px) { }`——满足条件时才应用里面的规则|TODO 05|
|断点|媒体查询里那个分界宽度。是经验值，不对应某款具体手机|TODO 05|
|`object-fit`|图片和容器尺寸对不上时怎么放：拉伸、裁切还是留白|TODO 03|
|`transform`|改变元素的视觉位置／大小／角度，**不重新挤动周围元素**|TODO 04|
|`clamp()`|`clamp(最小, 理想, 最大)`——理想值随屏幕变，但被两端兜住|TODO 06|

### 三个最小例子，本课六个任务都是它们的变形

**例 1：Grid 两列**

```css
.list {
  display: grid;                        /* 变成网格容器 */
  grid-template-columns: 1fr 1fr;       /* 两列，各占一半 */
  gap: 20px;                            /* 格子之间留 20px */
}
```

**例 2：媒体查询——窄屏时换一套规则**

```css
.list { grid-template-columns: 1fr 1fr; }   /* 默认两列 */

@media (max-width: 640px) {
  .list { grid-template-columns: 1fr; }     /* 窄屏改一列 */
}
```

**例 3：图片怎么装进固定比例的框**

```css
.cover { aspect-ratio: 3 / 2; overflow: hidden; }  /* 框固定 3:2 */
.cover img { width: 100%; height: 100%; object-fit: cover; }
/* cover = 保持比例放大到铺满，超出部分裁掉，不变形 */
```

**这三个例子的分工要讲透**：Grid 决定"怎么排"，媒体查询决定"什么屏幕用哪一套排法"，
`object-fit` 决定"图片怎么装进格子"。本课所有 TODO 都跳不出这三件事。

> **本课所有效果都靠拉动窗口宽度来看。** 建议先把浏览器窗口调成不到半屏宽，
> 每做完一步都从最窄拉到最宽再拉回来。也可以按 `F12` → 左上角手机图标，
> 用设备模拟器直接切换 iPhone / iPad / 桌面。

### 这一步的常见故障

|现象|原因|处理|
|---|---|---|
|`系统找不到指定的路径`|桌面上还没有 `web-work`|上面第 1 步的 `mkdir` 那两行不能跳过|

**第一步：把本课新增的文件领到自己的工程里。**

```text
git remote add course https://github.com/02-gdit-ffd-20260818/ffd-student-course-kit.git
git fetch course p1-l03-standalone-v3.0
git checkout course/p1-l03-standalone-v3.0 -- lesson-03-task.css
```

三条命令分别做三件完全不同的事：

|命令|它做了什么|做完工作目录有变化吗|
|---|---|---|
|`git remote add course <网址>`|给教师模板仓库起个代号，只写一行配置|**没有**，不联网不下载|
|`git fetch course <分支>`|把这个分支下载到 `.git` 里|**没有**，文件还看不见|
|`git checkout course/<分支> -- <文件名>`|把指定文件写进工作目录|**有**，文件出现了|

**第二步最容易被误解**：`fetch` 跑完你去 `dir`，文件**还是不存在**。
这不是失败——它只下载到了 `.git` 这个"仓库数据库"里，没写到你看得见的地方。
`checkout` 才是真正把文件写出来的一步。`--` 是分隔符，意思是"后面全是文件名"。

第一条如果提示 `remote course already exists`，说明之前加过了，**跳过它**接着执行后两条。

**第二步：确认文件真的到手了，再往下走。**

**Windows CMD**

```

**Windows PowerShell**

```

**看到 `Ready for changes` 才算成功。** 浏览器通常会自动打开；
没自动打开就自己访问 <http://localhost:7000>。

**三件事要记住**：

1. **这个终端要一直开着。** 关掉它服务就停了，页面会打不开。
2. **停止服务按 `Ctrl + C`**（在跑着服务的那个终端里按）。
3. **改完代码按 `Ctrl+S` 保存，浏览器会自己刷新**，
   不用再按 `Ctrl+R`。这就是"热更新"。

### 第四步：打开开发者工具

按 `F12`，**整节课都开着**。这一课要用 Elements，还要用**设备工具栏**：
   - **左上角的手机图标**：切换手机 / 平板 / 桌面尺寸；
   - **右上角显示的视口尺寸**：像 `640 × 812`，拉窗口时实时变化，
     用来验证断点到底发生在多少像素。

> **这一课最重要的操作习惯**：把浏览器窗口调成不到半屏宽，
> **每做完一步都从最窄拉到最宽再拉回来。**
> 响应式的效果只有拉窗口才看得见，一直全屏看会以为什么都没变。

### 为什么不双击打开 HTML

双击打开时，浏览器地址栏是 `file:///E:/.../index.html`；
用服务器打开是 `http://localhost:7000`。**这两个不是一回事。**

|  |双击打开（file 协议）|本地服务器（http 协议）|
|---|---|---|
|改完代码|**要自己按 `Ctrl+R` 刷新**|**自动刷新**|
|读取本地 JSON、用 `fetch`|**会被浏览器拦住**（跨域限制）|正常|
|`type="module"` 的脚本|**加载不了**|正常|
|`localStorage`|行为和正式环境不一样|和正式环境一致|
|同学能不能看到|不能|**能**，见下面|
|和上线之后的环境|不一样|**几乎一样**|

后面几课会用到 JSON 数据、模块化脚本、本地存储，
**那时候用 file 协议打开会直接报错，而且报的错看起来毫无道理**
（"明明文件就在那儿"）。
**从第一课就用服务器，把这类坑一次性避掉。**

### `--host=0.0.0.0` 能做什么：让同学直接打开你的页面

加了这个参数之后，**同一个局域网里的其他设备可以访问你的页面**——
最实用的就是**用手机看自己做的页面**，尤其是第 03 课的响应式。

**第一步：查自己的局域网 IP**

**Windows CMD**

```bat
ipconfig
```

**Windows PowerShell**

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' -or $_.IPAddress -like '10.*' } | Select-Object IPAddress, InterfaceAlias
```

找 `IPv4 地址` 那一行，通常是 `192.168.x.x` 或 `10.x.x.x`。

**第二步：让同学（或你的手机）访问**

```text
http://你的IP:7000
```

比如 `http://192.168.1.23:7000`。**手机要连同一个 Wi-Fi。**

|问题|原因|处理|
|---|---|---|
|同学打不开|Windows 防火墙挡了|第一次启动时弹出的提示要选「允许访问」；已经点了拒绝就到「防火墙 → 允许应用」里放行 Node|
|手机打不开|不在同一个 Wi-Fi|确认手机和电脑连的是同一个网络，机房有时分了好几个网段|
|IP 有好几个|有虚拟网卡（VMware、WSL）|用 `192.168.` 开头那个通常没错，不行就一个个试|

> **安全提示**：`0.0.0.0` 的意思是"对本机所有网卡开放"。
> 在教室和家里的局域网没问题，**但不要在公共 Wi-Fi（咖啡馆、机场）下这么开**。
> 只想自己用的时候，把参数去掉就行：`npx live-server --port=7000`。

### 启动不起来怎么办

|终端里报什么|原因|处理|
|---|---|---|
|`'npx' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**；再 `node -v` 确认|
|卡在下载不动|npm 源慢|`npm config set registry https://registry.npmmirror.com` 之后重试|
|`EADDRINUSE` / 端口被占用|7000 已经被别的程序占了（**多半是你自己上一次没关**）|换一个端口：`--port=7001`；或者到之前那个终端按 `Ctrl+C`|
|浏览器显示目录列表，不是页面|工程根目录里没有 `index.html`|`dir index.html` 确认位置，`cd` 到对的目录重来|
|页面打开了但一片空白|HTML 里有错，或者文件名拼错|`F12` → Console 看红字；确认文件名大小写|
|改了代码不自动刷新|文件没保存；或者改的不是这个目录里的文件|`Ctrl+S`；确认 Trae 打开的文件夹和终端所在的是同一个|

**实在起不来也别耽误上课**：先双击 `index.html` 应急，
本课绝大部分内容照样能做，**下课前再来解决**。

### TODO 01 · 把作品列表变成网格容器

**难度**：极简单


**为什么做这个**
这是整个响应式的地基。不先变成网格，后面六个任务全都无从谈起。
同时它能立刻演示一件事：**有些属性只在特定布局下才起作用。**

**涉及的知识点**

`display` 决定这个元素**内部**怎么排列它的子元素：

|值|排法|
|---|---|
|`block`|普通块级，子元素从上到下堆叠|
|`flex`|一维弹性，子元素排成一行或一列|
|`grid`|二维网格，可以同时规定行和列|

**改哪里**：`lesson-03-task.css` 里 `.portfolio-list` 的 `display`，`block` → `grid`。

**操作前 / 操作后**

- 操作前：四张作品卡上下紧挨着，中间没有空隙。
- 操作后：四张卡之间出现 **30px 的间隙**，看得出是四块独立的卡片了。

**自己验证**
1. 保存刷新，卡片之间出现空隙。
2. **注意：还是一列。** 这是对的——列数要 TODO 02 才设。
3. F12 → Elements 选中 `.portfolio-list`，Styles 里能看到 `display: grid`。
   Chrome 会在它旁边显示一个小小的 `grid` 标记，点一下能把网格线画在页面上。

**多想一步**
`gap: 30px` 这一行**本来就在文件里**，你一个字都没动，它却突然生效了。
因为 `gap` 只在 grid 和 flex 布局下有意义，`block` 布局下浏览器直接忽略它。
**CSS 里有不少这种"要搭配使用才生效"的属性**，写了没反应时先想想：
它依赖的那个前提条件满足了吗？

### TODO 02 · 桌面上一行放两张卡

**难度**：简单


**为什么做这个**
**这是本课变化最大的一步。** 四张卡从竖着一条排下来，变成整齐的四宫格，
页面一下子就"像个作品集"了。

**涉及的知识点**

```css
grid-template-columns: repeat(2, minmax(0, 1fr));
```

|部分|意思|
|---|---|
|`grid-template-columns`|规定网格有几列、每列多宽|
|`repeat(2, X)`|把 X 连续写两次，等于建立两列|
|`fr`|fraction，份额。`1fr` = 占剩余空间的 1 份|
|`minmax(0, 1fr)`|这一列最小可以缩到 0，最大占 1 份|

**为什么不直接写 `1fr`，非要套一层 `minmax(0, 1fr)`？**

网格列的默认最小宽度是 `auto`，意思是"不能比里面的内容还窄"。
万一某张卡里有一个很长的不换行的英文单词或者网址，这一列就会被撑开，
**整个页面出现横向滚动条**。把最小值压到 0 就不会了。
这是 Grid 布局里最常见的一个坑，很多人做完响应式发现手机上能左右拖动，
原因就在这里。

**改哪里**：`.portfolio-list` 的 `grid-template-columns`，改成 `repeat(2, minmax(0, 1fr))`。

**操作前 / 操作后**

- 操作前：四张卡竖着一列排下来。
- 操作后：桌面宽度下变成 **2×2 四宫格**，两列等宽。

**自己验证**
1. 保存刷新，四宫格出现。
2. 把窗口慢慢拉窄，两列会**一起变窄**（因为用的是 `fr` 份额，不是固定像素）。
3. **对比实验**：临时改成 `repeat(2, 1fr)`（去掉 minmax），
   然后在某张卡的标题里粘一串很长的英文，比如
   `averyveryverylongwordwithoutanyspace`，刷新——
   页面底部出现横向滚动条。改回 `minmax(0, 1fr)` 就没了。**做完把长单词删掉。**

**多想一步**
`fr` 和 `%` 有什么区别？`50%` 是"容器宽度的一半"，**不扣掉 gap**，
两列各 50% 加上 30px 的 gap 就超出了容器，会溢出。
`1fr` 是"**剩余**空间的一份"——浏览器先扣掉 gap，再把剩下的分。
**做网格布局用 `fr`，别用 `%`。**

### TODO 03 · 让四张封面一样高、还不变形

**难度**：简单


**为什么做这个**
四张封面图的原始尺寸不一定相同。不处理的话卡片高矮不齐，
四宫格看着就"歪"。这个任务解决的是**图片和容器尺寸对不上**这个通用问题。

**涉及的知识点**

两个属性配合：

```css
.work-cover { aspect-ratio: 3 / 2; overflow: hidden; }  /* 框固定 3:2 */
.work-cover img { width: 100%; height: 100%; object-fit: cover; }
```

`object-fit` 的三个常用值，**一定要挨个试一遍**：

|值|做法|结果|
|---|---|---|
|`fill`（默认）|把图片拉伸／压扁塞满框|**画面变形**，人脸会被压扁或拉长|
|`cover`|保持比例放大到铺满框，超出部分裁掉|不变形，但会裁掉边缘|
|`contain`|保持比例缩小到完全装进框，四周留空|不变形不裁边，但有空白条|

**封面图几乎总是用 `cover`**：宁可裁掉一点边，也不能让画面变形。
`contain` 适合商品图、logo 这类"必须完整显示"的场景。

**改哪里**：`.work-cover img` 的 `object-fit`，`fill` → `cover`。

**操作前 / 操作后**

- 操作前：四张封面被**拉伸变形**（横图被压扁、竖图被拉长），高矮也可能不齐。
- 操作后：四张封面**一样高、比例正常**，四宫格整整齐齐。

**自己验证**
1. 改之前先仔细看一眼封面里的画面比例，记住它变形的样子。
2. 改成 `cover` 刷新，对比。
3. **再改成 `contain` 刷新**——图片完整了，但上下或左右出现空白条。
4. 三个值都看过之后，留在 `cover`。
5. F12 → Elements 选中 `.work-cover`，Styles 里能看到 `aspect-ratio: 3 / 2`；
   把它临时删掉，卡片高度立刻变得参差不齐。看完撤销。

**多想一步**
`overflow: hidden` 这一行不能删。`cover` 会把图片放大到铺满框，
放大之后**超出框的部分默认还是会画出来**，盖住旁边的内容。
`overflow: hidden` 就是"超出我这个框的部分不要画"。
**"固定比例的框 + `object-fit: cover` + `overflow: hidden`"是一套固定搭配**，
以后做任何图片列表都用得上。

### TODO 04 · 鼠标移上去，卡片轻轻上浮

**难度**：简单


**为什么做这个**
前三个任务都是"静态排版"。这一个第一次加上**交互反馈**——
让用户知道"这张卡是可以点的"。

**涉及的知识点**

这个任务有**两处**要改，分别管"变成什么样"和"怎么变过去"：

```css
.work-card { transition: transform 180ms ease, box-shadow 180ms ease; }  /* 怎么变 */
.work-card:hover { transform: translateY(-4px); }                        /* 变成什么样 */
```

|部分|意思|
|---|---|
|`transition: 属性 时长 节奏`|这个属性变化时，用多久播完，什么节奏|
|`ease`|开头和结尾慢、中间快，比匀速（`linear`）自然|
|`180ms`|0.18 秒。**150—250ms 是界面动效的舒适区**，短了看不见，长了粘手|
|`transform: translateY(-4px)`|沿垂直方向移动。Y 轴向下为正，所以负数是向上|

**`transform` 和 `margin-top: -4px` 有什么区别？**
效果看起来一样，但 `margin` 会**重新挤动周围所有元素**，浏览器要重算整页布局；
`transform` 只改"画出来的位置"，布局不变。
**做动效永远优先用 `transform` 和 `opacity`**，这两个最省性能。

**还要注意选择器里的 `:focus-within`**——意思是"内部任何元素获得键盘焦点时"。
手机上没有鼠标、永远不会 `hover`，键盘用户也用不上，
所以交互效果要把 `:focus` 一起写上。

**改哪里**：两处。`.work-card` 的 `transition`，和 `.work-card:hover` 的 `transform`。

**操作前 / 操作后**

- 操作前：鼠标移到卡片上没有任何反应。
- 操作后：卡片**轻轻上浮 4px、阴影加深**，像被拿起来一点；移开时平滑落回。

**自己验证**
1. 鼠标在卡片上移进移出几次，动作应该是**平滑**的。
2. 只改 `transform` 不改 `transition` 试试——卡片"啪"地跳上去，很生硬。
3. **用键盘验证**：连按 `Tab` 键，直到焦点进入某张卡片里的链接，
   卡片应该有同样的上浮效果。这就是 `:focus-within` 的作用。
4. 把 `-4px` 改成 `-40px` 刷新——夸张到能看清它确实是"浮起来"而不是"变大"。
   看完改回 `-4px`。

**多想一步**
文件最后那段 `@media (prefers-reduced-motion: reduce)` 是什么？
操作系统里有个"减少动态效果"的辅助功能开关。
**有些人看到页面上的动效会头晕**（前庭功能障碍），这不是矫情。
开了这个开关的用户，浏览器会让这段媒体查询生效，把过渡关掉。
**凡是写动效，都要配一段这个。** 这和写 `alt` 一样，是基本要求不是加分项。

### TODO 05 · 把窗口拉窄，四宫格变一列

**难度**：中等


**为什么做这个**
**这是"响应式"三个字第一次真正出现。** 前面四个任务在手机上效果都很差：
两列意味着每列不到 200px，图片和文字挤成一团。

**涉及的知识点：媒体查询**

```css
@media (max-width: 640px) {
  .portfolio-list { grid-template-columns: 1fr; }
}
```

|部分|意思|
|---|---|
|`@media`|媒体查询，"满足条件时才应用里面的规则"|
|`(max-width: 640px)`|条件：**可视区域宽度不超过** 640px 时|
|640px|**断点（breakpoint）**，一个经验分界值|

**断点不对应任何一款具体手机。** 常见的经验值是 640 / 768 / 1024 / 1280，
分别大致对应 手机 / 平板竖屏 / 平板横屏 / 桌面。
选哪个不重要，重要的是**在内容真的挤不下的地方切**。

**改哪里**：文件里那段 `@media (max-width: 640px)` 内部的 `grid-template-columns`，
改成 `1fr`。

**操作前 / 操作后**

- 操作前：把窗口拉到很窄，作品仍然是两列，挤成一团。
- 操作后：窗口拉窄到 640px 以下时，**四宫格突然变成一列**，一张一张往下排。

**自己验证**
1. **慢慢来回拉动窗口宽度**，能清楚看到"跳变"发生在某个位置。
2. F12 → 左上角手机图标，切到 iPhone 尺寸，应该是一列。
3. F12 打开时右上角会显示当前视口宽度（像 `640 × 812`），
   对照着拉，验证跳变确实发生在 640 附近。
4. 窄屏下**不应该有横向滚动条**。有的话回头检查 TODO 02 的 `minmax(0, 1fr)`。

**多想一步**
`max-width` 是"最大宽度条件"，写的是"**窄到**多少时生效"，
这种从宽到窄逐步覆盖的写法叫**桌面优先**。
反过来用 `min-width`，先写手机样式再逐步加宽，叫**移动优先**，
是现在更主流的做法。本课用桌面优先是因为模板的基础样式已经是桌面版了，
两种思路没有对错，一个项目里统一用一种就行。

### TODO 06 · 大标题跟着屏幕宽度缩放

**难度**：中等


**为什么做这个**
把窗口拉到很窄，你会发现 46px 的大标题占掉大半个屏幕，
甚至撑出横向滚动条。**字号也需要响应式。**

**涉及的知识点：`clamp()`**

老办法是写好几个断点：

```css
h1 { font-size: 46px; }
@media (max-width: 900px) { h1 { font-size: 38px; } }
@media (max-width: 640px) { h1 { font-size: 30px; } }
@media (max-width: 400px) { h1 { font-size: 26px; } }
```

又长又难维护，而且在断点处是"跳变"的。新办法一行搞定：

```css
h1 { font-size: clamp(28px, 6vw, 46px); }
```

|部分|意思|
|---|---|
|`clamp(最小, 理想, 最大)`|取理想值，但不小于最小、不大于最大|
|`vw`|viewport width，**1vw = 可视区域宽度的 1%**|
|`6vw`|屏幕 1000px 宽时 = 60px；屏幕 400px 宽时 = 24px|

所以 `clamp(28px, 6vw, 46px)` 的实际行为是：
窄屏被 28px 兜住 → 中间跟着屏幕平滑变 → 宽屏被 46px 封顶。

**改哪里**：`lesson-03-task.css` 里 TODO 06 注释下面的空白处，补一条 `h1` 规则。

**操作前 / 操作后**

- 操作前：慢慢拉动窗口，标题字号**纹丝不动**，窄屏时显得特别大甚至换行难看。
- 操作后：拉动窗口时标题**平滑地跟着变大变小**，两端有上下限兜住。

**自己验证**
1. 从最窄拉到最宽，标题应该是**连续变化**的，没有跳变。
2. 拉到极窄（比如 320px），标题不会小得看不清——被 28px 兜住了。
3. 拉到极宽（比如 1920px），标题不会大得离谱——被 46px 封顶了。
4. F12 → Elements 选中 `h1`，Computed 面板里的 `font-size` 会随着你拉窗口实时变化。
5. **对比实验**：临时改成 `font-size: 6vw`（去掉 clamp），
   拉到极宽时标题会大到夸张。看完改回来。

**多想一步**
`vw` 有个陷阱：它是**视口宽度**的百分比，和字号大小、用户的浏览器设置都无关。
如果一个视力不好的用户把浏览器默认字号调大，`px` 和 `rem` 会跟着变大，
但纯 `vw` 不会。所以正规做法是把 `rem` 掺进去，比如
`clamp(1.75rem, 4vw + 1rem, 2.875rem)`。本课先掌握 `clamp` 的形状，
这个细节知道有这么回事就行。

### 已写好 · 让列数自己决定，不写死

**为什么做这个**
回头看 TODO 02 和 TODO 05：你写死了"桌面两列、手机一列"。
那平板呢？折叠屏呢？超宽屏呢？每多一种屏幕就要多一个断点。

**这个任务展示 Grid 最强的一个能力：让浏览器自己算该排几列。**
一行代码顶掉所有断点。

**涉及的知识点**

```css
grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
```

读法：重复若干列，每列**最小 260px、最大占 1 份**；
至于到底重复几列，**由浏览器根据容器宽度自己算**。

|容器宽度|能放下几个 260px|结果|
|---|---|---|
|900px|3 个|三列|
|600px|2 个|两列|
|300px|1 个|一列|

`auto-fit` 和 `auto-fill`的区别：元素不够填满时，
`auto-fit` 会把剩余空间分给已有的列（列变宽），`auto-fill` 会留着空列。
做卡片列表一般用 `auto-fit`。

## 6. Git 提交与推送

### 第一步：先看清楚自己改了什么

### 第三步：推送到你自己的仓库

```bat

```

**如果报 `'origin' does not appear to be a git repository`：**

这是正常的，不是你操作错了。本课工程是从上一课或教师模板克隆来的，
它的来源已经被改名成 `previous` / `course`——那是**别人的仓库，不能推**。

"Add a README file"，否则会和本地冲突），然后：

**Windows CMD**

```bat

git remote add origin https://github.com/你的用户名/p1-lesson-03-学号.git

REM -M 把当前分支强制改名成 main
git branch -M main

REM -u 记住这次的目标，以后只写 git push 就够了
git push -u origin main

REM 确认：origin 应该指向你自己的仓库

**Windows PowerShell**

git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。

## 常见问题

### 布局不对

|现象|原因|处理|
|---|---|---|
|改了 CSS 完全没反应|`index.html` 里没引用 `lesson-03-task.css`|见第 2 节第三步|
|引用了也没反应|引用写在了 `styles.css` **前面**|两行调换顺序，后写的才赢|
|还是没反应|浏览器缓存了旧 CSS|按 `Ctrl+F5` 强制刷新；也确认一下跑 live-server 的终端还开着|
|设了 `gap` 没有间隙|还是 `display: block`|`gap` 只在 grid / flex 下有效|
|列数不对|`grid-template-columns` 写错，或被后面的规则覆盖了|F12 选中元素，Styles 里被划掉的就是输掉的规则|
|**页面出现横向滚动条**|列宽写成了 `1fr` 没套 `minmax(0, ...)`|改成 `minmax(0, 1fr)`|
|横向滚动条还在|某张图片或某段文字比容器宽|F12 → Elements 逐个元素看，哪个的宽度超了|

### 图片不对

|现象|原因|处理|
|---|---|---|
|图片变形|`object-fit` 还是 `fill`|改成 `cover`|
|图片四周有空白条|用了 `contain`|封面图用 `cover`|
|图片溢出盖住别的内容|`overflow: hidden` 被删了|加回 `.work-cover` 上|
|卡片高矮不齐|`aspect-ratio` 被删了|加回 `.work-cover` 上|

### 交互不对

|现象|原因|处理|
|---|---|---|
|悬停"啪"地跳|漏了 `transition`|`.work-card` 上补 `transition: transform 180ms ease, box-shadow 180ms ease`|
|悬停时周围卡片跟着动|用了 `margin` 而不是 `transform`|改用 `transform: translateY(-4px)`|
|键盘 Tab 没有效果|选择器里漏了 `:focus-within`|两个选择器要用逗号一起写|
