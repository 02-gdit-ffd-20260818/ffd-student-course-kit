### 三个最小例子，本课六个任务都是它们的变形

**例 1：数组装对象**

```js
const students = [
  {{ name: '张三', age: 19 }},   // 一个对象 = 一张登记表
  {{ name: '李四', age: 20 }},
]
console.log(students[0].name)   // 张三——先按下标取对象，再按名字取属性
```

**例 2：对每一项做同一件事**

```js
students.forEach(student => {{
  console.log(student.name)     // 数组里有几项就执行几次
}})
```

**例 3：筛选和排序**

```js
const adults = students.filter(s => s.age >= 20)        // 只留满 20 岁的
const sorted = [...students].sort((a, b) => b.age - a.age)  // 按年龄从大到小
//             ↑ 先复制一份再排，否则原数组会被改掉
```

**这三个例子的分工要讲透**：数组和对象负责"把数据组织好"，
`forEach` 负责"逐条处理"，`filter` 和 `sort` 负责"挑出要的、排成想要的顺序"。
本课所有 TODO 都跳不出这四件事。

> **这一课要建立的核心观念**：第 01 课你是用复制粘贴写出四张作品卡的 HTML。
> 加一个作品就要复制一大段标签，改一个字段要在四处改。
> 这一课之后，**加作品只要在数组里多写一个对象，HTML 一个字都不用动。**
> 这个思路后面每个项目都会用到——项目 4 的文案库、项目 5 的歌单，都是同一回事。

三条命令分别做三件完全不同的事：

|命令|它做了什么|做完工作目录有变化吗|
|---|---|---|
|`git remote add course <网址>`|给教师模板仓库起个代号，只写一行配置|**没有**，不联网不下载|
|`git fetch course <分支>`|把这个分支下载到 `.git` 里|**没有**，文件还看不见|
|`git checkout course/<分支> -- <文件名>`|把指定文件写进工作目录|**有**，文件出现了|

第一条如果提示 `remote course already exists`，说明之前加过了，**跳过它**接着执行后两条。

**第二步：确认两个文件都到手了，再往下走。**

|`--port=7000`|服务开在 7000 端口。网址就是 `http://localhost:7000`|
|`--host=0.0.0.0`|**允许同一个局域网里的其他设备访问**（不加只有本机能开）|

### 第三步：确认启动成功

终端里会打印出类似这样的内容：

```text
Serving "E:\...\p1-lesson-05" at http://127.0.0.1:7000
Ready for changes
```

**看到 `Ready for changes` 才算成功。** 浏览器通常会自动打开；
没自动打开就自己访问 <http://localhost:7000>。

**三件事要记住**：

1. **这个终端要一直开着。** 关掉它服务就停了，页面会打不开。
2. **停止服务按 `Ctrl + C`**（在跑着服务的那个终端里按）。
3. **改完代码按 `Ctrl+S` 保存，浏览器会自己刷新**，
   不用再按 `Ctrl+R`。这就是"热更新"。

### 第四步：打开开发者工具

按 `F12`，**整节课都开着**。**整节课都开着 Console 标签。**
   这一课比前几课更依赖它：JavaScript 出错只在 Console 里说，页面上什么都不显示。

> **这一课要养成一个新习惯：用 Console 直接查数据。**
> 在 Console 里输入 `works` 回车，能看到整个数组；
> 输入 `works[0].title` 能取到第一个作品的标题。
> **不确定数据对不对，就去 Console 问一句**，比盯着代码猜快得多。
>
> 注意热更新会重新加载页面，**Console 里的历史输出会被清空**，
> 这是正常的，不是出错了。

### 为什么不双击打开 HTML

双击打开时，浏览器地址栏是 `file:///E:/.../index.html`；
用服务器打开是 `http://localhost:7000`。**这两个不是一回事。**

|  |双击打开（file 协议）|本地服务器（http 协议）|
|---|---|---|
|改完代码|**要自己按 `Ctrl+R` 刷新**|**自动刷新**|
|读取本地 JSON、用 `fetch`|**会被浏览器拦住**（跨域限制）|正常|
|`type="module"` 的脚本|**加载不了**|正常|
|`localStorage`|行为和正式环境不一样|和正式环境一致|
|同学能不能看到|不能|**能**，见下面|
|和上线之后的环境|不一样|**几乎一样**|

后面几课会用到 JSON 数据、模块化脚本、本地存储，
**那时候用 file 协议打开会直接报错，而且报的错看起来毫无道理**
（"明明文件就在那儿"）。
**从第一课就用服务器，把这类坑一次性避掉。**

### `--host=0.0.0.0` 能做什么：让同学直接打开你的页面

加了这个参数之后，**同一个局域网里的其他设备可以访问你的页面**——
最实用的就是**用手机看自己做的页面**，尤其是第 03 课的响应式。

**第一步：查自己的局域网 IP**

**Windows CMD**

```bat

```

**Windows PowerShell**

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' -or $_.IPAddress -like '10.*' } | Select-Object IPAddress, InterfaceAlias
```

找 `IPv4 地址` 那一行，通常是 `192.168.x.x` 或 `10.x.x.x`。

**第二步：让同学（或你的手机）访问**

```text

```

比如 `http://192.168.1.23:7000`。**手机要连同一个 Wi-Fi。**

|同学打不开|Windows 防火墙挡了|第一次启动时弹出的提示要选「允许访问」；已经点了拒绝就到「防火墙 → 允许应用」里放行 Node|

### TODO 03 · 把一条数据变成一张卡片

**难度**：简单


**为什么做这个**
前两个任务只是准备数据。这一个才是真正的"渲染"——
把一个对象翻译成一堆 DOM 元素。

**涉及的知识点**

|写法|作用|
|---|---|
|`document.createElement('li')`|凭空造一个元素（还没放进页面）|
|`元素.textContent = '文字'`|设置里面的纯文字|
|`元素.className = 'work-card'`|设置 class，CSS 靠它找到这个元素|
|`父元素.append(子元素)`|把子元素放进父元素里|
|`` `${{work.title}}的网页截图` ``|模板字符串，反引号包起来，`${{}}` 里放变量|

**三个要点，每个都有真实原因：**

1. **用 `textContent` 而不是 `innerHTML`。**
   `innerHTML` 会把内容当成 HTML 解析。万一数据里有 `<script>`，它会被执行。
   `textContent` 一律当纯文字，安全得多。**凡是显示"别人提供的内容"，都用 `textContent`。**
2. **`alt` 要说清楚图上是什么**：`` `${{work.title}}的网页截图` ``，不能只写"图片"。
3. **`img` 的 `width` / `height` 不要删。** 浏览器靠它们在图片下载完之前
   就预留好位置，否则图片一加载页面会"跳一下"，正在读的人会跟丢。
   这个问题有个名字叫**布局偏移（CLS）**。

**改哪里**：`works-render.js` 里 `createWorkCard` 函数，补全六处 `/* 填这里 */`。

### TODO 05 · 点标签只显示相关作品

**难度**：中等


**这是本课效果最强的一步。** 点一下标签，四张卡立刻只剩下相关的那几张。

**为什么做这个**
作品多了以后，访客需要快速找到他关心的那类。
更重要的是：这个任务让你第一次体会到**"界面 = 状态的函数"**——
状态（`activeTag`）一变，整个列表就按新状态重画一遍。

**涉及的知识点**

```js
const filtered =
  activeTag === '全部' ? works : works.filter(work => work.tags.includes(activeTag))
```

|部分|作用|
|---|---|
|`条件 ? A : B`|三元运算符。条件成立取 A，否则取 B|
|`filter(条件函数)`|只留下让条件返回 `true` 的项，**返回新数组**|
|`数组.includes(值)`|这个数组里有没有这个值|

**`filter` 返回的是新数组，原数组 `works` 完全不动。**
这一点很重要：如果 `filter` 会改动原数组，那你筛过一次「AI」之后，
再点「全部」就只剩下 AI 的作品了——数据被越筛越少。

**改哪里**：`works-render.js` 里 `getVisibleWorks` 函数，把 `return works` 改掉。

### TODO 06 · 点排序按钮，卡片顺序重排

**难度**：中等


**为什么做这个**
筛选解决"看哪些"，排序解决"先看哪个"。
这个任务还有一个专门的教学目的：**让你踩一次 `sort` 会改原数组的坑。**

**涉及的知识点**

```js
return [...filtered].sort((a, b) => (newestFirst ? b.year - a.year : a.year - b.year))
```

|部分|作用|
|---|---|
|`[...filtered]`|**先复制一份**。展开语法会生成一个新数组|
|`sort(比较函数)`|排序。**会就地改动数组本身**|
|`(a, b) => b.year - a.year`|返回负数 a 排前面，正数 b 排前面。这里是"年份大的在前"|

**`[...]` 这一层复制绝对不能省。**
`sort` 和 `filter` 不一样：`filter` 返回新数组，`sort` 直接改原数组。
忘了复制的话，切换几次排序，`works` 里的原始顺序就被**永久打乱**了——
而且这个 bug 很隐蔽，因为界面看起来"好像也能用"。

**改哪里**：两处。
`getVisibleWorks` 里的排序（TODO 06 的一半），
和文件末尾 `sortButton` 的 click 监听（另一半）。

### 已写好 · 根据数据自动生成标签按钮

**为什么做这个**
筛选要有按钮可点。但按钮**不应该手写在 HTML 里**——
那样你在数据里加一个新标签，还得记得回去改 HTML，迟早会忘。

**让按钮由数据算出来。** 这是本课"数据驱动"思想的第二次体现。

**涉及的知识点**

```js
const tags = ['全部', ...new Set(works.flatMap(work => work.tags))]
```

这一行有三个东西，拆开看：

|部分|作用|例子|
|---|---|---|
|`flatMap`|取出每项的数组并**摊平**成一个大数组|`[['前端','后端'],['前端']]` → `['前端','后端','前端']`|
|`new Set(...)`|去重。Set 里同样的值只存一份|`['前端','后端','前端']` → Set {{前端, 后端}}|
|`...`（展开）|把 Set 摊回普通数组|Set {{前端, 后端}} → `['前端','后端']`|

前面再拼一个 `'全部'`，就是完整的按钮列表。

**还要注意 `aria-pressed`**：

```js
button.setAttribute('aria-pressed', String(tag === activeTag))
```

它一举两得：CSS 里写了 `button[aria-pressed="true"]` 的高亮样式；
读屏软件读到它会说"已按下"。**一个属性同时服务于视觉和无障碍。**

## 常见问题

### 报错类

|Console 里的报错|原因|处理|
|---|---|---|
|`works is not defined`|两个 `<script>` 顺序反了|`works-data.js` 必须在 `works-render.js` **前面**|
|`Cannot read properties of undefined`|数据里少了某个字段，或字段名拼错|对照 `works-data.js` 检查六个字段名|

|`box is null`|页面上没有 `#works-tags`|第 2 节第三步的工具条 HTML 没加|

### 效果不对类

|现象|原因|处理|
|---|---|---|
|一张卡都没有|数据数组是空的，或 TODO 01 没填|Console 输入 `works` 看看有没有东西|
|卡片有框但没内容|TODO 03 的六处没填|逐个检查 `/* 填这里 */`|
|年份徽标不显示|`year` 字段写成了字符串，或 TODO 03 漏了|`year: 2026` 不要加引号|
|页面上出现 `undefined`|某个字段名拼错了|`work.titel` → `work.title`|
|标题里的 HTML 标签真的生效了|用了 `innerHTML`|改成 `textContent`|
|点标签没反应|`renderWorks()` 没被调用|点击事件里要同时调 `renderTags()` 和 `renderWorks()`|
|点回「全部」作品少了|`filter` 用错了，或改动了原数组|`filter` 返回新数组，不要写成 `works = works.filter(...)`|
|排序点几次之后顺序乱了|`sort` 前面漏了 `[...]`|`[...filtered].sort(...)`|
|筛选之后排序失效|两个功能没写在同一个出口|都要在 `getVisibleWorks` 里|
|按钮出现但不高亮|`aria-pressed` 没设，或设成了布尔值|要用 `String(tag === activeTag)`|
