### 本课要用到的 HTTP 方法

|方法|意思|本课的接口|
|---|---|---|
|`GET`|取数据，**不改变任何东西**|`GET /api/articles`|
|`POST`|新建一个|`POST /api/articles`|
|`PUT`|整体替换一个|`PUT /api/articles/:id`|
|`DELETE`|删掉一个|`DELETE /api/articles/:id`|

**`GET` 不能有副作用**，这是一条铁律。
写成 `GET /api/articles/5/delete` 这种接口会出事——
浏览器预加载、搜索引擎爬虫、甚至聊天软件生成预览，都会自动发 `GET` 请求。
真出现过网站被爬虫"点"光所有删除链接的事故。

### 一个最小例子：同一段代码处理新增和修改

```js
for (const method of ['post', 'put'])
  app[method](method === 'post' ? '/api/articles' : '/api/articles/:id', admin, handler)
```

新增和修改的校验、字段处理**完全一样**，只有 SQL 和状态码不同。
与其写两份几乎一样的代码（改一处忘一处），不如合成一处、用 `method` 区分。

**这一课要建立的核心观念**：

> **权限判断必须放在后端，而且要"不该给的数据一开始就不查出来"。**

前端"把草稿藏起来不显示"是没用的——数据已经发到浏览器了，F12 一看全在。

## 2. 生成本机配置

**Windows CMD**

```bat
if not exist .env copy .env.example .env
findstr /B /C:"PORT=" /C:"DATABASE_PATH=" /C:"SESSION_SECRET=" /C:"ADMIN_USERNAME=" /C:"ADMIN_PASSWORD=" .env
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`findstr` 在文件中查找文字；`/B` 只匹配行首；每个 `/C:"字段="` 是一个完整查找词，多个 `/C` 表示任意一个匹配就显示；最后的 `.env` 是要读取的文件。`/R` 表示用正则表达式，`^` 是行首，`[A-Z_]` 是大写字母或下划线，`*` 是重复零次或多次。输出只用于本机检查，含密钥的行不要截图或发给别人。

`copy`（CMD）/ `Copy-Item`（PowerShell）把第一个路径的文件复制到第二个路径。只在目标配置尚不存在时复制模板；已有 .env 时直接打开并检查所需项，避免覆盖已经填写的值。
<!-- COMMAND_HELP:END -->


**Windows PowerShell**

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' }
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`Test-Path -LiteralPath 路径` 检查这个原样路径是否存在，返回 True 或 False；`-not` 取反。`if (...) { ... }` 只在条件成立时执行花括号里的操作，因此这里已有 .env 就不再覆盖。

`Get-Content` 逐行读取文件；`|` 把读取结果交给右边；`Where-Object` 只保留条件成立的行；`$_` 代表正在检查的那一行；`-match` 表示正则匹配；`^[A-Z_]+=` 表示行首是一个或多个大写字母/下划线，紧接等号。
<!-- COMMAND_HELP:END -->


能看到英文配置行就说明复制成功；不再用 CMD 的 `type .env` 打印中文注释，避免 UTF-8 乱码。
运行下面的命令生成随机值，并填到 `.env` 的 `SESSION_SECRET=` 后面：

```bat
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

**把命令逐段读懂**：`node` 是在终端运行 JavaScript；`-e` 表示直接执行引号内代码；
`require('node:crypto')` 加载 Node 自带密码学模块；`randomBytes(32)` 生成 32 字节安全随机数据；
`toString('base64url')` 把它变成约 43 个可复制字符；`console.log` 只负责打印。
命令不会自动修改任何文件：要把输出复制到自己的 `.env`，不要放进 `.env.example` 或 Git。

**这一课还要配一个管理员账号。** 打开 `.env`，填上：

```ini
ADMIN_USERNAME=admin
ADMIN_PASSWORD=你自己设置的至少12位密码
```

上面的中文是格式说明，**不要原样照抄为密码**。这三项只改 `.env`，不要改 `.env.example`。

后端**首次建库**时会用它创建一个 `role='admin'` 的账号。
公开注册出来的都是 `reader`，管理员只能这样建——
这是第 07 课 `CHECK(role IN ('reader','admin'))` 和 `DEFAULT 'reader'` 的配套设计。

> 填完之后如果数据库已经存在，管理员不会被创建。
> 按 TODO 01 保留旧库，在 `.env` 中选择未使用的新练习库路径，重启后端再试；不要删除个人数据。

**改了代码要不要重启？**

|改什么|要不要手动重启|
|---|---|

|终端里报什么|原因|处理|

### TODO 01 · 给文章表加上约束

**难度**：极简单


**为什么做这个**
和第 07 课的用户表一样：**表结构定错了，后面所有课都在错的地基上盖房子。**

**涉及的知识点**

|约束|作用|不写会怎样|
|---|---|---|
|`slug ... UNIQUE`|文章地址不能重复|两篇文章抢同一个网址，打开哪篇全看运气|

因为正文永远是**整篇一起读、整篇一起改**，从来不需要"查出第 3 段"。
建段落表反而要多一次 JOIN、多一次排序。
**按使用方式设计表结构**，不是拆得越细越对。

**改哪里**：`server/blog-db.js` 里 `articles` 表的建表语句，TODO 01 的位置。

### TODO 04 · 把文章真的写进数据库

**难度**：中等


**为什么做这个**
**这是本课最有成就感的一步。** 前五个任务都在做约束和校验，
这一个才让"新建文章"真正能用。

**涉及的知识点**

```js
// 新增
'INSERT INTO articles(slug,title,...) VALUES($1,$2,...,$9) RETURNING *'
// 修改
'UPDATE articles SET slug=$1,title=$2,... WHERE id=$10 RETURNING *'
```

|要点|说明|
|---|---|
|`$1`—`$9`|与上面 `values` 数组**逐项对应**，顺序不能乱|

### TODO 05 · 删掉不存在的东西要说清楚

**难度**：中等


**为什么做这个**
删除是四件事里**最危险**的一个——删错了通常拿不回来。
所以它要把"到底删没删掉"说清楚。

**涉及的知识点**

```js
const rows = await db.query('DELETE FROM articles WHERE id=$1 RETURNING id', [...])
if (!rows.length) return fail(res, 404, '文章不存在')
res.sendStatus(204)
```

`DELETE ... RETURNING id` 的巧妙之处：**真的删掉了才会返回一行，
什么都没删返回空数组**。靠它就能分辨"删成功"和"本来就没有"，
不用先 SELECT 一次再 DELETE。

**`204` 是什么？** "成功，但没有内容要返回"。
删除成功后没什么好给的，用 204 比返回 `200 {}` 更准确。

### 已写好 · 链接名只许英文数字短横线

**为什么做这个**
slug 是文章网址里的那一段，比如 `/articles/html5-media` 里的 `html5-media`。
它会出现在网址、分享链接、搜索引擎结果里。

**涉及的知识点**

```js
/^[a-z0-9][a-z0-9-]{0,99}$/.test(input.slug.trim())
```

|部分|意思|
|---|---|
|`^[a-z0-9]`|必须以小写字母或数字开头（**不能以短横线开头**）|
|`[a-z0-9-]{0,99}`|后面最多 99 个小写字母、数字或短横线|
|`$`|到此为止，整体匹配|

**为什么不许中文？** 网址里的中文要做百分号编码：
`我的文章` 会变成 `%E6%88%91%E7%9A%84%E6%96%87%E7%AB%A0`——
又长又难读，复制粘贴还容易断。

**为什么不能以短横线开头？** 有些工具会把 `-` 开头的字符串当成命令行参数。
这类"看起来无所谓"的限制，往往是被坑过之后加上的。

## 常见问题

### 数据库

|现象|原因|处理|
|---|---|---|
|**改了建表语句没生效**|`CREATE TABLE IF NOT EXISTS` 不改已有的表|按 TODO 01 保留旧库、在 .env 指定未使用的新练习库路径，重启并检查实际表结构|
