### 容器和虚拟机的区别（一分钟讲清）

|  |虚拟机|容器|
|---|---|---|
|装的是|一整个操作系统|只有应用和它的依赖|
|大小|几个 GB|几十到几百 MB|
|启动|几十秒到几分钟|**一秒以内**|
|隔离|硬隔离，各有各的内核|**共用宿主机内核**|

最后一行很关键：**容器不是虚拟机**，隔离没有那么强。
所以 TODO 05 才要求不用 root 跑应用。

### 这一课要建立的核心观念

> **容器是用完即弃的，数据不是。**

这句话是整个容器化部署的地基。容器随时可以删掉重建——升级、扩容、
修复故障都靠这个。但**数据必须活得比容器久**，所以要放在卷里。

本课的核心实验就一个：

```text
docker compose down      → 再 up  → 数据还在   （卷还在）
docker compose down -v   → 再 up  → 数据没了   （-v 把卷也删了）
```

**只实操第一行的保留卷重建。第二行仅解释风险，不执行；不要删除个人数据卷。**

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`findstr` 在文件中查找文字；`/B` 只匹配行首；每个 `/C:"字段="` 是一个完整查找词，多个 `/C` 表示任意一个匹配就显示；最后的 `.env` 是要读取的文件。`/R` 表示用正则表达式，`^` 是行首，`[A-Z_]` 是大写字母或下划线，`*` 是重复零次或多次。输出只用于本机检查，含密钥的行不要截图或发给别人。

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

### 第 15 课：连接 Docker 里的 PostgreSQL

1. 在有 `compose.yaml` 的目录新建 `compose.navicat.local.yaml`，写入：

`-f` 指定配置文件，后者只增加本机观察端口；`-d` 表示后台运行；`ps` 查看容器状态。

3. Navicat → 连接 → PostgreSQL，填写：

|字段|填写内容|
|---|---|
|连接名|第15课本机 PostgreSQL|
|主机/IP|`127.0.0.1`，不要填 Docker 服务名 postgres|
|端口|`15432`|
|初始数据库|根 `.env` 中 `POSTGRES_DB` 的值|
|用户名|`POSTGRES_USER` 的值|
|密码|`POSTGRES_PASSWORD` 的真实值|

5. 新建查询执行下面 SQL；返回当前库名即证明连接到了服务器：

```sql
SELECT current_database();
SELECT tablename FROM pg_tables WHERE schemaname = 'public';
```

`current_database()` 返回连接使用的数据库；`pg_tables` 是 PostgreSQL 的表目录；`public` 是本课应用表所在的模式。

**难度**：简单

### TODO 05 · 容器里不要用 root 跑应用

**难度**：中等


**为什么做这个**
容器**不是虚拟机**，它和宿主机共用同一个内核。
容器里的 root 在某些配置下（挂载了宿主目录、开了特权模式）
能影响到宿主机。用普通用户跑，等于多一层保险。

**涉及的知识点**

```dockerfile
COPY --chown=node:node backend ./backend
USER node
```

|部分|说明|
|---|---|
|`USER node`|这行之后的所有指令和最终的 CMD 都以 node 用户运行|
|`node` 用户|**Node 官方镜像里预置的普通用户**，不用自己建|
|`--chown=node:node`|设置复制文件的属主；是否能读还取决于文件权限，属主不是唯一条件|

**`USER node` 要写在 `RUN npm ci` 之后**——装依赖需要写权限。
位置写错了会构建失败。

配套的还有 `compose.yaml` 里那行：

```yaml
security_opt:
  - no-new-privileges:true
```

意思是"这个容器里的进程**不能再提权**"。

### 已写好 · 校验 JWT 令牌

**为什么做这个**
**这是已提供的认证保护，不是本课新增 TODO。理解验签与只解码的区别即可。**

**涉及的知识点**

```js
req.user = jwt.verify(token, jwtSecret(), { issuer: 'personalink' })
```

|函数|做什么|
|---|---|
|`jwt.decode(token)`|**只解码，不验签名**。任何人伪造的令牌它都照单全收|
|`jwt.verify(token, 密钥)`|**验签名 + 验过期**，任何一项不过就抛错|

**JWT 本身不是加密的。** 它的内容任何人都能解开看
（可在本地解码虚构示例观察 `role`、`userId`；不要把真实登录令牌贴到第三方网站）。
它的安全性**完全来自签名**——签名证明"这是我签发的、没被改过"。

所以用 `decode` 等于**只看内容不看签名**，
任何人都能自己造一个 `{"role":"admin"}` 的令牌进来。
**这两个函数名字很像，用错了等于没有认证。**

第三个参数 `{ issuer: 'personalink' }` 要求签发方必须是我们自己。
不校验的话，别人用同一个密钥给别的系统签的令牌也能拿来用。

> 知道它在做什么、为什么这么写即可，**不用动手改**。

### 已写好 · 让镜像构建快起来

**为什么做这个**
改一行业务代码，重新构建要等好几分钟——因为依赖被重装了一遍。
**这是 Dockerfile 最经典的一条优化。**

**涉及的知识点**

Docker 的每一条指令都会生成一"层"，只要这一层的**输入没变**，
下次构建就直接用缓存。**但只要有一层失效了，它后面所有层都跟着失效。**

|写法|结果|
|---|---|
|`COPY . .` 然后 `RUN npm ci`|改任何一个文件都让 COPY 层失效 → **每次都重装依赖**|
|先 `COPY package*.json` 再 `RUN npm ci`，最后 `COPY` 源码|依赖清单没变 → **装依赖那层一直用缓存**|

```dockerfile
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY backend ./backend
```

**顺序就是全部的秘密**：把"不常变的"放前面，"常变的"放后面。

|镜像下载特别慢|网络问题|配置国内镜像加速器（Docker Desktop 设置里）|

### 容器起不来

|现象|原因|处理|
|---|---|---|
|`Restarting` 反复重启|启动就崩|`docker compose logs backend` 看具体报错|
|后端报 `connection refused`|TODO 02 没做|加 `condition: service_healthy`|
|`port is already allocated`|端口被占了|改 `.env` 里的 `FRONTEND_PORT`|
|数据库一直 `starting`|健康检查命令写错了|`docker compose logs postgres` 看|
|改了 `.env` 没生效|容器还是旧的环境变量|**应用配置可重新创建容器；已有数据库卷中的凭据不会因此自动更改，需另行迁移凭据**|

### 数据

|现象|原因|处理|
|---|---|---|
|`down` 之后数据没了|TODO 01 没做，或者打了 `-v`|检查 volumes 声明；**确认没打 `-v`；不要反复删除容器，先检查并保留现有卷**|
|想清理数据卷|卷中可能仍有个人数据|本课不要求删卷；先备份并确认归属，不运行批量清理命令|
|导入数据报语法错误|MySQL 的 SQL 不能直接给 PostgreSQL 用|保留原备份；本工程没有自动转换脚本，先完成容器任务，迁移作为拓展另行验证|

### 构建

|现象|原因|处理|
|---|---|---|
|每次都重装依赖|已写好的代码 没做|先复制 package.json 再装依赖|
|`USER node` 之后构建失败|`USER` 写得太早|`USER node` 要在 `RUN npm ci` 之后|
|容器里读不了自己的代码|复制时没改属主|`COPY --chown=node:node`|
