### 这一课的核心观念

> **能写成纯函数的，就不要写进组件里。**

打开 `src/stores/queueCore.js`，从头翻到尾——
**没有一处出现 `ref`、`reactive`、`store`**。这是故意的。

|  |写进组件里|抽成纯函数|
|---|---|---|
|怎么测|要启动页面、要点鼠标、要等渲染|**传个数组进去，断言返回值**|
|改规则的风险|可能弄坏界面|界面碰都不用碰|
|能不能复用|绑死在这个组件上|**换个框架也能用**|

对照 `tests/queue.test.mjs`：**六个用例，毫秒级跑完，一次浏览器都没开。**

### 什么叫"不修改传进来的参数"

```js
// ❌ 改了原数组。调用方拿着同一个数组，在不知情的情况下内容变了
function add(queue, item) {
  queue.push(item)
  return queue
}

// ✅ 生成一个新数组，原来那个一动没动
function add(queue, item) {
  return [...queue, item]
}
```

**第一种写法的 bug 极难查**：出问题的地方往往离这个函数很远，
你会在另一个文件里发现"数组怎么莫名其妙多了一项"。

## 2. 先看懂队列是怎么分层的

这个项目的队列分成**三层**，各管各的：

```text
queueCore.js   纯函数：四个操作的规则（加、删、下一首、移动）
      ↑ 被调用
queue.js       Pinia store：存状态、记操作日志、调上面那些纯函数
      ↑ 被调用
App.vue        界面：显示队列、响应点击
```

**为什么要分三层？** 看一眼 `queue.js` 里的 `add` 方法：

```js
add(item) {
  const result = addUnique(this.items, item)   // ← 规则在纯函数里
  this.items = result.queue                    // ← 状态更新在 store 里
  if (result.added) this.log('加入', item.title)  // ← 副作用也在 store 里
  return result.added
}
```

**规则、状态、副作用三件事分开了。**
改"要不要去重"只动纯函数，改"记不记日志"只动 store，界面一行都不用碰。

### TODO 05 · 一个人不能一直点

**难度**：中等


**为什么做这个**
课堂上总有人连点十首把队列霸占了。

**涉及的知识点**

这叫**滑动窗口限流**，最朴素的写法就三步：

```js
// 1) 把超出窗口的时间戳扔掉
const active = (history.get(key) ?? []).filter(time => now - time < windowMs)
// 2) 满了就拒绝，并算出还要等多久
if (active.length >= max)
  return { allowed: false, key, retryAfterMs: windowMs - (now - active[0]) }
// 3) 放行，把这一次记上
history.set(key, [...active, now])
return { allowed: true, key, retryAfterMs: 0 }
```

**"还要等几秒"这一项很重要**：只说"太频繁了"而不说等多久，
用户会一直点一直被拒，体验很差。

计算方法：**最早那次点歌什么时候滑出窗口，就是什么时候能再点**。

**两个细节要讲**：

1. 函数签名里 `now = Date.now()`——**时间是参数不是直接取的**。
   测试时传 `now + 60000` 就能模拟"一分钟后"，**不用真的等一分钟**。
2. `const max = options.max ?? 2` **不能写成 `||`**：
   `||` 会把 `0` 也当成"没传"，于是 `max: 0`（一次都不许点）会被悄悄变成 2。
   **这类 bug 不报错，只在某个边界上悄悄失效。**

**改哪里**：`src/services/requestPolicy.js`，TODO 05 的位置。

### 已写好 · 删一首之后，正在播的还是那一首吗

**为什么做这个**
**这个任务的难点不在写代码，在把情况分清楚。**

**涉及的知识点**

`currentIndex` 是"正在播第几首"，删掉一首之后它可能要跟着变。**一共四种情况**：

|删的是|`currentIndex` 怎么变|为什么|
|---|---|---|
|删空了|变 `-1`|没有正在播的歌了|
|**当前前面**的|`currentIndex - 1`|当前这首整体往前挪了一格|
|**正好是当前**这首|**位置不动**，自动轮到原来的下一首|但删的是最后一首时下标会越界，要 `Math.min` 拉回来|
|**当前后面**的|**不变**|跟正在播的没关系|

```js
const next = queue.filter((_, itemIndex) => itemIndex !== index)
if (!next.length) return { queue: [], currentIndex: -1 }
if (index < currentIndex) return { queue: next, currentIndex: currentIndex - 1 }
if (index === currentIndex)
  return { queue: next, currentIndex: Math.min(currentIndex, next.length - 1) }
return { queue: next, currentIndex }
```

> **先把四种情况写在纸上，再写代码。**
> 直接上手写必然漏掉一两种，而且漏掉的那种恰好最难复现。

`filter((_, itemIndex) => ...)`：第一个参数是元素（用不到，所以写 `_`），
第二个是下标。**这是 JS 里表示"我知道有这个参数但不用它"的惯例写法。**

### 已写好 · 快速连搜，结果不能错乱

**为什么做这个**
**这是前端最常见的竞态场景**，凡是"输入框边打边搜"都会遇到。

**涉及的知识点**

```js
const token = ++searchToken          // 发一个号
const response = await searchWithFailover(...)   // 等结果（可能很久）
if (token !== searchToken) return    // 回来发现号变了 → 自己过期了，丢掉
```

**为什么会错乱**：

```text
搜「周杰伦」 ────────────────────────→ 3 秒后回来
     搜「五月天」 ──→ 0.5 秒就回来了
                     ↑ 先显示五月天
                                      ↑ 周杰伦的结果后到，把它覆盖了
```

用户看到的是**五月天的关键词配周杰伦的结果**。

**号码牌的办法**：每次搜索发一个递增的号，结果回来时对一下号——
**不是最新的就直接丢掉**。

## 6. Git 提交与推送

### 第三步：推送到你自己的仓库

```bat
git push origin main
```

**推送报 `'origin' does not appear to be a git repository` 怎么办？**

走路线 B 的同学，`origin` 已经被改名成 `template`
（那是全班共用的模板仓库，**不能推**）。
先到 GitHub 新建一个空仓库 `p5-music-学号`（**不要**勾选 "Add a README file"），然后：

**Windows CMD**

```bat

git remote add origin https://github.com/你的用户名/p5-music-学号.git
git branch -M main

REM -u 的意思是"记住这个对应关系"，以后直接 git push 就行
git push -u origin main
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p5-music-学号.git
git branch -M main
git push -u origin main
git remote -v
```

`git remote -v` 应该看到：**`origin` 指向你自己的仓库，`template` 指向公共模板仓库**。


## 7. 部署上线（每一课都要做一次）

**这一课做完就上线一次，不要等到第 3 课。**

理由很实在：

|只在最后一课上线|每课都上线|
|---|---|
|前两课的成果只存在于本机|**每一课结束都有一个能发给别人的地址**|
|上线出问题时三课改动混在一起，不知道哪一步坏的|**每次只多了一课的改动，排查范围很小**|
|最后一次手忙脚乱|**做三遍就成了肌肉记忆**|

### 第一步：本地先确认能构建

**Windows CMD**

```bat
REM 先跑测试和结构检查，都过了再构建
npm test
npm run check

REM 构建生产版本，产物在 dist 目录
npm run build
```

**Windows PowerShell**

```powershell
npm test
npm run check
npm run build
```

**三条都要绿。** `npm run build` 最后会打印出 `dist/` 里各文件的大小，
看到 `✓ built in ...` 才算成功。

> **本地能跑 ≠ 能构建。** 开发模式（`npm run dev`）对很多错误很宽容，
> 构建时才会严格检查。**所以上线前必须先 build 一次。**

### 第二步：部署到 Netlify

第一次要先装命令行工具并登录（**只做一次**）：

**Windows CMD**

```bat
npm install -g netlify-cli
netlify login
```

**Windows PowerShell**

```powershell
npm install -g netlify-cli
netlify login
```

`netlify login` 会打开浏览器让你授权，点同意就行。

然后部署：

**Windows CMD**

```bat
REM 第一次部署会问你建新站点还是用已有的，选「Create & configure a new project」
REM 站点名建议用 p5-你的学号
netlify deploy --prod --dir dist
```

**Windows PowerShell**

```powershell
netlify deploy --prod --dir dist
```

成功后终端会打印出 **Website URL**，那就是你的公网地址。

> **第 2、3 课再部署时，同一个目录下直接跑 `netlify deploy --prod --dir dist` 就行**，
> 它把上次选的站点记在工程里一个隐藏的 netlify 状态文件中，那个文件不进 Git。

### 第三步：线上验收

打开自己的网址，确认这几件事：

|检查|怎么做|
|---|---|
|页面能打开|访问自己的网址|
|**队列去重**|同一首连点两次 ＋，只进一条，并提示"已经在队列里了"|
|**删除不跳歌**|播第 3 首时删掉第 1 首，还在放原来那首|
|**主持台可用**|点「主持台」→ 出现 ↑ ↓ 和「暂停点歌」「清空」|
|**限流生效**|一分钟内点第三首被拦住，并告诉你还要等几秒|
|**刷新还在**|F5 刷新，队列和播到第几首都还在|
|点歌有反馈|点 ＋ 提示"已排到第 N 位"；点整行立刻播放|

### 部署失败怎么办

|现象|原因|处理|
|---|---|---|
|`netlify: command not found`|CLI 没装|`npm install -g netlify-cli`，**装完重开终端**|
|一直卡在登录|浏览器没弹出来|复制终端里的链接手动打开|

|线上样式全没了|路径问题|`netlify.toml` 里已经配好了，别改 `base`|
|线上搜不到歌|**音源接口在这个网络下不通**|F12 → Network 看那几条请求；切到「课堂合成音」应该还能用|

## 常见问题

### 队列

|现象|原因|处理|
|---|---|---|
|同一首还是能加两次|TODO 02 没做，或者用了 `push`|`some` 判重 + `[...queue, item]`|
|删一首就跳歌|已写好的代码 的四种情况没写全|对照那张表逐条检查|
|删最后一首报错|`Math.min` 那一步漏了|下标会越界，要拉回到最后一个|
|↑ ↓ 点了没反应|TODO 04 没做；或者没开主持台|先点右上角「主持台」|
|顺序乱了|直接在原数组上 splice|**先 `[...queue]` 复制**|

### 限流与持久化

|现象|原因|处理|
|---|---|---|
|限流不生效|名字每次不一样|限流是按名字算的，**名字要填固定**|
|一直被拦住|窗口时间没过|等够 60 秒；或看提示里的秒数|
|刷新还是丢|TODO 01 没做，或漏了 `deep: true`|检查 watch 的第三个参数|
|刷新后白屏|存进去的数据坏了，而且没 try/catch|F12 → Application 清掉 `p5-queue`|
|线上和本机队列不一样|**localStorage 按域名隔离**|这是正常的，不是 bug|

### 测试

|现象|原因|处理|
|---|---|---|
|`npm run test:unit` 报找不到模块|不在工程根目录|先 `cd` 到有 `package.json` 的地方|
|某条测试一直红|看报错里的 expected / actual|**测试是在帮你，别删它**|
|改对了但测试还红|保存了吗；或者改的不是这个文件|`Ctrl+S`|
