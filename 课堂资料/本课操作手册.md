### LRC 歌词长什么样

```text
[ti:屋顶]
[ar:周杰伦]
[00:00.00] 作词 : 方文山
[00:26.17]看你在摇椅上织围巾
[00:33.82]一个人在客厅
[00:40.00][01:20.00]副歌这一句唱两遍
[00:46.88]
```

看起来简单，**但有三种情况必须处理**，少一种界面就出毛病：

|情况|不处理会怎样|
|---|---|
|开头的 `[ti:]` `[ar:]` 是元信息，**不是歌词**|歌词第一行显示成 "ti:屋顶"|
|一行可能有**多个时间戳**（副歌重复）|第二次唱到时不高亮|
|时间戳后面是空的（间奏）|界面上出现一堆空行|

## 2. 先看懂四种播放模式

打开 `src/services/playMode.js`，四种模式的差别**全在两件事上**：

|模式|自然放完这首，下一首是谁|**手动**点下一首呢|
|---|---|---|
|**顺序播放**|往后走；最后一首放完**就停**|往后走；最后一首**绕回开头**|
|**列表循环**|往后走；最后一首**回到第一首**|同左|
|**单曲循环**|**重复这一首**|**往后走**|
|**随机播放**|随机挑一首（**不会是自己**）|同左|

**注意两个容易写错的地方**：

1. **手动点「下一首」时，单曲循环不应该原地不动**——
   那样会让人以为按钮坏了。所以要区分"自然放完"和"手动点的"。
2. **顺序播放手动点到最后一首之后，要绕回开头**，
   否则按钮点了没反应，也像是坏的。

> **同一个功能，"自动触发"和"用户主动触发"的合理行为可能不一样。**
> 这是做交互时很容易漏掉的一层。

### TODO 01 · 一首播不出来，别卡在那儿

**难度**：极简单


**为什么做这个**
公开音源里**总有几首是失效的**（下架、地区限制、链接过期）。
碰上就卡住不动，用户得自己去点下一首。

**涉及的知识点**

```js
function onError() {
  queue.playerState = 'error'
  notice.value = '这一首播不出来（音源可能失效了），已自动跳到下一首'
  setTimeout(() => playNext(true), 800)
}
```

这个函数接在 `<audio>` 的 `@error` 上。

**为什么要等 800 毫秒再跳？**
立刻跳的话用户根本看不清发生了什么，会觉得"歌自己在乱换"。
**留一点时间让提示被看见。**

**顺便把 `<audio>` 的几个事件记一下**（模板里都用上了）：

|事件|什么时候触发|
|---|---|
|`play` / `pause`|开始播 / 暂停|
|`ended`|**自然播完**（手动切歌不触发）|
|`timeupdate`|播放进度变了，**每秒好几十次**|
|`loadedmetadata`|时长等信息拿到了|
|`error`|加载或解码失败|

### 已写好 · 把歌词文本解析出来

**为什么做这个**
右边那张「歌词」卡片现在永远显示"没有找到歌词"。

**涉及的知识点**

```js
const TIME_TAG = /\[(\d{1,2}):(\d{1,2})(?:[.:](\d{1,3}))?\]/g

for (const raw of String(text || '').split('\n')) {
  const stamps = [...raw.matchAll(TIME_TAG)]
  if (!stamps.length) continue
  const content = raw.replace(TIME_TAG, '').trim()
  if (!content) continue
  for (const stamp of stamps) {
    const fraction = stamp[3] ? Number(stamp[3].padEnd(3, '0')) : 0
    lines.push({ time: 分 * 60 + 秒 + fraction / 1000, text: content })
  }
}
return lines.sort((a, b) => a.time - b.time)
```

|部分|说明|
|---|---|
|`matchAll`|把这一行**所有**时间戳都找出来（`match` 只给第一个）|
|`[...matchAll(...)]`|它返回的是迭代器，**要展开成数组**才能 `.length`|
|`replace(TIME_TAG, '')`|把时间戳全删掉，剩下的就是歌词正文|
|`(?: )` 非捕获分组|只分组不编号，这样 `stamp` 的第 3 项才对得上百分秒|
|`padEnd(3, '0')`|**`.85` 和 `.850` 都是 850 毫秒**，补齐到三位再算|
|最后 `sort`|多个时间戳拆开之后顺序是乱的|

**三种情况怎么处理的**（对照上面那张表）：

- 元信息行：`[ti:屋顶]` 里的 `ti` 不是数字，**正则匹配不上**，自动跳过；
- 一行多个时间戳：`for (const stamp of stamps)` **每个都 push 一条**；
- 间奏空行：`if (!content) continue`。

**先想清楚要做什么**：给一个时间（比如 63.2 秒），
找出**最后一句时间 ≤ 63.2 的歌词**是第几条。

学生的第一反应一定是从头遍历：

**功能上完全正确。** 那为什么要改？

> **不是因为数据大，是因为调用频繁。**

这个函数跟着 `<audio>` 的 `timeupdate` 事件走，**每秒被调用几十次**。
一首歌 100 行歌词：

|  |每次比较次数|一秒（按 50 次调用）|
|---|---|---|
|逐个遍历|100|**5000 次比较**|
|二分查找|7|350 次比较|

**这是讲"为什么要关心复杂度"最好的一个例子**——
比"假如有一百万条数据"那种假设有说服力得多，**因为它就在眼前发生**。

**涉及的知识点**

```js
let low = 0
let high = lines.length - 1
let found = 0
while (low <= high) {
  const mid = (low + high) >> 1
  if (lines[mid].time <= time) {
    found = mid       // 这一句已经唱过了，记下来，往右继续找更晚的
    low = mid + 1
  } else {
    high = mid - 1    // 这一句还没唱到，往左找
  }
}
return found
```

|部分|说明|
|---|---|
|`>> 1`|右移一位 = 除以 2 向下取整，比 `Math.floor` 快一点点|
|`found = mid` 之后还继续找|因为可能还有**更晚但也已唱过**的句子|
|`time < lines[0].time` 返回 −1|**还没唱到第一句**，界面上不高亮任何一行|

**二分查找的前提是数据有序**——所以解析歌词最后那个 `sort` 不能省。

### 已写好 · 随机播放不能抽到自己

**为什么做这个**
切到「随机播放」，一首放完之后有几率**又放同一首**，体验很怪。

**涉及的知识点**

直觉写法是 while 循环重抽：

```js
let next = current
while (next === current) next = Math.floor(Math.random() * length)
```

能用，但**队列只有两首时可能转很多圈**（每次 50% 概率要重来）。

更好的办法：**在"除当前外"的 length−1 个位置里抽，再映射回去**：

```js
const pick = Math.floor(random() * (length - 1))
return pick >= current ? pick + 1 : pick
```

**一次就出结果**，而且概率均匀。画个图就明白了：

```text
队列：  0  1  2  3  4        当前在 2
抽取范围： 0  1  2  3         （只有 4 个位置）
映射后：  0  1  3  4         （≥2 的都往后挪一位，正好跳过 2）
```

**还有一个更重要的点**——看函数签名：

```js
export function nextIndexByMode(mode, length, current, auto = true, random = Math.random)
```

**把随机数当参数传进来。** 测试时就能塞一个固定值：

```js
nextIndexByMode('shuffle', 5, 2, true, () => 0.5)   // 结果是确定的
```

> **凡是依赖随机、时间、网络的函数，都该把它们做成可注入的**，
> 否则这个函数**根本没法测**。这叫依赖注入。
> 第 2 课的限流函数把 `now` 做成参数，是同一个道理。

## 7. 部署上线（每一课都要做一次）

**这一课做完就上线一次，不要等到第 3 课。**

理由很实在：

|只在最后一课上线|每课都上线|
|---|---|
|前两课的成果只存在于本机|**每一课结束都有一个能发给别人的地址**|
|上线出问题时三课改动混在一起，不知道哪一步坏的|**每次只多了一课的改动，排查范围很小**|
|最后一次手忙脚乱|**做三遍就成了肌肉记忆**|

### 第一步：本地先确认能构建

**Windows CMD**

```bat
REM 先跑测试和结构检查，都过了再构建
npm test
npm run check

REM 构建生产版本，产物在 dist 目录
npm run build
```

**Windows PowerShell**

```powershell
npm test
npm run check
npm run build
```

**三条都要绿。** `npm run build` 最后会打印出 `dist/` 里各文件的大小，
看到 `✓ built in ...` 才算成功。

> **本地能跑 ≠ 能构建。** 开发模式（`npm run dev`）对很多错误很宽容，
> 构建时才会严格检查。**所以上线前必须先 build 一次。**

### 第二步：部署到 Netlify

第一次要先装命令行工具并登录（**只做一次**）：

**Windows CMD**

```bat
npm install -g netlify-cli
netlify login
```

**Windows PowerShell**

```powershell
npm install -g netlify-cli
netlify login
```

`netlify login` 会打开浏览器让你授权，点同意就行。

然后部署：

**Windows CMD**

```bat
REM 第一次部署会问你建新站点还是用已有的，选「Create & configure a new project」
REM 站点名建议用 p5-你的学号
netlify deploy --prod --dir dist
```

**Windows PowerShell**

```powershell
netlify deploy --prod --dir dist
```

成功后终端会打印出 **Website URL**，那就是你的公网地址。

> **第 2、3 课再部署时，同一个目录下直接跑 `netlify deploy --prod --dir dist` 就行**，
> 它把上次选的站点记在工程里一个隐藏的 netlify 状态文件中，那个文件不进 Git。

### 第三步：线上验收

打开自己的网址，确认这几件事：

|**点歌词能跳**|点某一句，播放跳到那个时间点|

### 已写好的二分查找要重点讲读（建议花 10 分钟）

这是整个项目 5 最好的一个教学点，按这个顺序讲：

1. **先在白板上写出朴素的遍历版本**（三行），说明它功能上完全正确；
2. 然后问："这个函数一秒被调用多少次？"
   （让他们在 `timeupdate` 里加个 `console.count()` 自己数，**大约每秒 50 次**）；
3. 算一笔账：100 行 × 50 次 = **每秒 5000 次比较**；
4. 再讲二分，7 次 vs 100 次；
5. **最后跑那条"二分与遍历结果必须一致"的测试**——
   **先有测试，才敢改算法。**

> 这个流程比直接讲"二分查找的时间复杂度是 O(log n)"有效得多，
> 因为学生是**自己算出"太亏了"这个结论的**。

## 常见问题

### 歌词

|现象|原因|处理|
|---|---|---|
|一直显示"没有找到歌词"|用的音源不提供歌词|**只有「流行热歌」带歌词**|
|歌词出来了但不动|已写好的代码 没做|`activeLineIndex` 要真的按时间找|
|歌词高亮不准，总是慢一拍|时间戳的百分秒没处理好|`.85` 要补成 `850` 毫秒|
|歌词里有一堆空行|间奏行没过滤|`if (!content) continue`|
|第一行显示成 "ti:歌名"|元信息行没跳过|正则只匹配数字时间戳就自动跳过了|
|歌词不自动滚|TODO 02 没做|检查那个 watch|

### 播放

|现象|原因|处理|
|---|---|---|
|进度条点了没反应|TODO 04 没做|`seek` 要算比例|
|点左半边跳得不对|用了 `event.target`|**必须用 `currentTarget`**|
|随机老是放同一首|已写好的代码 没做|在"除当前外"的范围里抽|
|顺序播放放完不停|模式判断写反了|`auto` 为真且是最后一首才返回 −1|
|失效的歌卡住|TODO 01 没做|接上 `@error`|

### 快捷键

|现象|原因|处理|
|---|---|---|
|按空格没反应|TODO 03 没做；或焦点在输入框里|**点一下页面空白处**再按|
|在搜索框打空格歌暂停了|**那三行焦点判断漏了**|`if (tag === 'INPUT' ...) return`|
|按空格页面往下跳|漏了 `preventDefault()`|空格的默认行为是滚动|
|切走再回来快捷键失效|监听被摘掉了没加回来|检查 `onMounted` / `onUnmounted`|

更多通用排错见 `通用附录_运行提交部署与排错.md`；
命令和参数的逐条解释见 [命令参数逐个拆开](<../../01_入门与通用规范/04_命令参数逐个拆开.md>)。
