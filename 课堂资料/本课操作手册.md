## 本课在项目 4 里的位置

|课次|这一课做什么|课后你手上多了什么|
|---|---|---|
|1|**前端**：把卡片编辑器做出来|一个能选场景、选卡面、实时预览的页面（还不会真的生成文案）|
|2|**后端与 AI**：接上 MiniMax，并处理它出错的各种情况|文案真的由大模型写；模型挂了也照样出稿|
|3|**上线**：短链接、分享页、安全与缓存|一条 `/c/林老师-20260922` 的链接，发给谁都能打开|

**三课做的是同一个产品**，一课比一课往外走一层：
先是只有自己电脑能看的页面，再是要联网调别人接口的服务，
最后是**发给别人、别人也能打开**的东西。
**每往外走一层，要考虑的事就多一类：出错怎么办、被恶意使用怎么办、流量大了怎么办。**


**第 1 课的页面还不会真的生成文案**——点"生成祝福"出来的是本地文案库里的句子。
这一课要接上**真正的大模型**（MiniMax-M3），
并且处理好一件第 1 课完全不用管的事：**别人的服务会用各种方式失败。**

### 这一课的核心观念（讲透这一条，本课就成了）

> **别人的服务一定会失败，而且失败的方式不止一种。**

学生的直觉是"调个接口而已，拿到结果用就行了"。真实情况是：

|失败方式|表现|本课哪个 TODO 管它|
|---|---|---|
|密钥错、限流、对方挂了|**HTTP 返回 4xx/5xx，但 `fetch` 不抛错**|TODO 04|
|余额不足、触发内容风控|**HTTP 是 200，错误藏在响应体里**|已写好的代码|
|对方很慢，甚至不回|**请求一直挂着，用户干等**|已写好的代码|
|返回了，但内容带一堆废话|卡面上出现"祝福语："和引号|TODO 05|
|根本没配密钥|一上来就没法调|TODO 03|

**五种失败，五种不同的处理方式。** 这张表是本课的骨架。

### 另一条同样重要的观念

> **前端的按钮只是方便用户，不是安全措施。**

第 1 课做的下拉框和按钮，任何人都能用 `curl` 绕过去。
所以 TODO 01 要在服务端把同样的规则**再写一遍**。
这和第 1 课"按钮都 disabled 了为什么还要再判断一次"是同一条原则，
**只是这次的后果严重得多**——服务端不校验，别人能往你的模型请求里塞任何东西，
**花的是你的钱**。

## 2. 配置密钥：这一课最要小心的一步

### 第一步：生成自己的 `.env`

**Windows CMD**

```bat
REM 仓库里只有 .env.example（一个不含真实值的样板）
REM 复制一份改名成 .env，真实密钥只写在这一份里
copy .env.example .env
findstr /R "^[A-Z_][A-Z_]*=" .env
```

**Windows PowerShell**

```powershell
Copy-Item .env.example .env
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' }
```

能打印出英文 `KEY=value` 行才算成功；这里只显示配置行，不显示 UTF-8 中文注释，
避免 CMD 乱码。
**报「系统找不到指定的文件。」说明不在工程根目录**，先 `cd` 过去再重来。

### 第二步：把密钥填进去

用 Trae 打开 `.env`：

```ini
# 教师课堂上会发一把临时密钥
MINIMAX_API_KEY=这里填发给你的密钥
PORT=3030
```

### 第三步：确认 `.env` 不会被提交

**这一步不能跳过。**

**Windows CMD**

```bat
REM 看一下工作区状态，列表里不应该出现 .env
git status

REM 直接问 Git：.env 是被哪条规则忽略的？
REM 打印出 .gitignore:12:.env  这样一行才算对
git check-ignore -v .env
```

**Windows PowerShell**

```powershell
git status
git check-ignore -v .env
```

|结果|意思|
|---|---|
|打印出一行 `.gitignore:…:.env`|**正确**，它被忽略了|
|什么都不打印|**危险**：`.env` 没被忽略，继续操作会把密钥提交上去。**立刻停下来找教师**|

> **为什么这么紧张？**
> 密钥一旦进了 Git 历史，**删掉文件也没用**——历史里还在，
> 任何克隆过你仓库的人都能翻出来。GitHub 上有机器人专门扫这个，
> 泄露的密钥通常几分钟内就被人拿去用了，**账单算你的**。
> 唯一的补救是去控制台**作废这把密钥重新签发**。
>
> 课堂上发的这把密钥，**课后教师会统一作废重发**——
> 因为你们的作业仓库是公开的。

### 第四步：万一真的提交了怎么办

**不要慌，但要立刻按顺序做这三件事**：

1. **先去 MiniMax 控制台把这把密钥作废。**（最重要，先止血）
2. 告诉教师。
3. 再考虑清理 Git 历史（很麻烦，而且推到远程之后基本清不干净）。

**顺序不能反。** 先作废，泄露的那把就没有价值了。

### 启动之后先确认这三件事

1. **终端里出现了上面说的那行提示**，而不是一串红色报错。
2. **浏览器真的能打开页面**，不是"无法访问此网站"。
3. **这些终端要一直开着。** 关掉哪个，哪一半功能就没了。
   要执行别的命令**请再开一个新终端**，不要在跑着服务的终端里敲。

**停止服务**：在跑着它的那个终端里按 `Ctrl + C`。
按一次没反应就再按一次，Windows 上偶尔会问 `终止批处理操作吗(Y/N)?`，输 `Y` 回车。

**改了代码要不要重启？**

|改什么|要不要手动重启|
|---|---|
|前端代码（页面、组件、样式）|**不用**，保存后浏览器自动刷新|
|后端代码|**不用**，`--watch` / `nodemon` 会自动重启|
|`.env` 里的配置|**要**，环境变量只在启动时读一次|
|`package.json` 的依赖|**要**，而且要先 `npm install`|

### 启动不起来怎么办

|终端里报什么|原因|处理|
|---|---|---|
|`'npm' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**，再 `node -v` 确认|
|`Cannot find module`|依赖没装，或者不在工程目录里|先确认当前目录对不对，再 `npm install`|
|`EADDRINUSE` 端口被占用|**多半是上一次的服务没关**|找到那个终端按 `Ctrl+C`；或者换个端口|
|`npm ci` 报 lock 文件对不上|`package.json` 改过但没更新 lock|先 `npm install` 生成新的 lock，再提交|
|装依赖卡住不动|npm 源慢|`npm config set registry https://registry.npmmirror.com` 再重试|
|页面能打开但数据是空的|**后端没起来**|F12 → Network，看那条请求是红的还是 200|

### TODO 01 · 把输入挡在服务端

### TODO 02 · 所有输入先洗一遍

**难度**：简单


**为什么做这个**
用户输入的东西五花八门：前后带空格、中间一堆换行、夹着尖括号。
**先统一成一种写法，后面所有逻辑都好写。**

**涉及的知识点**

```js
function clean(value) {
  return String(value ?? '')
    .replace(/[<>]/g, '')
    .replace(/\s+/g, ' ')
    .trim()
}
```

|这一步|做什么|不做会怎样|
|---|---|---|
|`String(value ?? '')`|**先确保是字符串**|传进来是数字或 undefined 时，下面 `.replace` 直接报 "not a function"|
|`.replace(/[<>]/g, '')`|去掉尖括号|它有机会被当成 HTML 标签（第 3 课细讲）|
|`.replace(/\s+/g, ' ')`|连续空白压成一个空格|"林    老师" 和 "林 老师" 被当成两个人|
|`.trim()`|去掉首尾空格|"  林老师" 和 "林老师" 存成两条|

**正则里的 `/g`**：global，**替换所有匹配**，不加只替换第一处。
`\s` 匹配任何空白（空格、Tab、换行、全角空格）。

**归一化和校验是两件事，顺序不能反**：

```text
先归一化（洗干净） → 再校验（合不合规）
```

反过来的话，"  生日  " 会因为带空格被白名单拒绝——**用户会觉得莫名其妙。**

### TODO 04 · fetch 不会因为 500 抛错

**难度**：中等


**为什么做这个**
**这是对接外部接口最容易踩的坑，没有之一。**

**涉及的知识点**

```js
if (!response.ok) {
  const detail = await response.text().catch(() => '')
  throw Object.assign(new Error(`upstream_${response.status}`), {
    code: 'UPSTREAM_ERROR',
    detail: detail.slice(0, 200),
  })
}
```

**`fetch` 的判定标准和你想的不一样**：

|情况|`fetch` 抛错吗|`response.ok`|
|---|---|---|
|网络断了、域名解析不了|**抛**|—|
|对方返回 200|不抛|`true`|
|对方返回 401（密钥错）|**不抛**|`false`|
|对方返回 429（限流）|**不抛**|`false`|
|对方返回 500（对方挂了）|**不抛**|`false`|

**只要请求发出去、对方回了话，`fetch` 就算成功。**
至于对方说的是"好的"还是"你没权限"，它不管。

不自己检查会怎样：下面 `response.json()` 解析出一个**错误对象**，
`data.content` 是 undefined，`cleanOutput` 收到 undefined……
最后用户收到一张内容是空白或 `undefined` 的贺卡。**而且没有任何报错。**

**`detail.slice(0, 200)` 也不是随手写的**：
上游出错时可能返回几十 KB 的 HTML 错误页，
整个塞进日志会把日志刷爆。**错误详情一律截断。**

### TODO 05 · 把模型的废话擦掉

**难度**：中等


**为什么做这个**
提示词第 1 条已经写了"只输出祝福正文本身"，但模型**还是会时不时加前缀**。

**涉及的知识点**

```js
return String(text || '')
  .replace(/^\s*(祝福语|文案|以下是[^：:]*)[：:]\s*/, '')
  .replace(/^[""「『]/, '')
  .replace(/[""」』]\s*$/, '')
  .replace(/\s*\n\s*/g, '\n')
  .trim()
  .slice(0, 260)
```

|这一步|擦掉什么|
|---|---|
|第 1 条|开头的 `祝福语：` `文案：` `以下是为您准备的：`|
|第 2 条|开头的引号（中英日三种都要）|
|第 3 条|结尾的引号|
|第 4 条|每行首尾的空格，**但保留换行**|
|`.trim().slice(0, 260)`|去首尾空白，再兜一道长度上限|

**正则里的 `^` 和 `$`**：`^` 表示"字符串开头"，`$` 表示"结尾"。

**注意前三条都没加 `/g`**——
**只擦开头结尾那一处，别把正文中间的引号也擦了**。
祝福里完全可能出现"愿你的'小满'如愿"这样的写法。

### 已写好 · HTTP 200 不等于成功

**为什么做这个**
**这个坑比 TODO 04 更隐蔽**，因为 TODO 04 那道关卡完全拦不住它。

**涉及的知识点**

```js
if (data?.base_resp && data.base_resp.status_code !== 0)
  throw Object.assign(new Error(data.base_resp.status_msg || 'upstream_rejected'), {
    code: 'UPSTREAM_REJECTED',
  })
```

MiniMax 在余额不足、触发内容风控时，**HTTP 状态码仍然是 200**，
错误藏在响应体的 `base_resp` 里：

```json
{ "base_resp": { "status_code": 1008, "status_msg": "insufficient balance" } }
```

`response.ok` 是 `true`，TODO 04 的检查**一点作用都没有**。

|部分|说明|
|---|---|
|`data?.base_resp`|**可选链**。没有这个字段时返回 undefined 而不是报错|
|`status_code !== 0`|**0 表示成功**，非 0 都是错|
|`status_msg`|对方给的错误描述，直接用作错误信息|

**知识点：很多国内接口都是这个风格**——HTTP 层永远 200，
业务成败看响应体里的 code 字段（微信、支付宝都是这样）。

> **对接任何一个新接口，先翻文档确认它是哪种风格。**
> 不要想当然地以为 `response.ok` 就够了。

### 已写好 · 给外部请求加超时

**为什么做这个**
模型偶尔会很久不返回。**`fetch` 默认没有超时**——
对方不回你就一直等，页面上那个"正在落笔"会一直转下去。

**涉及的知识点**

```js
const controller = new AbortController()
const timer = setTimeout(() => controller.abort(), options.timeoutMs ?? 20000)
try {
  const response = await fetchImpl(url, { …, signal: controller.signal })
  …
} finally {
  clearTimeout(timer)
}
```

|部分|说明|
|---|---|
|`AbortController`|一个"遥控取消器"|
|`controller.signal`|把它交给 fetch，fetch 就听它指挥|
|`controller.abort()`|一调，**fetch 立刻抛 `AbortError`**|
|`setTimeout(fn, 20000)`|20 秒后执行 fn|
|**`finally` 里的 `clearTimeout`**|**请求正常返回也要把定时器清掉**|

**`clearTimeout` 为什么不能少？** 请求 3 秒就成功返回了，
但那个定时器还在，**17 秒后它还会触发一次 abort**。
虽然此时 fetch 已经结束、不会真的出问题，
但定时器堆积起来是实实在在的资源泄漏。

**用 `finally` 而不是写在 try 末尾**：
**不管成功、失败还是抛错，`finally` 都一定会执行。**

**20 秒是怎么来的？** 实测：M3 正常 3~8 秒返回。
贺卡是"等得起"的场景，但也不能让人干等。

> **超时时间该设多少，取决于业务，不是抄来的。**
> 搜索框的接口 1 秒都嫌长，视频转码等 10 分钟都正常。

## 常见问题

### 密钥与配置

|现象|原因|处理|
|---|---|---|
|`git status` 里出现 `.env`|`.gitignore` 出问题了|**立刻停下来找教师**，不要提交|
|改了 `.env` 不生效|**`.env` 只在启动时读一次**|**重启后端**|
|一直显示"未配置模型密钥"|`.env` 没建、变量名打错、或者没重启|检查文件名就是 `.env`（不是 `.env.txt`）|
|`.env.txt`|Windows 隐藏了扩展名|文件资源管理器 → 查看 → 勾"文件扩展名"|

### 接口

|现象|原因|处理|
|---|---|---|
|页面一直转圈|已写好的代码 没做，或者后端没起|先看后端终端有没有报错|
|`ECONNREFUSED 3030`|**后端没启动**|开第二个终端跑 `npm run server`|
|`404 /api/greeting`|前端代理没生效|确认用的是 5173 而不是直接开的 html 文件|
|curl 报引号错误|CMD 里 JSON 的引号要转义|**改用 PowerShell 的 `Invoke-RestMethod`**，清楚得多|
|文案里带"祝福语："|TODO 05 没做|`cleanOutput` 的清洗链|

### 两个终端

|现象|原因|处理|
|---|---|---|
|关掉终端页面就打不开|服务跟着终端一起没了|**两个终端都要一直开着**|
|`Port 3030 is in use`|上次的后端还在跑|关掉那个终端，或者在任务管理器里结束 node 进程|
