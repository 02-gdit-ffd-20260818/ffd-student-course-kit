## 本课在项目 3 里的位置

**这是项目 3 的最后一课，也是整个课程第一次真正谈"上线"。**

前三课都在回答"数据存在哪"。这一课回答两个新问题：

1. **环境怎么一键复制**——"在我电脑上是好的"这句话，从此不再是借口；
2. **数据怎么不跟着容器一起消失**——这是本课最重要的一个实验。

|课次|工程|数据存在哪|这一课新出现的问题|
|---|---|---|---|
|12|`PersonaLink_NoDB`|一个 `db.json` 文本文件|并发写会互相覆盖；没有任何约束|
|13|`PersonaLink_SQLite`|一个 `.sqlite` 文件（Node 24 内置）|约束、外键、事务交给数据库|
|14|`PersonaLink_MySQL`|独立运行的 MySQL 服务|第一次有账号密码；密码不能明存|
|15|`PersonaLink_Docker`|PostgreSQL 容器 + 数据卷|环境怎么一键复制；数据怎么不跟着容器消失|

**四课做的是同一个产品**——界面、接口、功能完全一样，
差别只在**数据存在哪、怎么存**。所以这四课最值得记住的不是某一种数据库的语法，
而是：**换一种存储，同一件事该怎么做、代价是什么。**


## 开课前先讲这些概念

|知识点|小白要理解的话|本课在哪里用到|
|---|---|---|
|镜像（image）|一个打包好的只读模板，**像光盘**|已写好的代码|
|容器（container）|镜像跑起来的一个实例，**用完即弃**|全课|
|卷（volume）|独立于容器存在的一块存储，**容器删了它还在**|TODO 01|
|编排（compose）|用一个文件描述"这套系统由哪几个容器组成"|全课|
|健康检查|定期问一句"你活着吗"，答对了才算就绪|TODO 01、02|
|端口映射|把容器里的端口开到宿主机上|TODO 03|
|镜像分层|Dockerfile 每条指令一层，没变的层直接用缓存|已写好的代码|

### 容器和虚拟机的区别（一分钟讲清）

|  |虚拟机|容器|
|---|---|---|
|装的是|一整个操作系统|只有应用和它的依赖|
|大小|几个 GB|几十到几百 MB|
|启动|几十秒到几分钟|**一秒以内**|
|隔离|硬隔离，各有各的内核|**共用宿主机内核**|

最后一行很关键：**容器不是虚拟机**，隔离没有那么强。
所以 TODO 05 才要求不用 root 跑应用。

### 这一课要建立的核心观念

> **容器是用完即弃的，数据不是。**

这句话是整个容器化部署的地基。容器随时可以删掉重建——升级、扩容、
修复故障都靠这个。但**数据必须活得比容器久**，所以要放在卷里。

本课的核心实验就一个：

```text
docker compose down      → 再 up  → 数据还在   （卷还在）
docker compose down -v   → 再 up  → 数据没了   （-v 把卷也删了）
```

**这一对实验人人都要亲手做一遍。**

### 装不上 Docker 怎么办

Docker Desktop 在 Windows 家庭版需要 WSL 2，有些机器要在 BIOS 里开虚拟化。
课堂上如果有同学装不上：

|情况|处理|
|---|---|
|BIOS 没开虚拟化|任务管理器→性能→CPU，看"虚拟化"是否已启用|
|WSL 2 没装|管理员 PowerShell 执行 `wsl --install`，**要重启**|
|完全装不上|**两人一组共用一台机器**；本课重点是概念和实验，不是每人一套环境|

### TODO 01 · 给数据库加上持久卷和健康检查

**难度**：极简单


**为什么做这个**
**这是本课最重要的一个 TODO。**

容器是用完即弃的——删掉重建之后，容器里写的东西全没了。
数据库的数据必须放在**卷**里，卷独立于容器存在。

**涉及的知识点**

```yaml
volumes:
  - postgres_data:/var/lib/postgresql/data
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
  interval: 10s
  timeout: 5s
  retries: 5
```

|部分|说明|
|---|---|
|`postgres_data`|卷的名字。它是 Docker 管理的一块存储，**不在容器里**|
|`/var/lib/postgresql/data`|PostgreSQL 存数据的目录。把卷挂到这里，数据就写进卷了|
|`pg_isready`|PostgreSQL 自带的命令，能连上就返回 0|
|`interval`|每隔多久检查一次|
|`retries`|连续失败几次才判定为不健康|

### 已写好 · 校验 JWT 令牌

**为什么做这个**
**这是本课唯一一个前端看得见的 TODO，也是一个真实发生过的事故。**

**涉及的知识点**

```js
req.user = jwt.verify(token, jwtSecret(), { issuer: 'personalink' })
```

|函数|做什么|
|---|---|
|`jwt.decode(token)`|**只解码，不验签名**。任何人伪造的令牌它都照单全收|
|`jwt.verify(token, 密钥)`|**验签名 + 验过期**，任何一项不过就抛错|

**JWT 本身不是加密的。** 它的内容任何人都能解开看
（把令牌贴到 jwt.io 就能看到里面的 `role`、`userId`）。
它的安全性**完全来自签名**——签名证明"这是我签发的、没被改过"。

所以用 `decode` 等于**只看内容不看签名**，
任何人都能自己造一个 `{"role":"admin"}` 的令牌进来。
**这两个函数名字很像，用错了等于没有认证。**

第三个参数 `{ issuer: 'personalink' }` 要求签发方必须是我们自己。
不校验的话，别人用同一个密钥给别的系统签的令牌也能拿来用。

> 这段代码工程里**已经写好了**。打开对应文件，找到这一段读一遍注释，
> 知道它在做什么、为什么这么写即可，**不用动手改**。

### 已写好 · 让镜像构建快起来

**为什么做这个**
改一行业务代码，重新构建要等好几分钟——因为依赖被重装了一遍。
**这是 Dockerfile 最经典的一条优化。**

**涉及的知识点**

Docker 的每一条指令都会生成一"层"，只要这一层的**输入没变**，
下次构建就直接用缓存。**但只要有一层失效了，它后面所有层都跟着失效。**

|写法|结果|
|---|---|
|`COPY . .` 然后 `RUN npm ci`|改任何一个文件都让 COPY 层失效 → **每次都重装依赖**|
|先 `COPY package*.json` 再 `RUN npm ci`，最后 `COPY` 源码|依赖清单没变 → **装依赖那层一直用缓存**|

```dockerfile
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY backend ./backend
```

**顺序就是全部的秘密**：把"不常变的"放前面，"常变的"放后面。

## 6. Git 提交与推送

### 第一步：先看清楚自己改了什么

```bat
git status
git diff
```

确认列表里**没有**这几样：
`node_modules/`、`.env`、`*.sqlite`、`db.json` 里的真实数据、备份文件。
它们都在 `.gitignore` 里，正常不会出现；出现了说明 `.gitignore` 出了问题。

### 第二步：提交

```bat
git add .
git commit -m "P3第15课：Docker 编排、数据卷持久化与上线安全"
git log -1 --oneline
```

### 第三步：推送到你自己的仓库

```bat
git push origin main
```

**推送报 `'origin' does not appear to be a git repository` 怎么办？**
本课工程是从教师模板克隆来的，`origin` 已经被改名成 `template`
（那是全班共用的模板仓库，**不能推**）。
先到 GitHub 新建一个空仓库 `p3-docker-学号`（**不要**勾选 "Add a README file"），然后：

**Windows CMD**

```bat
git remote add origin https://github.com/你的用户名/p3-docker-学号.git
git branch -M main
git push -u origin main
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p3-docker-学号.git
git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。
`git remote -v` 应该看到：`origin` 指向你自己的仓库，`template` 指向公共模板仓库。

## 常见问题

### Docker 环境

|现象|原因|处理|
|---|---|---|
|`cannot connect to the Docker daemon`|Docker Desktop 没启动|启动它，托盘图标变绿再试|
|`docker compose` 不认识|Docker 版本太老|升级 Docker Desktop；老版本命令是 `docker-compose`|
|WSL 相关报错|WSL 2 没装好|管理员 PowerShell 跑 `wsl --install`，**要重启**|
|镜像下载特别慢|网络问题|配置国内镜像加速器（Docker Desktop 设置里）|

### 容器起不来

|现象|原因|处理|
|---|---|---|
|`Restarting` 反复重启|启动就崩|`docker compose logs backend` 看具体报错|
|后端报 `connection refused`|TODO 02 没做|加 `condition: service_healthy`|
|`port is already allocated`|端口被占了|改 `.env` 里的 `FRONTEND_PORT`|
|数据库一直 `starting`|健康检查命令写错了|`docker compose logs postgres` 看|
|改了 `.env` 没生效|容器还是旧的环境变量|**`docker compose up -d` 重新创建容器**|

### 数据

|现象|原因|处理|
|---|---|---|
|`down` 之后数据没了|TODO 01 没做，或者打了 `-v`|检查 volumes 声明；**确认没打 `-v`**|
|卷删不掉|还有容器在用|先 `docker compose down` 再删|
|导入数据报语法错误|MySQL 的 SQL 不能直接给 PostgreSQL 用|用工程自带的 `db:import-mysql` 转换脚本|

### 构建

|现象|原因|处理|
|---|---|---|
|每次都重装依赖|已写好的代码 没做|先复制 package.json 再装依赖|
|`USER node` 之后构建失败|`USER` 写得太早|`USER node` 要在 `RUN npm ci` 之后|
|容器里读不了自己的代码|复制时没改属主|`COPY --chown=node:node`|

更多通用排错见 `通用附录_运行提交部署与排错.md`；
命令和参数的逐条解释见 [命令参数逐个拆开](<../../01_入门与通用规范/04_命令参数逐个拆开.md>)。
