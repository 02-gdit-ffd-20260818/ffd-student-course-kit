## 开课前先讲这些概念

学生动手之前，先把这几个词讲清楚。每个只讲到"能用自己的话解释"为止，不展开。

|知识点|小白要理解的话|本课在哪里用到|
|---|---|---|
|CSS|决定页面**"长什么样"**。HTML 说"这是标题"，CSS 说"标题是绿色的 30px"|全部 TODO|
|选择器|"改谁"。`h2` 改所有二级标题，`.section` 改所有带这个类的元素|全部 TODO|
|声明|"改成什么"。`color: red;` 一条就是一个声明|全部 TODO|
|层叠|同一个元素被多条规则命中时，**写在后面的、更具体的那条赢**|第 2 节、TODO 01|
|继承|有些属性（颜色、字号、行高）会自动传给子元素，有些（边框、背景）不会|TODO 03、04|
|CSS 变量|`--heading: green;` 存一个值，`var(--heading)` 到处读它。**改一处，全站变**|TODO 01—04|
|盒模型|每个元素都是盒子：content → padding → border → margin，由内到外四层|TODO 05|
|伪类|选的是元素的**状态**而不是元素本身，例如 `a:hover` 是"鼠标悬停时"|TODO 06|

### 三个最小例子，本课七个任务都是它们的变形

**例 1：选择器 + 声明**

```css
h2 {              /* 选谁：所有 h2 */
  color: green;   /* 改成什么：文字变绿 */
  font-size: 30px;
}
```

**例 2：变量——改一处，全站变**

```css
:root { --main: #254a40; }   /* 存一个值 */
h1 { color: var(--main); }   /* 到处读它 */
h2 { color: var(--main); }
a  { color: var(--main); }
/* 想换配色？只改 :root 里那一行 */
```

**例 3：盒模型的四层**

```css
.card {
  padding: 16px;              /* 内容到边框的距离，背景色会铺到这里 */
  border: 1px solid #ccc;     /* 边框 */
  margin: 24px;               /* 和别的盒子的距离，背景色铺不到这里 */
}
```

**这三个例子的分工要讲透**：选择器决定"改谁"，声明决定"改成什么"，
变量让"改一次到处生效"，盒模型决定"元素占多大地方"。
本课所有 TODO 都跳不出这四件事。

> **padding 和 margin 怎么区分？** 想让**背景色跟着变大**就用 padding；
> 想让它**和邻居离远点**就用 margin。TODO 05 会现场对比。

### 这一步的常见故障

|现象|原因|处理|
|---|---|---|
|`系统找不到指定的路径`|桌面上还没有 `web-work`|上面第 1 步的 `mkdir` 那两行不能跳过|
|`fatal: repository not found`|仓库地址写错，或仓库是私有的|检查用户名和学号；私有仓库要先登录|
|`fatal: destination path '...' already exists`|这个文件夹已经建过了|换个名字，或先删掉原来那个|
|`dir index.html` 说找不到|`cd` 没进到工程文件夹里|把第 1、2 步的 `cd` 再执行一遍，注意路径最后一段|
|`remote origin does not exist`|`git remote rename` 执行过两次了|跳过这一条，用 `git remote -v` 看现在叫什么|

**`dir` / `Get-ChildItem` 看不到 `index.html` 就不要往下走。** 后面所有步骤都建立在"你在对的文件夹里"这个前提上。

|部分|意思|
|---|---|
|`remote`|远程仓库|
|`add`|新增一个|

|后面那串网址|教师模板仓库的地址|

这条命令只往 `.git/config` 里写一行配置，**不联网、不下载、一个文件都不会变**。
整个项目只需要做一次；提示 `remote course already exists` 就是已经做过了，**跳过它**。

**② `git fetch course p1-l02-standalone-v3.0`——把本课分支下载到 `.git` 里，工作目录仍然看不到。**

**这一步最容易被误解**：命令跑完之后你去 `dir`，会发现 `lesson-02-task.css`
**还是不存在**。这不是失败。`fetch` 只把内容下载进 `.git` 这个"仓库数据库"里存着，
**没有写到你看得见的工作目录**。

**③ `git checkout course/p1-l02-standalone-v3.0 -- lesson-02-task.css`——真正把文件写出来的一步。**

|部分|意思|
|---|---|
|`checkout`|这里的意思是"从某个版本里取出文件，写进工作目录"|
|`course/p1-l02-...`|从哪个版本取|
|`--`|分隔符，意思是"**后面全是文件名，不是分支名**"|
|`lesson-02-task.css`|要取的文件，只取这一个|

### 第三步：确认启动成功

终端里会打印出类似这样的内容：

```text

Ready for changes
```

**看到 `Ready for changes` 才算成功。** 浏览器通常会自动打开；
没自动打开就自己访问 <http://localhost:7000>。

**三件事要记住**：

1. **这个终端要一直开着。** 关掉它服务就停了，页面会打不开。
2. **停止服务按 `Ctrl + C`**（在跑着服务的那个终端里按）。
3. **改完代码按 `Ctrl+S` 保存，浏览器会自己刷新**，
   不用再按 `Ctrl+R`。这就是"热更新"。

### 第四步：打开开发者工具

按 `F12`，**整节课都开着**。**这一课主要用 Elements 标签**：
   左边看结构，右边 Styles 看这个元素命中了哪些规则、哪些被划掉了（说明输掉了），
   右下角还有一张四色盒模型图。

> **一个好习惯**：把 Trae 和浏览器左右并排放。改一行、保存、看效果。
> CSS 尤其要这样——**数值调多少合适，只能靠眼睛一次次试出来**，
> 热更新把每次试的成本降到了零点几秒。

### 为什么不双击打开 HTML

双击打开时，浏览器地址栏是 `file:///E:/.../index.html`；
用服务器打开是 `http://localhost:7000`。**这两个不是一回事。**

|  |双击打开（file 协议）|本地服务器（http 协议）|
|---|---|---|
|改完代码|**要自己按 `Ctrl+R` 刷新**|**自动刷新**|
|读取本地 JSON、用 `fetch`|**会被浏览器拦住**（跨域限制）|正常|
|`type="module"` 的脚本|**加载不了**|正常|
|`localStorage`|行为和正式环境不一样|和正式环境一致|
|同学能不能看到|不能|**能**，见下面|
|和上线之后的环境|不一样|**几乎一样**|

后面几课会用到 JSON 数据、模块化脚本、本地存储，
**那时候用 file 协议打开会直接报错，而且报的错看起来毫无道理**
（"明明文件就在那儿"）。
**从第一课就用服务器，把这类坑一次性避掉。**

### `--host=0.0.0.0` 能做什么：让同学直接打开你的页面

加了这个参数之后，**同一个局域网里的其他设备可以访问你的页面**——
最实用的就是**用手机看自己做的页面**，尤其是第 03 课的响应式。

**第一步：查自己的局域网 IP**

**Windows CMD**

```bat
ipconfig
```

**Windows PowerShell**

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' -or $_.IPAddress -like '10.*' } | Select-Object IPAddress, InterfaceAlias
```

找 `IPv4 地址` 那一行，通常是 `192.168.x.x` 或 `10.x.x.x`。

**第二步：让同学（或你的手机）访问**

```text
http://你的IP:7000
```

比如 `http://192.168.1.23:7000`。**手机要连同一个 Wi-Fi。**

|问题|原因|处理|
|---|---|---|
|同学打不开|Windows 防火墙挡了|第一次启动时弹出的提示要选「允许访问」；已经点了拒绝就到「防火墙 → 允许应用」里放行 Node|
|手机打不开|不在同一个 Wi-Fi|确认手机和电脑连的是同一个网络，机房有时分了好几个网段|
|IP 有好几个|有虚拟网卡（VMware、WSL）|用 `192.168.` 开头那个通常没错，不行就一个个试|

> **安全提示**：`0.0.0.0` 的意思是"对本机所有网卡开放"。
> 在教室和家里的局域网没问题，**但不要在公共 Wi-Fi（咖啡馆、机场）下这么开**。
> 只想自己用的时候，把参数去掉就行：`npx live-server --port=7000`。

### 启动不起来怎么办

|终端里报什么|原因|处理|
|---|---|---|
|`'npx' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**；再 `node -v` 确认|
|卡在下载不动|npm 源慢|`npm config set registry https://registry.npmmirror.com` 之后重试|
|`EADDRINUSE` / 端口被占用|7000 已经被别的程序占了（**多半是你自己上一次没关**）|换一个端口：`--port=7001`；或者到之前那个终端按 `Ctrl+C`|
|浏览器显示目录列表，不是页面|工程根目录里没有 `index.html`|`dir index.html` 确认位置，`cd` 到对的目录重来|
|页面打开了但一片空白|HTML 里有错，或者文件名拼错|`F12` → Console 看红字；确认文件名大小写|
|改了代码不自动刷新|文件没保存；或者改的不是这个目录里的文件|`Ctrl+S`；确认 Trae 打开的文件夹和终端所在的是同一个|

**实在起不来也别耽误上课**：先双击 `index.html` 应急，
本课绝大部分内容照样能做，**下课前再来解决**。

### TODO 01 · 换掉全站标题颜色

**难度**：极简单


**为什么做这个**
把它放在第一个，是为了让你**立刻体会到 CSS 变量的价值**：
页面上有一个 `h1` 和七个 `h2`，一共八处标题——你只改一行，八处一起变。

**涉及的知识点**

```css
:root { --heading: #254a40; }   /* 定义：存一个值 */
h1, h2 { color: var(--heading); }  /* 使用：读它 */
```

|概念|说明|
|---|---|
|`:root`|代表整个文档的根元素（`<html>`），适合放全站通用的变量|
|`--名字`|自定义属性（变量），**开头必须是两个减号**|
|`var(--名字)`|读取这个变量|
|十六进制颜色|`#254a40` 是 红/绿/蓝 三组两位十六进制数|

**改哪里**：`lesson-02-task.css` 顶部 `:root` 里的 `--heading`。
备选值注释里给了四个，挑一个或自己调。

**操作前 / 操作后**

- 操作前：所有标题是墨绿色。
- 操作后：**一个 `h1` 加七个 `h2`，八处标题一起变成你选的颜色。**

**自己验证**
1. 保存刷新，从页面最上滚到最下，确认**每一个**栏目标题都变了。
2. F12 → Elements，点中任意一个 `h2`，右侧 Styles 面板里能看到
   `color: var(--heading)`，鼠标悬停在它上面会显示实际算出来的颜色值。

**多想一步**
如果不用变量，你得在 CSS 里找到所有写了这个颜色的地方，一个个改——
真实项目里可能有几十处，漏一处页面就"花"了。
**变量的本质是"给一个值起名字，让它只有一个出处"。**
这个思路在后面所有课里都会反复出现（第 05 课的数据数组、项目 4 的文案库都是同一回事）。

### TODO 02 · 把纯白底色换成"纸白"

**难度**：极简单


**为什么做这个**
纯白 `#ffffff` 在屏幕上是最刺眼的颜色。长时间阅读的网站——
知乎、微信读书、各种文档站——几乎都不用纯白。

**涉及的知识点**

|颜色写法|例子|说明|
|---|---|---|
|十六进制|`#fbfaf6`|最常用。六位分别是 红红绿绿蓝蓝|
|简写|`#fff`|等于 `#ffffff`，每位重复一次|
|`rgb()`|`rgb(251, 250, 246)`|每个通道 0—255|
|`rgba()`|`rgba(0, 0, 0, .5)`|最后一位是透明度，0 全透明、1 不透明|

`#fbfaf6` 比 `#ffffff` 低了几个数值，肉眼几乎看不出是"米色"，
但整页的刺眼感会明显下降。**好的设计常常是这种看不出来的差别。**

**改哪里**：`:root` 里的 `--background`。

**操作前 / 操作后**

- 操作前：页面底色是模板默认的。
- 操作后：整页底色变了。**对比办法**：新开一个空白标签页（纯白），
  和你的页面来回切，差别立刻就出来了。

**自己验证**
1. 保存刷新。
2. 新开一个空白标签页，两个标签来回切三次，你会觉得空白页"发白发亮"。
3. F12 → Elements，选中 `<body>`，Styles 里能看到你设的背景色。

**多想一步**
试试把 `--background` 改成 `#000`（纯黑），刷新看看——
**文字变得几乎看不清了**，因为文字颜色是深色的。
这说明背景和文字的颜色必须**成对考虑**，不能只改一边。
项目 4 会专门讲这件事，还会用脚本自动算"对比度够不够"。看完改回来。

### TODO 03 · 把正文调到读着舒服的大小

**难度**：简单


**为什么做这个**
字号是阅读体验里影响最大的一个变量，比配色重要得多。

**涉及的知识点**

|概念|说明|
|---|---|
|`px`|CSS 像素。`19px` 就是 19 个 CSS 像素，和屏幕物理像素不完全一样|
|继承|`body` 上设了 `font-size`，**里面的段落会自动继承**，不用一个个设|
|不要小于 16px|很多学生觉得 14px"精致"，那是给密集表格用的，长段落读着累|

**改哪里**：`:root` 里的 `--body-size`。建议在 17px—20px 之间试。

**操作前 / 操作后**

- 操作前：正文是默认大小。
- 操作后：正文明显变大或变小，**整页的"疏密感"跟着变**。

**自己验证**
1. 先改成 `14px` 刷新，再改成 `22px` 刷新，**两个极端都试一遍**，
   然后挑中间一个你觉得最舒服的。
2. F12 → Elements，选中任意一个 `<p>`，Computed 面板里的 `font-size`
   应该等于你设的值——**注意 `<p>` 上并没有写 font-size，它是继承来的**。

**多想一步**
`h1` 的 `font-size: 46px` 是写死的，**不会跟着变量变**。
这是故意留的：让你看到"继承"只对没有自己设值的元素生效。
想让标题也跟着缩放，可以用 `rem` 单位——那是后面的内容。

### TODO 04 · 把行高调开

**难度**：简单


**为什么做这个**
**这是本课最能体会到效果的一个任务。** 中文段落不调行高，
一眼看过去就是一堵密密麻麻的墙，读三行就想放弃。

**涉及的知识点**

```css
body { line-height: 1.8; }   /* 正确：不写单位 */
body { line-height: 1.8em; } /* 不推荐：会把算好的固定值硬塞给子元素 */
```

|概念|说明|
|---|---|
|行高|每一行文字占的高度。文字本身的高度之外，上下多出来的空隙|
|不写单位|`1.8` 表示"**自己字号**的 1.8 倍"，子元素按各自字号重新算|
|写 `em`|父元素先算成一个固定像素值，再塞给子元素，字号不同的子元素会挤|
|中文 vs 英文|中文字形方正、笔画密，行高要更大。英文常用 1.5，**中文建议 1.75—1.9**|

**改哪里**：两处都要改——
`:root` 里的 `--body-line`（定义），以及 `body` 里的 `line-height`（把它用上）。
**模板里 `body` 现在写的是 `1.5`，要改成 `var(--body-line)`。**

**操作前 / 操作后**

- 操作前：段落挤在一起，一眼看过去像一堵墙。
- 操作后：行与行之间松开，长段落明显好读。

**自己验证**
1. 改成 `1.2` 刷新——挤成一团；改成 `2.4` 刷新——散得不像一段话。
   然后调到 `1.8` 左右。**两个极端都试过，你才知道这个值在干什么。**
2. 用手机模拟器（F12 → 左上角手机图标）再看一次，窄屏上行高的影响更明显。

**多想一步**
为什么只改 `body` 一处，整页段落都变了？因为 `line-height` 是**可继承属性**。
可继承的大多是"文字相关"的：颜色、字体、字号、行高、对齐。
不可继承的大多是"盒子相关"的：边框、背景、内外边距、宽高。
**记不住没关系，记住"文字的会传下去、盒子的不会"就够用了。**

### TODO 05 · 用盒模型给栏目标题做出层次

**难度**：简单


**为什么做这个**
前四个任务改的都是"文字本身"。这一个第一次改**元素占多大地方**——
这是 CSS 里最核心、也最容易搞混的一块。

**涉及的知识点：盒模型的四层**

```text
┌─────────────── margin（和邻居的距离，背景色铺不到）
│ ┌───────────── border（边框）
│ │ ┌─────────── padding（内容到边框的距离，背景色铺到这里）
│ │ │
│ │ │  content（文字本身）
│ │ │
```

**padding 和 margin 怎么区分？**

|想要什么效果|用哪个|
|---|---|
|让背景色块变大，文字周围更宽松|`padding`|
|让这个元素和上下左右的元素离远点|`margin`|

**多值写法**：

```css
padding: 8px;              /* 四边都是 8px */
padding: 8px 14px;         /* 上下 8px，左右 14px */
padding: 8px 14px 10px;    /* 上 8，左右 14，下 10 */
padding: 8px 14px 10px 6px;/* 上 右 下 左，顺时针 */
```

**改哪里**：`lesson-02-task.css` 里的 `h2` 规则。三个数值都改一遍：
`padding`、`border-left` 的粗细、`background` 的颜色。

**操作前 / 操作后**

- 操作前：栏目标题和正文混在一起，扫一眼分不清哪里是新栏目的开头。
- 操作后：标题有了底色块和左侧竖线，**栏目边界一目了然**。

**自己验证（这一条一定要做完）**
1. 把 `padding: 8px 14px` 改成 `padding: 30px`，刷新——
   **底色块变得很大**，因为背景铺到 padding。
2. 再改回 `8px 14px`，另外给 `h2` 加一行 `margin: 30px;`，刷新——
   **标题被推远了，但底色块大小没变**。
3. **这两步的对比就是 padding 和 margin 的全部区别。** 做完把 margin 那行删掉。
4. F12 → Elements 选中 `h2`，右下角有一张**四色盒模型图**：
   橙色是 margin，黄色是 border，绿色是 padding，蓝色是 content。
   鼠标移到每一层上，页面里对应区域会高亮。

**多想一步**
`border-left: 3px solid #b8a27d` 这一条竖线，为什么不用 `border` 画四条边？
因为只画左边一条，视觉上像"引用标记"，指向性很强又不封闭——
这是排版里很常用的一个手法。试试改成 `border: 3px solid`，看四边框住之后
是不是显得笨重。看完改回来。

### TODO 06 · 让链接在鼠标移上去时有反应

**难度**：中等


**为什么做这个**
现在链接是"死"的，鼠标移上去除了光标变小手没有任何变化。
用户在点之前需要一个确认："我要点的就是这个"。
**这是本课第一个和"交互"有关的任务**，也是第 04 课 JavaScript 的铺垫。

**涉及的知识点：伪类**

```css
a { color: #42635b; }               /* 平时 */
a:hover { color: #254a40; }         /* 鼠标悬停时 */
a:focus-visible { outline: 2px solid; }  /* 键盘 Tab 选中时 */
```

|概念|说明|
|---|---|
|伪类|以 `:` 开头，选的是元素的**状态**，不是元素本身|
|`:hover`|鼠标悬停|
|`:focus-visible`|用键盘 Tab 切换到它时。**键盘用户靠它知道自己选中了哪个**|
|`transition`|让变化"渐变"而不是"瞬变"|

`transition: color .2s` 的意思是"`color` 这个属性发生变化时，用 0.2 秒过渡完"。
**0.2 秒左右最自然**：短了看不出来，长了会觉得页面"粘"。

**改哪里**：`lesson-02-task.css` 里 `a` 那条规则下面，补两条：

```css
a { transition: color .2s, text-decoration-thickness .2s; }
a:hover { color: var(--heading); text-decoration-thickness: 2px; }
```

**操作前 / 操作后**

- 操作前：鼠标移到链接上，除了光标变小手没有任何变化。
- 操作后：链接颜色**平滑地**变深，下划线变粗，"可以点"这件事变得很明确。

**自己验证**
1. 鼠标在链接上移进移出几次，颜色应该是**渐变**的，不是"啪"地换掉。
2. 把 `transition` 那行临时注释掉（前后加 `/*` `*/`），再移一次——
   **能明显感到生硬**。看完取消注释。
3. 用键盘按 `Tab` 键在页面里跳，看能不能清楚看到"现在选中的是哪个链接"。

**多想一步**
只做 `:hover` 是不够的——**手机上没有鼠标，永远不会触发 hover**，
键盘用户也用不上。所以正规做法是 `:hover` 和 `:focus-visible` 一起写。
这一课先建立意识，第 03 课做响应式时会再回到这个问题。

### TODO 07 · 限制正文宽度，别让文字横跨整个屏幕

**难度**：中等


**为什么做这个**
把浏览器窗口拉到最宽，现在的文字会一直铺到屏幕两端。
一行太长，眼睛从行尾回到下一行的行首时**很容易串行**——
这是排版里最基本的一条规律，和字体配色无关，纯粹是生理问题。

**涉及的知识点**

|写法|区别|
|---|---|
|`width: 960px`|**永远** 960 宽。手机上会横向溢出，要左右拖着看|
|`max-width: 960px`|**最多** 960 宽。屏幕比它窄时自动缩小，手机上正常|

**做响应式永远优先用 `max-width`。** 这是第 03 课的核心思路，本课先埋下。

`margin-left: auto; margin-right: auto;` 是"左右外边距平分剩余空间"，
效果就是**水平居中**。这是 CSS 里居中一个块元素最经典的写法。

**一行多宽最好读？** 印刷和网页排版的共识是
**45—75 个西文字符**，中文大约 30—40 个字。960px 配 19px 字号差不多正好。

**改哪里**：`lesson-02-task.css` 末尾，按注释补上 `.container` 的规则。

**操作前 / 操作后**

- 操作前：把窗口拉到最宽，文字从屏幕最左铺到最右，读起来要转头。
- 操作后：内容居中成一栏，两侧留白，**无论屏幕多宽都好读**。

**自己验证**
1. 把浏览器窗口从最窄慢慢拉到最宽。改之前文字一直跟着变宽；
   改之后到 960px 就停住了，两边开始留白。
2. 把 `max-width` 临时改成 `width`，然后把窗口拉得**很窄**——
   会出现横向滚动条，内容被挤出屏幕。**这就是两者的区别。** 看完改回 `max-width`。
3. 数一数一行大概多少个中文字，应该在 30—40 之间。

**多想一步**
`.container` 这个类在 `index.html` 里出现了好几处（页头、正文、页脚都有）。
你只写一条规则，所有用了这个类的地方一起生效——
**这就是"类"存在的意义：把同一种样式起个名字，到处复用。**
回头看第 01 课那些 `class="experience-item"`，现在应该明白它们是干什么的了。

## 6. Git 提交与推送

### 第一步：先看清楚自己改了什么

**Windows CMD / PowerShell 通用**（Git 命令两边写法完全一样）

```bat
REM 列出有改动的文件
git status

REM 逐行看改了什么内容；按 q 退出查看
git diff
```

确认列表里**只有你自己改的文件**，没有密码、临时文件和无关文件。

### 第二步：提交

```bat
REM . 表示"当前目录下所有改动"
git add .

REM -m 后面是这次改了什么，用一句话写清楚
git commit -m "P1第02课：配色、字号、行高、盒模型与内容宽度"

REM 看一眼刚才提交成功没有
git log -1 --oneline
```

### 第三步：推送到你自己的仓库

```bat
git push origin main
```

**如果报 `'origin' does not appear to be a git repository`：**

这是正常的，不是你操作错了。本课工程是从上一课或教师模板克隆来的，
它的来源已经被改名成 `previous` / `course`——那是**别人的仓库，不能推**。

先到 GitHub 新建一个空仓库，名字用 `p1-lesson-02-学号`（新建时**不要**勾选
"Add a README file"，否则会和本地冲突），然后：

**Windows CMD**

```bat
REM 告诉 git "我自己的仓库在这儿"
git remote add origin https://github.com/你的用户名/p1-lesson-02-学号.git

REM -M 把当前分支强制改名成 main
git branch -M main

REM -u 记住这次的目标，以后只写 git push 就够了
git push -u origin main

REM 确认：origin 应该指向你自己的仓库
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p1-lesson-02-学号.git
git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。

### 第四步：开启 GitHub Pages

1. 打开你刚推上去的仓库页面。
2. 顶部 `Settings` → 左侧 `Pages`。
3. Source 选 `Deploy from a branch`。
4. 分支选 `main`，目录选 `/(root)`，点 `Save`。
5. 等一到两分钟，刷新这个页面，顶部会出现 `Your site is live at ...`。

**打开那个网址，把第 5 节的自检清单在线上再走一遍。**
本地好好的、线上不对，九成是文件名大小写写错了——
Windows 不区分大小写，服务器区分，`App.js` 和 `app.js` 在服务器上是两个文件。

## 常见问题

### 改了没反应

|现象|原因|处理|
|---|---|---|
|改了 CSS 页面完全没变|`index.html` 里没有引用 `lesson-02-task.css`|见第 2 节第三步|
|引用了也没变|引用写在了 `styles.css` **前面**|两行调换顺序，后写的才能覆盖前面的|
|还是没变|浏览器缓存了旧 CSS|按 `Ctrl+F5` 强制刷新；也确认一下跑 live-server 的终端还开着|
|只有一部分标题变了|有的标题被更具体的选择器覆盖了|F12 选中它，Styles 面板里被划掉的就是"输掉的规则"|
|`h1` 字号没跟着变量变|`h1` 自己写死了 `font-size: 46px`|这是故意的，用来演示"继承只对没设值的元素生效"|

### 效果不对

|现象|原因|处理|
|---|---|---|
|文字看不清了|背景和文字颜色都改成了深色|背景和文字要**成对**考虑，改一边就要看另一边|
|标题底色块很大很怪|`padding` 值给太大了|回到 `8px 14px` 附近再微调|
|标题和正文粘在一起|用了 `padding` 但想要的是 `margin`|让它离邻居远点要用 `margin`|
|段落散得不像一段话|`line-height` 给到 2.4 以上了|中文正文 1.75—1.9 最合适|
|窄屏出现横向滚动条|写成了 `width` 而不是 `max-width`|改成 `max-width`|
|悬停变色很生硬|漏了 `transition`|给 `a` 加 `transition: color .2s;`|

|现象|原因|处理|
|---|---|---|
|`git fetch` 之后 `dir` 找不到文件|这是正常的，`fetch` 只下到 `.git` 里|必须再执行第三条 `git checkout ... -- 文件名`|
|`remote course already exists`|之前加过了|跳过第一条命令|
|`dir` 看不到 `index.html`|不在工程文件夹里|把第 1 节的 `cd` 重新执行一遍|
|`git push` 报 `'origin' does not appear...`|来源已改名成 previous / course|见第 6 节第三步|
|Pages 上样式全没了|CSS 文件没提交|`git status` 看有没有漏文件|
