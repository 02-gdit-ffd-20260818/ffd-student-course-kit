这是整门课的第一节。六次课做同一个作品——**你自己的个人主页**，

|课次|这一课加上什么|
|---|---|
|**01（本课）**|**把内容写对：姓名、照片、经历、作品、联系方式，并第一次发布上线**|
|02|用 CSS 让它好看：字体、配色、盒模型|
|03|响应式：手机上也好读；作品图片自适应|
|04|JavaScript：导航高亮、滚动联动、返回顶部|
|05|作品列表改成由数据生成，还能筛选排序|
|06|测试、修复，交出最终版本，并让 GitHub 自动检查|

**本课不碰样式，也不碰 JavaScript。** 只把"内容"这件事做扎实——
一个页面如果内容本身没写对，后面加再多特效都没意义。

## 开课前先讲这些概念

学生动手之前，先把这几个词讲清楚。每个只讲到"能用自己的话解释"为止，不展开。

|知识点|小白要理解的话|本课在哪里用到|
|---|---|---|
|HTML|决定页面**"是什么"**：这是标题、这是段落、这是图片|全部 TODO|
|标签|用尖括号包起来的名字，成对出现：`<p>内容</p>`|全部 TODO|
|属性|写在开始标签里的附加信息：`<img src="..." alt="...">`|TODO 03、04、06|
|语义标签|`header`/`main`/`section`/`footer` 这类**有含义**的标签，人和机器都能看懂|TODO 07|
|标题层级|`h1` 只能有一个，是全页最重要的；`h2` 是栏目标题，不能跳级用|TODO 02|
|相对路径|`assets/photo.jpg` 表示"从当前文件出发，进 assets 文件夹找"|TODO 03|
|链接协议|`https:` 打开网页，`mailto:` 唤起邮件，`#id` 跳到本页某处|TODO 04、06|
|Git|`add` 挑出这次要保存的改动，`commit` 存成一个带说明的版本|第 6 节|

### 三个最小例子，本课七个任务都是它们的变形

**例 1：标签包内容**

```html
<h1>张三</h1>
<p>软件技术专业在读，喜欢把想法做成能打开的网页。</p>
```

**例 2：属性带信息**

```html
<!-- src 是图片在哪，alt 是图片加载不出来时替代的文字 -->
<img src="assets/zhangsan.jpg" alt="张三的证件照">
```

**例 3：链接的三种去处**

```html
<a href="https://example.com">去别的网站</a>
<a href="mailto:me@example.com">给我发邮件</a>
<a href="#portfolio">跳到本页的作品栏目</a>
```

**这三个例子的分工要讲透**：标签决定"这是什么"，属性决定"细节是什么"，
链接决定"点了去哪"。本课所有 TODO 都跳不出这三件事。

> **`alt` 不是可有可无的。** 图片加载失败时它顶上来，视障用户用读屏软件时靠它理解图片。
> 写「图片」「照片」等于没写，要写清楚图上是什么：「张三在实验室调试电路板」。

**Windows CMD**

```bat
REM 先确认自己在工程根目录：看得到 index.html 才对
dir index.html

REM 启动本地服务器（第一次运行会先下载 live-server，要联网，等十几秒）
```

**Windows PowerShell**

```powershell

# 启动本地服务器

```

**这条命令每个部分是什么意思**：

|部分|作用|
|---|---|
|`npx`|**临时下载并运行**一个命令行工具，用完就好，不用先 `npm install -g` 装到电脑上|
|`live-server`|一个极小的本地网页服务器，**自带热更新**|
|`--port=7000`|服务开在 7000 端口。网址就是 `http://localhost:7000`|
|`--host=0.0.0.0`|**允许同一个局域网里的其他设备访问**（不加只有本机能开）|

### 第三步：确认启动成功

终端里会打印出类似这样的内容：

```text
Serving "E:\...\p1-lesson-01" at http://127.0.0.1:7000
Ready for changes
```

**看到 `Ready for changes` 才算成功。** 浏览器通常会自动打开；
没自动打开就自己访问 <http://localhost:7000>。

**三件事要记住**：

1. **这个终端要一直开着。** 关掉它服务就停了，页面会打不开。
2. **停止服务按 `Ctrl + C`**（在跑着服务的那个终端里按）。
3. **改完代码按 `Ctrl+S` 保存，浏览器会自己刷新**，
   不用再按 `Ctrl+R`。这就是"热更新"。

### 第四步：打开开发者工具

按 `F12`，**整节课都开着**。这一课主要用两个标签：
   - **Elements**：看页面的结构树，点一个元素能在页面上高亮出来；
   - **Network**：看图片有没有加载成功。**红色的行就是没加载到的资源。**

> **一个好习惯**：把 Trae 和浏览器左右并排放。改一处、保存、看效果。
> 有了热更新，这个循环只剩"改 → 看"两步，**不要一口气改完再试**。

### 为什么不双击打开 HTML

双击打开时，浏览器地址栏是 `file:///E:/.../index.html`；
用服务器打开是 `http://localhost:7000`。**这两个不是一回事。**

|  |双击打开（file 协议）|本地服务器（http 协议）|
|---|---|---|
|改完代码|**要自己按 `Ctrl+R` 刷新**|**自动刷新**|
|读取本地 JSON、用 `fetch`|**会被浏览器拦住**（跨域限制）|正常|
|`type="module"` 的脚本|**加载不了**|正常|
|`localStorage`|行为和正式环境不一样|和正式环境一致|
|同学能不能看到|不能|**能**，见下面|
|和上线之后的环境|不一样|**几乎一样**|

后面几课会用到 JSON 数据、模块化脚本、本地存储，
**那时候用 file 协议打开会直接报错，而且报的错看起来毫无道理**
（"明明文件就在那儿"）。
**从第一课就用服务器，把这类坑一次性避掉。**

### `--host=0.0.0.0` 能做什么：让同学直接打开你的页面

加了这个参数之后，**同一个局域网里的其他设备可以访问你的页面**——
最实用的就是**用手机看自己做的页面**，尤其是第 03 课的响应式。

**第一步：查自己的局域网 IP**

**Windows CMD**

```bat
ipconfig
```

**Windows PowerShell**

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' -or $_.IPAddress -like '10.*' } | Select-Object IPAddress, InterfaceAlias
```

找 `IPv4 地址` 那一行，通常是 `192.168.x.x` 或 `10.x.x.x`。

**第二步：让同学（或你的手机）访问**

```text
http://你的IP:7000
```

比如 `http://192.168.1.23:7000`。**手机要连同一个 Wi-Fi。**

|问题|原因|处理|
|---|---|---|
|同学打不开|Windows 防火墙挡了|第一次启动时弹出的提示要选「允许访问」；已经点了拒绝就到「防火墙 → 允许应用」里放行 Node|
|手机打不开|不在同一个 Wi-Fi|确认手机和电脑连的是同一个网络，机房有时分了好几个网段|
|IP 有好几个|有虚拟网卡（VMware、WSL）|用 `192.168.` 开头那个通常没错，不行就一个个试|

> **安全提示**：`0.0.0.0` 的意思是"对本机所有网卡开放"。
> 在教室和家里的局域网没问题，**但不要在公共 Wi-Fi（咖啡馆、机场）下这么开**。
> 只想自己用的时候，把参数去掉就行：`npx live-server --port=7000`。

### 启动不起来怎么办

|终端里报什么|原因|处理|
|---|---|---|
|`'npx' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**；再 `node -v` 确认|
|卡在下载不动|npm 源慢|`npm config set registry https://registry.npmmirror.com` 之后重试|
|`EADDRINUSE` / 端口被占用|7000 已经被别的程序占了（**多半是你自己上一次没关**）|换一个端口：`--port=7001`；或者到之前那个终端按 `Ctrl+C`|
|浏览器显示目录列表，不是页面|工程根目录里没有 `index.html`|`dir index.html` 确认位置，`cd` 到对的目录重来|
|页面打开了但一片空白|HTML 里有错，或者文件名拼错|`F12` → Console 看红字；确认文件名大小写|
|改了代码不自动刷新|文件没保存；或者改的不是这个目录里的文件|`Ctrl+S`；确认 Trae 打开的文件夹和终端所在的是同一个|

**实在起不来也别耽误上课**：先双击 `index.html` 应急，
本课绝大部分内容照样能做，**下课前再来解决**。

### TODO 01 · 改掉浏览器标签页上的名字

**难度**：极简单


**为什么做这个**
`<title>` 的内容**不显示在页面里**，它显示在浏览器标签页上，
也是别人收藏这个页面、搜索引擎收录时看到的名字。
把它放在第一个，是因为它能立刻说明一件事：**HTML 里不是所有内容都会出现在页面上。**

**涉及的知识点**

|概念|说明|
|---|---|
|`<head>`|页面的"说明书"区域，里面的东西给浏览器和搜索引擎看，不直接显示|
|`<title>`|标签页上的名字，也是收藏夹里的名字|
|`<body>`|页面的"正文"区域，这里面的才会显示出来|

**改哪里**：`index.html` 最上面，`TODO 01` 注释下面那个 `<title>`。
写法建议：`姓名 · 一句话身份`，例如 `张三 · 软件技术在读`。

**操作前 / 操作后**

- 操作前：浏览器标签页上写着「我的个人主页」。
- 操作后：标签页上写着你的名字。

**自己验证**
1. 保存刷新，看浏览器**标签页**（不是页面内容）。
2. 按 `Ctrl+D` 试着收藏一下，收藏对话框里显示的就是这个名字（看完可以取消）。

**多想一步**
把 `<title>` 里的字改了，页面内容一个字都没变——这说明 `<head>` 里的东西
和 `<body>` 里的东西职责完全不同。以后学 `<meta>` 描述、分享预览图，也都在 `<head>` 里。

### TODO 02 · 把首屏的姓名和身份换成自己的

**为什么做这个**
首屏是别人打开你主页看到的第一块内容，HR 停留的头三秒就在看这里。

**涉及的知识点**


|`class`|给元素起的样式名，CSS 靠它找到这个元素。改内容时**不要动 class**|

**改哪里**：`TODO 02` 注释下面那一段，`section class="hero"` 里面。

**操作前 / 操作后**

- 操作前：首屏写着模板里的示例姓名和方向。
- 操作后：首屏是你的姓名、你的专业方向，一句话说清你是谁。

**自己验证**
1. 保存刷新，页面最上方的大字就是你的名字。
2. F12 → Elements，确认它确实在 `<h1>` 里，不是 `<h2>` 或 `<div>`。
3. 页面上从头到尾**只有一个 `h1`**：在 Console 里输入

**多想一步**
为什么一页只写一个 `h1`？搜索引擎和读屏软件把它当成"这一页讲什么"的总标题。

### TODO 03 · 换上你自己的照片

**难度**：简单


**为什么做这个**
这是首屏第二显眼的东西。同时它是本课唯一一个**涉及文件路径**的任务——
路径写错是初学者最常见的故障，在这里踩一次比以后踩强。

**涉及的知识点**

```html
<img src="assets/zhangsan.jpg" alt="张三在实验室调试电路板">
```

|属性|作用|写错会怎样|
|---|---|---|
|`src`|图片在哪。`assets/x.jpg` 表示"从当前 HTML 出发，进 assets 文件夹找 x.jpg"|图片裂开，显示 alt 文字|
|`alt`|图片的文字替代|图片裂了什么都看不到；读屏软件念不出内容|

**相对路径怎么读**：

```text
assets/photo.jpg    进 assets 文件夹，拿 photo.jpg
./assets/photo.jpg  同上，./ 表示"当前文件夹"，可以省略
../photo.jpg        ../ 表示"上一层文件夹"
/assets/photo.jpg   开头的 / 表示"网站根目录"，本地打开时常常找不到，本课不要用
```

**改哪里**：先把你的照片文件**放进 `assets` 文件夹**，再改 `TODO 03` 下面 `img` 的
`src` 和 `alt`。

**操作前 / 操作后**

- 操作前：首屏右侧是模板自带的占位图。
- 操作后：是你自己的照片，且**鼠标悬停时能看到 alt 文字**。

**自己验证**
1. 保存刷新，照片出来了。
2. **故意把 `src` 改错一个字母**，刷新——图片裂开，位置上显示你写的 alt 文字。
   这就是 alt 的作用。看完改回来。
3. F12 → Network 标签，刷新页面，找到你的图片那一行，状态码应该是 `200`。
   如果是 `404`，就是路径写错了。

**多想一步**
文件名里**不要有中文和空格**。`我的照片 1.jpg` 在本地能打开，传到服务器上
常常就裂了——网址里的中文和空格要转义，很容易出错。
养成习惯：文件名只用小写英文、数字和短横线，`zhang-san.jpg`。

### TODO 04 · 把联系方式做成能点的链接

**难度**：简单


**为什么做这个**
现在联系方式只是一段死文字，别人看到了还得手动抄下来。
这个任务第一次让页面上的东西"可以被操作"。

**涉及的知识点**

```html
<a href="mailto:me@example.com">me@example.com</a>
```

链接的 `href` 可以是三种完全不同的东西：

|写法|点了会怎样|
|---|---|
|`href="https://example.com"`|打开另一个网站|
|`href="mailto:me@example.com"`|唤起电脑上的邮件客户端，收件人已填好|
|`href="#portfolio"`|跳到**本页**里 `id="portfolio"` 的地方|

**改哪里**：`TODO 04` 注释下面，把那段 `<p>请填写可公开的联系方式</p>` 里的文字
换成一个 `<a href="mailto:你的邮箱">你的邮箱</a>`。

**安全提醒**：**只写可以公开的联系方式。** 不要写手机号、身份证号、家庭住址、
班级群号。这个页面最后会发布到公网，任何人都能看到。

**操作前 / 操作后**

- 操作前：一行灰色的死文字，鼠标移上去没有任何反应。
- 操作后：文字变成带下划线的链接，鼠标移上去**变成小手**，点一下唤起邮件客户端。

**自己验证**
1. 鼠标移上去，光标变成小手，浏览器**左下角**显示 `mailto:...`。
2. 点一下（如果电脑装了邮件客户端会弹出来；没装也没关系，看左下角提示就够）。
3. F12 → Elements，确认它是 `<a>` 标签，且 `href` 以 `mailto:` 开头。

**多想一步**
`mailto:` 和 `https:` 一样叫**协议**。浏览器看到协议名，才知道该"打开网页"
还是"交给邮件软件"。还有 `tel:`（打电话）、`sms:`（发短信），手机上很常用。

### TODO 05 · 写上你自己的经历，并再加一条

**难度**：简单


**为什么做这个**
前四个任务都是"改一处文字"。这一个第一次让你**复制整块结构**——
这是 HTML 最常做的事，也是最容易弄坏页面的地方。

**涉及的知识点**

|概念|说明|
|---|---|

|`<strong>`|表示"内容重要"，浏览器通常显示为粗体|

一直选到**对应的那个** `</div>`，整块一起复制。
Trae 里把鼠标放在 `<div` 上，编辑器会用一条竖线标出它到哪里结束。

- 操作后：至少两条你自己的经历，时间、单位、说明都对得上，**排版和第一条一模一样**。

2. **如果第二条样式乱了**，九成是复制时少带了一个 `</div>`。

### TODO 07 · 给页脚加上署名，并检查整页的语义结构

**难度**：中等


**为什么做这个**
两件事：一是给页面一个正式的收尾；二是回头**整体看一遍这页的骨架**——
这是本课最重要的一个认知任务。

**涉及的知识点：语义标签**

```html
<header>  页头，放品牌和导航
<main>    正文主体，一页只有一个
<section> 一个有明确主题的区域，通常带 id 和标题
<footer>  页脚，放署名、备案、次要链接
```

**为什么不能全用 `<div>`？**

|用 `<div class="header">`|用 `<header>`|
|---|---|
|浏览器只知道"这是个盒子"|浏览器知道"这是页头"|
|读屏软件念不出结构，视障用户只能一行行听|读屏软件可以直接"跳到主内容"|
|搜索引擎难以判断哪块是正文|搜索引擎知道 `<main>` 里的才是重点|

**语义标签不改变外观，改变的是"机器能不能读懂"。** 这是它最难被初学者接受、
也最重要的一点。

**改哪里**：`TODO 07` 注释下面的 `<footer>`，在两个链接后面加一段 `<p>© 2026 你的名字</p>`。

**操作前 / 操作后**

- 操作前：页脚只有两个链接，页面结尾很突兀。
- 操作后：页脚多一行署名，整页有了正式收尾。

**自己验证**
1. 保存刷新，页脚出现署名。
2. **整页结构自查**：F12 → Elements，把最外层折叠起来，你应该清楚看到
   `header` → `main` → `footer` 三块并列。
3. 在 Console 里逐条输入，确认结构正确：

```js
document.querySelectorAll('h1').length        // 应该是 1
document.querySelectorAll('main').length      // 应该是 1
document.querySelectorAll('section[id]').length  // 应该是 7
```

**多想一步（课堂演示，做完记得撤销）**
把 `<main id="main">` 临时改成 `<div id="main">`，保存刷新——
**页面看起来一模一样**，因为 CSS 用的是 `#main` 这个 id，不是标签名。
但这时候读屏软件就找不到"主内容"了。
**这就是语义标签的意义：给人看的没变，给机器看的塌了。** 看完按 `Ctrl+Z` 撤销。

## 6. Git 提交与推送

### 第一步：先看清楚自己改了什么

**Windows CMD / PowerShell 通用**（Git 命令两边写法完全一样）

```bat
REM 列出有改动的文件
git status

REM 逐行看改了什么内容；按 q 退出查看
git diff
```

确认列表里**只有你自己改的文件**，没有密码、临时文件和无关文件。

### 第二步：提交

```bat
REM . 表示"当前目录下所有改动"
git add .

REM -m 后面是这次改了什么，用一句话写清楚
git commit -m "P1第01课：完成个人内容并首次上线"

REM 看一眼刚才提交成功没有
git log -1 --oneline
```

### 第三步：推送到你自己的仓库

```bat
git push origin main
```

**如果报 `'origin' does not appear to be a git repository`：**

这是正常的，不是你操作错了。本课工程是从上一课或教师模板克隆来的，
它的来源已经被改名成 `previous` / `course`——那是**别人的仓库，不能推**。

先到 GitHub 新建一个空仓库，名字用 `p1-lesson-01-学号`（新建时**不要**勾选
"Add a README file"，否则会和本地冲突），然后：

**Windows CMD**

```bat
REM 告诉 git "我自己的仓库在这儿"
git remote add origin https://github.com/你的用户名/p1-lesson-01-学号.git

REM -M 把当前分支强制改名成 main
git branch -M main

REM -u 记住这次的目标，以后只写 git push 就够了
git push -u origin main

REM 确认：origin 应该指向你自己的仓库
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p1-lesson-01-学号.git
git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。

### 第四步：开启 GitHub Pages

1. 打开你刚推上去的仓库页面。
2. 顶部 `Settings` → 左侧 `Pages`。
3. Source 选 `Deploy from a branch`。
4. 分支选 `main`，目录选 `/(root)`，点 `Save`。
5. 等一到两分钟，刷新这个页面，顶部会出现 `Your site is live at ...`。

**打开那个网址，把第 5 节的自检清单在线上再走一遍。**
本地好好的、线上不对，九成是文件名大小写写错了——
Windows 不区分大小写，服务器区分，`App.js` 和 `app.js` 在服务器上是两个文件。

## 常见问题

### 页面显示不对

|现象|原因|处理|
|---|---|---|
|照片裂开，显示一行文字|`src` 路径写错|F12 → Network 看那张图是不是 404；检查文件名大小写和文件夹名|
|照片在本地能看，Pages 上裂了|文件名有中文、空格，或大小写不一致|改成小写英文加短横线，重新提交|
|改了内容页面没变|没保存；或者 live-server 没在跑|先 `Ctrl+S`；再看终端是不是还显示着 `Ready for changes`。仍然不变按 `Ctrl+F5` 强制刷新|
|第二条经历样式乱了|复制时少带了 `</div>`|F12 → Elements 展开看，两块应该并列不是嵌套|
|整页排版突然崩了|某个标签没闭合|Trae 里看标签配对的竖线；或者 `Ctrl+Z` 退回上一步重来|
|点作品卡把主页顶掉了|`target="_blank"` 被删了|加回去，同时确认 `rel="noopener noreferrer"` 也在|

### 命令与提交

|现象|原因|处理|
|---|---|---|
|`'git' 不是内部或外部命令`|Git 没装，或装完没重开终端|装完**关掉所有终端窗口**再开新的|
|`dir` 看不到 `index.html`|不在工程文件夹里|把第 1 节的 `cd` 重新执行一遍|
|`git push` 报 `'origin' does not appear...`|来源已改名成 course / previous|见第 6 节第三步，先关联自己的仓库|
|GitHub 推送要账号密码，输了还是不行|GitHub 不再支持密码推送|用浏览器弹出的授权登录；或改用 SSH（见通用附录）|
|Pages 打开是 404|刚保存还没构建完，或目录选错|等一两分钟；确认选的是 `main` + `/(root)`|
|Pages 上样式全没了|`styles.css` 没提交，或路径写错|`git status` 看有没有漏文件|

更多通用排错见 `通用附录_运行与排错.md`；
命令和参数的逐条解释见 [命令参数逐个拆开](<../../01_入门与通用规范/04_命令参数逐个拆开.md>)。
