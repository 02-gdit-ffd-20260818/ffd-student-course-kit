### 本课要用到的状态码

|状态码|意思|本课什么时候用|
|---|---|---|
|`200`|成功|登录成功|
|`201`|**创建**成功|注册成功（比笼统的 200 更准确）|
|`400`|你发的东西不合格|用户名太短、密码太短|
|`401`|**我不知道你是谁**|没登录，或密码不对，或令牌无效|
|`403`|我知道你是谁，但你不能干这个|（第 10 课会用到）|
|`409`|**冲突**：请求没问题，但和现有数据撞车了|用户名已被占用|
|`500`|**服务器内部错误**|完成本课后，普通输错应返回 400，不能变成 500；起点代码的短密码问题会在 TODO 02 修复|

**这张表要背下来。** 后面四节课一直在用。
初学者最常见的毛病是"不管什么错都返回 500"或者"不管什么错都返回 200 加一句话"，
那样前端根本没法区分该怎么处理。

### 两个最小例子

**例 1：一个最简单的接口**

```js
app.post('/api/hello', (req, res) => {
  const name = req.body?.name        // 取出前端发来的 JSON
  if (!name) return res.status(400).json({ error: { message: '请填写名字' } })
  res.json({ data: { greeting: `你好，${name}` } })
})
```

**例 2：参数化查询 vs 字符串拼接**

```js
// 危险：用户名里写一段 SQL 就能操作你的数据库
db.query(`SELECT * FROM users WHERE username='${username}'`)

// 安全：$1 是占位符，值单独传，无论里面写什么都只当数据
db.query('SELECT * FROM users WHERE username=$1', [username])
```

**这一课要建立的核心观念**：

> **前端的校验只是方便用户，后端的校验才是真的防线。**

任何人都能用 `curl` 绕过你的页面直接打接口。
所以凡是"不能让它发生的事"，都必须在后端挡住——最好再让数据库也挡一道。

## 2. 生成本机配置

后端要读 `.env` 里的配置才能启动。

**Windows CMD**

```bat
REM .env.example 是模板，可以进 Git；.env 存真实值，永远不进 Git
if not exist .env copy .env.example .env
findstr /B /C:"PORT=" /C:"DATABASE_PATH=" /C:"SESSION_SECRET=" /C:"ADMIN_USERNAME=" /C:"ADMIN_PASSWORD=" .env
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`findstr` 在文件中查找文字；`/B` 只匹配行首；每个 `/C:"字段="` 是一个完整查找词，多个 `/C` 表示任意一个匹配就显示；最后的 `.env` 是要读取的文件。`/R` 表示用正则表达式，`^` 是行首，`[A-Z_]` 是大写字母或下划线，`*` 是重复零次或多次。输出只用于本机检查，含密钥的行不要截图或发给别人。

`copy`（CMD）/ `Copy-Item`（PowerShell）把第一个路径的文件复制到第二个路径。只在目标配置尚不存在时复制模板；已有 .env 时直接打开并检查所需项，避免覆盖已经填写的值。
<!-- COMMAND_HELP:END -->


**Windows PowerShell**

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' }
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`Test-Path -LiteralPath 路径` 检查这个原样路径是否存在，返回 True 或 False；`-not` 取反。`if (...) { ... }` 只在条件成立时执行花括号里的操作，因此这里已有 .env 就不再覆盖。

`Get-Content` 逐行读取文件；`|` 把读取结果交给右边；`Where-Object` 只保留条件成立的行；`$_` 代表正在检查的那一行；`-match` 表示正则匹配；`^[A-Z_]+=` 表示行首是一个或多个大写字母/下划线，紧接等号。
<!-- COMMAND_HELP:END -->


能看到 `PORT=`、`DATABASE_PATH=`、`SESSION_SECRET=` 等配置行，说明复制成功。
这里故意只打印英文配置行，不打印中文注释，避免 CMD 把 UTF-8 中文显示成乱码；乱码不等于文件损坏。
**报「系统找不到指定的文件。」表示源文件或路径不存在**；先检查终端是否在本课工程根目录。若提示拒绝访问，也要解决权限问题后再继续。

现在运行下面的命令，生成一个约 43 字符的本机开发密钥：

```bat
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

**把命令逐段读懂**：`node` 是在终端运行 JavaScript；`-e` 表示直接执行引号内代码；
`require('node:crypto')` 加载 Node 自带密码学模块；`randomBytes(32)` 生成 32 字节安全随机数据；
`toString('base64url')` 把它变成约 43 个可复制字符；`console.log` 只负责打印。
命令不会自动修改任何文件：要把输出复制到自己的 `.env`，不要放进 `.env.example` 或 Git。

复制输出，打开 `.env`，把空行 `SESSION_SECRET=` 改成
`SESSION_SECRET=刚才生成的字符串`。不要照抄这段中文占位文字。

**涉及的知识点**

|约束|作用|不写会怎样|
|---|---|---|
|`NOT NULL`|这一列不能为空|能插入一个没有密码的用户|

- **约束是最后一道防线**：不管是谁、从哪个入口写数据，都绕不过它。

- **代码判断负责说人话**：约束被触发时数据库抛的是一句英文异常，

### TODO 02 · 把非法输入挡在后端

**难度**：简单


**为什么做这个**
前端的表单校验只是方便用户。**任何人都能用 `curl` 绕过你的页面直接打接口**——

**涉及的知识点**

```js
/^[a-z0-9_]{3,24}$/.test(username)
```

|部分|意思|
|---|---|
|`^` `$`|从头到尾完整匹配，不是"包含"|
|`[a-z0-9_]`|只允许小写字母、数字、下划线|
|`{3,24}`|长度 3 到 24|
|`.test(值)`|匹配返回 `true`，不匹配返回 `false`|

**为什么用户名限制得这么死？** 因为它会出现在网址里、数据库里、日志里。
放开空格和中文会带来一连串转义问题。**先收紧，以后要放开很容易；
先放开，以后收紧就会影响已有用户。**

**改哪里**：`server/blog-app.js` 注册接口里 TODO 02 的位置。

**具体怎么写**：在 TODO 02 注释结束线的下一行、TODO 03 标题的上一行，加入下面这一整段。这里考察的是正则、逻辑或 `||`、取反 `!`、类型与长度判断如何组合：

```js
if (
  !/^[a-z0-9_]{3,24}$/.test(username) ||
  !displayName ||
  displayName.length > 24 ||
  typeof password !== 'string' ||
  password.length < 12 ||
  password.length > 128
)
  return fail(res, 400, '用户名3—24位字母/数字/下划线，昵称1—24字，密码12—128字符')
```

逐行读懂后再输入：第一行是“用户名不匹配”，中间两行检查昵称，最后三行先检查密码类型、再检查上下限。六个判断用 `||` 连接，表示任意一个为真就拒绝。

### TODO 04 · 注册完直接就是登录状态

**难度**：中等


**为什么做这个**
用户刚填完一遍账号密码，如果还要再登录一次，体验很差。
同时这个任务引出本课最重要的概念：**令牌**。

**涉及的知识点**

**HTTP 是"无状态"的**：服务器处理完一个请求就忘了你是谁。
下一个请求过来，它**完全不知道**这是刚才那个人。

所以登录成功后要发一张"通行证"，之后每次请求都带上它：

```text
① 登录成功 → 服务器签发令牌 → 浏览器存起来
② 之后每次请求 → 浏览器在请求头带上 Authorization: Bearer <令牌>
③ 服务器验一下签名 → 知道"哦，是你"
```

**令牌的载荷只是 base64，不是加密**：任何人都能解开看见里面的内容。
所以里面只放 id、角色、过期时间这类不敏感信息。
它的安全性来自"**改了就对不上签名**"，不是"看不见"。

**`user(u)` 这个函数很关键**：它主动挑出安全字段返回。

```js
const user = u => ({ id: Number(u.id), username: u.username,
                     displayName: u.display_name, role: u.role })
```

**直接返回数据库那一行 `u` 是很常见的泄密方式**——那样 `password_hash`
和 `password_salt` 会一起发给浏览器。

### 已写好 · 把密码变成摘要再入库

**为什么做这个**
**数据库里永远不能出现明文密码。** 一旦被拖库，所有人的密码就都泄了——
而很多人在别的网站用的是同一个密码，后果会扩散到你控制不了的地方。

**涉及的知识点**

```js
const { salt, hash } = hashPassword(password)
```

|概念|说明|
|---|---|
|**摘要**|把密码算成一串固定长度的值，**算得回去是不可能的**|
|**盐**|每个用户一份的随机串，和密码拼在一起再算摘要|
|为什么要盐|没有盐，两个人用同样的密码会得到同样的摘要，拖库后一张预先算好的表就能批量还原|
|为什么用 scrypt|它**故意设计得很慢、很费内存**。正常登录慢几十毫秒无所谓，但让攻击者穷举的代价高到不现实|

**千万不要用 md5 / sha1 / sha256 直接算密码**——它们快得正好帮了攻击者。

**参数化查询**：

```js
// 危险：用户名里写一段 SQL 就能操作你的数据库
db.query(`INSERT INTO users(username) VALUES('${username}')`)

// 安全：$1 是占位符，值单独传
db.query('INSERT INTO users(username) VALUES($1)', [username])
```

`$1`—`$4` 和数组里的四项**按顺序一一对应**。数据库会把它们当成纯数据，
无论里面写什么都不会被当成 SQL 执行。

### 已写好 · 登录时验证密码

**为什么做这个**
注册只做一次，登录要做无数次。而且登录是最常被攻击的接口。

**涉及的知识点**

```js
const [u] = await db.query('SELECT * FROM users WHERE username=$1', [username])
if (!u || !verifyPassword(password, u.password_salt, u.password_hash))
  return fail(res, 401, '用户名或密码不正确')
```

**两种失败必须返回同一句话。** 如果分别提示"用户名不存在"和"密码错误"，
攻击者就能靠它一个个试出哪些用户名是真实存在的——这叫**用户名枚举**。
拿到一批真实用户名之后，再去撞库就容易多了。

**宁可让正常用户少一点提示，也不给攻击者送信息。**

**`verifyPassword` 里还有一层保护**：它用的是"恒定时间比较"。
普通的 `===` 比较从第一个字节开始，一不同就立刻返回，
于是"猜对前几个字节"会比"第一个字节就错"慢那么一点点。
攻击者反复测量这个时间差，就能一个字节一个字节地把摘要试出来（**时序攻击**）。
恒定时间比较无论内容是否相同都走完全程。详见 `server/services/auth.js`。

### 已写好 · 每个请求都先认一认"你是谁"

**为什么做这个**
前六个任务解决了"怎么发通行证"。这一个解决"怎么查通行证"。

它是一个**全局中间件**：所有接口在执行自己的逻辑之前，都先经过这里。
写在一处，所有接口都受益——这正是中间件存在的意义。

**涉及的知识点**

```js
app.use((req, res, next) => {
  req.user = verifyAccessToken(readBearerToken(req.get('authorization')), secret)
  next()        // 交给下一个中间件或接口
})
```

三步连起来看：

|步骤|做什么|
|---|---|
|`req.get('authorization')`|取请求头，形如 `Bearer eyJzdWIi...`|
|`readBearerToken(...)`|把 `Bearer ` 前缀去掉，只留令牌本身|
|`verifyAccessToken(...)`|**验签名、验过期**，通过返回载荷，否则返回 `null`|

**验证不通过返回 `null` 而不是抛错**，所以游客访问公开接口完全不受影响——
`req.user` 是 `null`，只是"不知道你是谁"，不是"出错了"。
这一点设计得很巧：同一个中间件既服务登录用户，也不妨碍游客。

`next()` 这一行不能漏。不调用它，请求就卡在这里，页面会一直转圈。

## 6. Git 提交与推送

### 第一步：提交前先本地验证

```bat
REM 后端测试
node scripts/check-lesson07.mjs 4

REM 看一眼数据库里真的有东西
npm run db:inspect
```

**测试不通过就不要提交。**

### 第二步：看清楚自己改了什么

```bat
git status
git diff
```

确认列表里**没有** `var/`（数据库文件）、`node_modules/`、`.env`。
这三样都在 `.gitignore` 里，正常不会出现；出现了说明 `.gitignore` 出了问题。

### 第三步：提交并推送

```bat
git add .
git commit -m "P2第07课：用户表约束、注册登录与令牌验证"
git push origin main
```

**推送报 `'origin' does not appear to be a git repository` 怎么办？**
路线 B 克隆下来之后，`origin` 已经被改名成 `template`
（那是全班共用的模板仓库，**不能推**）。
先到 GitHub 新建一个空仓库 `p2-blog-07-学号`（**不要**勾选 "Add a README file"），然后：

**Windows CMD**

```bat
git remote add origin https://github.com/你的用户名/p2-blog-07-学号.git
git branch -M main
git push -u origin main
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p2-blog-07-学号.git
git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。
`git remote -v` 应该看到：`origin` 指向你自己的仓库，`template` 指向公共模板仓库。

## 常见问题

### 启动与环境

|现象|原因|处理|
|---|---|---|
|`'npm' 不是内部或外部命令`|Node 没装或没重开终端|装完 Node 24 **关掉所有终端重开**|
|页面打开一片空白，Console 全是请求失败|终端 1 的后端没起来|回终端 1 执行 `npm run dev:api`|
|后端报 `请设置至少32字符 SESSION_SECRET`|`.env` 里没有这一项|复制 `.env.example` 为 `.env` 并填一个 32 位以上的随机串|
|启动时报 `ON CONFLICT clause does not match`|拿到了 2026-09-29 较早发布的第 7 课模板，种子写入错误依赖尚未完成的 `UNIQUE`|如果还没写代码，删除旧目录后重新克隆 `lesson-07`；不要为了绕过启动错误提前照抄 TODO 答案|
|`EADDRINUSE` 端口被占用|上一个进程没关干净|关掉所有终端重来；或改 `.env` 里的端口|
|改了后端代码没生效|`--watch` 没检测到|看终端 1 有没有打印重启信息；必要时 Ctrl+C 重启|

### 数据库

|现象|原因|处理|
|---|---|---|
|**改了建表语句没生效**|`CREATE TABLE IF NOT EXISTS` 不会改已有的表|按 TODO 01 保留旧库、修改 `.env` 的 DATABASE_PATH 为未使用的新练习库路径；重启后执行文件库检查，不删除旧库|
|`db:inspect` 报"先启动 npm run start:api"|数据库文件还没生成|先把后端跑起来，它首次启动会自动建库|
|注册报 500，终端里是 SQL 异常|表结构和 INSERT 的列对不上|对照 TODO 01 和 已写好的代码 检查列名|
|`SQLITE_CONSTRAINT`|违反了约束（比如插入了重复用户名）|正常现象，说明约束在工作；补上 TODO 03 给出友好提示|

### 接口

|现象|原因|处理|
|---|---|---|
|TODO 01 后仍能同名注册|只改了代码，未使当前文件库采用新结构；或网页连接旧后端|执行 TODO 01 的文件库检查，确认实际路径及页面请求目标；首次 201、第二次 409 才通过|
|任何请求都 404|路径写错，或前端代理没配|检查 `vite.config.js` 的 proxy 和接口路径|
|Network 里是 500|后端抛异常，被统一处理为通用提示|先运行当前阶段检查，核对输入校验和表结构；统一处理未必打印堆栈，不要认定终端无输出就没有错误，也不要把密码或令牌写入日志|
|登录成功但刷新就掉|已写好的代码 没做|全局中间件要读请求头|
|`req.body` 是 undefined|请求没带 `Content-Type: application/json`|curl 要加 `-H "Content-Type: application/json"`|
|curl 发中文乱码|Windows 终端默认不是 UTF-8|用页面测，或把请求体存成 UTF-8 文件再 `-d @req.json`|

### 提交

|现象|原因|处理|
|---|---|---|
|`git push` 报 `'origin' does not appear...`|来源已改名成 template|见第 6 节第三步|
|`var/` 或 `node_modules/` 出现在 `git status` 里|`.gitignore` 出了问题|检查 `.gitignore`，**数据库文件绝不能提交**|

更多通用排错见 `通用附录_运行提交部署与排错.md`；
命令和参数的逐条解释见 [命令参数逐个拆开](<通用/04_命令参数逐个拆开.md>)。
