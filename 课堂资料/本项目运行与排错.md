## 2. 四次课的存储方式对照


## 3. 每次课都要做的三处验证

只看页面「好像没报错」不算完成。三处证据缺一不可：

1. **浏览器 Network**：F12 → Network，找到本次操作的请求，看 HTTP 状态码。
2. **后端终端**：后端有没有打印请求或报错。
3. **数据层**：

|课次|怎么查数据|
|---|---|
|12|打开 `backend/db.json` 搜索刚才的记录|
|13|`npm run db:status`|
|14|`mysql -u personalink -p personalink -e "SELECT COUNT(*) FROM users;"`|
|15|`docker compose exec postgres psql -U personalink -d personalink -c "SELECT COUNT(*) FROM users;"`|

## 4. HTTP 状态码速查

|状态码|含义|常见场景|
|---|---|---|
|200|成功|查询成功|
|201|已创建|注册成功|
|400|请求有问题|少填字段、班级不存在|
|401|没登录|没带令牌或令牌过期|
|403|登录了但没权限|普通用户访问管理员接口|
|404|地址不存在|路由拼错、忘了 `/api` 前缀|
|409|冲突|邮箱已被注册|
|500|服务器内部错误|后端代码抛异常，去看后端终端|

**401 和 403 的区别是考点**：401 是「你是谁我不知道」，403 是「我知道你是谁，但你不能干这个」。

## 5. Git 标准流程

```cmd
REM 1. 看改了什么
git status

REM 2. 确认 .env、node_modules、数据库文件都没出现在列表里
REM    出现了就先检查 .gitignore，不要直接 add

REM 3. 加入暂存区
git add .

REM 4. 提交，写清楚这次做了什么
git commit -m "第XX课：一句话说明本次改动"

REM 5. 推送到个人仓库
git push origin main
```

第一次推送到个人仓库：

```cmd
REM 绑定个人远程仓库
git remote add origin <你的仓库地址>

REM 把当前分支改名为 main
git branch -M main

REM 推送并建立跟踪关系
git push -u origin main
```

### 绝对不能提交的东西

```text
node_modules/     依赖，可以用 npm install 重新装
.env              含真实密码和密钥
*.sqlite          数据库运行文件
dist/ build/      构建产物
logs/ backups/    运行记录
```

这些在 `.gitignore` 里都已经配好了。**如果 `.env` 不小心提交过，仅仅删掉文件是不够的——必须立刻更换里面所有的密码和密钥**，因为 Git 历史里还留着。

### 常见 Git 问题

|现象|处理|
|---|---|
|`git pull --ff-only` 失败|本地有未推送的提交，先 `git log --oneline origin/main..HEAD` 看是什么，再请教师处理|
|`push` 被拒绝，提示 non-fast-forward|远程有别人的提交，先 `git pull --ff-only`|
|提交了不该提交的大文件|停下来找教师，不要自己乱用 `reset --hard`|
|不小心在模板仓库上提交|检查 `git remote -v`，模板应该叫 `template`，个人仓库才叫 `origin`|

## 6. 端口被占用

```cmd
REM 查出是哪个进程占着 3003 端口
netstat -ano | findstr :3003

REM 用上一条命令最后一列的 PID 结束它（把 <PID> 换成真实数字）
taskkill /F /PID <PID>
```

最常见的原因是上一次课的后端终端没关。开始新一课前，先把旧终端全部关掉。

## 7. npm 常见问题

|现象|原因|处理|
|---|---|---|
|`npm install` 很慢或超时|网络问题|换用校园网或配置镜像源|
|装完还是提示找不到模块|在错误的目录执行了安装|第 12 课要分别在 `backend` 和 `frontend` 装；第 13、15 课在根目录装一次即可|
|`EBADENGINE` 警告|Node 版本不对|装 Node 24|
|想彻底重来|依赖树坏了|删掉 `node_modules` 后重新 `npm install`|

```cmd
REM 彻底重装依赖
rmdir /s /q node_modules
npm install
```

## 8. 部署路线总览

|课次|部署方式|产物|
|---|---|---|
|12|本机运行为主|前后端在本机 3000 / 3003|
|13|本机运行为主|同上，数据进入 SQLite 文件|
|14|Ubuntu + systemd + Nginx|后端注册为系统服务，Nginx 反代 `/api`|
|15|Ubuntu + Docker Compose|一条命令拉起全栈，宿主 Nginx 反代到 3100|

第 14、15 课的详细部署步骤分别见：

- `../PersonaLink_MySQL/docs/Ubuntu24.04从GitHub部署与零丢数据迁移教程.md`
- `../PersonaLink_Docker/docs/deploy-ubuntu.md`

部署三条铁律：

1. **服务器上的 `.env` 单独写，密码和本机不同。**不要把本机的 `.env` 传上去。
2. **上线第一天就把备份跑通，并真的恢复一次。**没验证过恢复的备份不算备份。
3. **数据库不要对公网开放端口。**只允许应用所在的机器连接。
