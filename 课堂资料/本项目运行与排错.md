## 2. 常用命令

```cmd
REM 安装依赖（本地开发）
npm install
REM 严格按 lock 文件安装（CI 和服务器用）
npm ci

REM 启动前端，5173
npm run dev
REM 启动后端，3030
npm run dev:api

REM 项目自检：关键功能是否都还在
npm run check
REM 扫描仓库里有没有疑似密钥
npm run check:secrets
REM 跑全部测试
npm test
REM 构建静态产物到 dist/
npm run build
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`npm` 管理项目依赖并执行脚本；`install` 安装依赖（有兼容的锁文件时使用锁定版本）；`ci` 严格按锁文件安装并重建 node_modules；`run 名称` 执行当前 package.json 的 scripts 中同名命令；`test` 是运行测试脚本。先确认终端所在目录有本课 package.json。服务启动后持续占用终端是正常的，另开终端做下一步，Ctrl+C 才停止服务。
<!-- COMMAND_HELP:END -->


后端改了 `.env` 必须重启才生效（`.env` 只在启动时读一次）。

## 4. 用 curl 测接口时的中文坑

Windows 终端里把中文直接写进 `curl -d "…"`，中文常常被终端编码弄坏，服务端会误报"请选择有效场景"。

**把请求体写进一个 UTF-8 文件再发：**

```cmd
curl.exe -i -X POST http://127.0.0.1:3030/api/greeting -H "Content-Type: application/json" --data-binary @req.json
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`curl.exe` 是发送 HTTP 请求的程序，在终端运行，不在浏览器地址栏输入。`-i` 同时显示状态行和响应头；`-X` 指定请求方法（GET 读取、POST 提交、DELETE 删除）；`-H` 添加请求头；`-d` 发送请求体；`--data-binary @文件名` 原样发送文件内容。`Content-Type: application/json` 告诉后端内容是 JSON；`Authorization: Bearer 令牌` 携带当前用户身份。`-f` 遇到 HTTP 错误返回失败退出码，`-sS` 隐藏进度但保留错误，`-L` 跟随跳转，`-o` 指定下载文件。示例里的中文编号/令牌必须替换成自己的值。CMD 的行尾 `^` 表示下一行仍是同一条命令，符号后不能有空格；PowerShell 不使用这种续行符。
<!-- COMMAND_HELP:END -->


先在工程根目录用编辑器新建 `req.json`，以 UTF-8 保存下面内容；然后在同一目录的 CMD 或 PowerShell 执行上面的命令（不要在浏览器地址栏输入）。

```json
{"receiver":"同学","occasion":"感谢","tone":"真诚","details":"谢谢帮助"}
```

`@req.json` 表示从文件读取请求体，不是把文件名作为文案。应看到 HTTP 状态行和 JSON；没有模型密钥时 `mode` 为 `fallback` 是正常兜底。`req.json` 是本机调试临时文件，测完可删除，不要提交。

## 5. HTTP 状态码速查

|状态码|含义|本项目里什么时候出现|
|---|---|---|
|200|成功|正常生成文案|
|400|请求格式或内容不合格|没填称呼、场景不在白名单、补充信息超长|
|413|请求体过大|有人塞了超过 20KB 的内容|
|422|格式没问题但内容不予处理|输入命中了不适合做贺卡的词|
|429|请求过于频繁|一分钟内超过 12 次|
|500|服务端内部错误|后端代码抛异常，去看后端终端|

## 6. Git 标准流程

```cmd
REM 先看改了什么
git status
REM 确认 .env、node_modules、dist、req.json 都不在列表里
git add .
git commit -m "P4第X课：一句话说明本次改动"
git push origin main
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`git` 管理版本；`status` 查看改动；`diff` 查看逐行差异；`add` 选择待提交文件；`commit -m` 创建本地版本并写说明；`push` 发到远端；`clone` 下载仓库，`--branch` 选择分支，`--single-branch` 只取该分支历史；`remote` 管理远端别名，`fetch` 只取回记录。命令中的 `.` 表示当前目录，`--` 后面是文件路径。推送前用 `git remote -v` 核实 origin 是自己的仓库。
<!-- COMMAND_HELP:END -->


第一次从课堂仓库克隆后，先检查远端；保留课程来源，再绑定个人仓库：

```cmd
git remote -v
REM 仅当 origin 仍是课堂仓库、且还没有 course 远端时执行下一行
git remote rename origin course
git remote add origin <你的个人仓库地址>
git branch -M main
git push -u origin main
```

### 绝对不能提交的东西

```text
node_modules/   依赖，npm install 能装回来
dist/           构建产物，npm run build 能生成
.env            含真实密钥
req.json        本机调试临时文件
```

**`.env` 一旦提交过，仅仅删文件没用**——Git 历史里还在。必须去平台后台**作废这个密钥重新生成**。

## 7. CI/CD

GitHub Actions 的完整入门见 `../../01_入门与通用规范/05_CI-CD与部署配置.md`。

本项目的工作流在 `.github/workflows/ci.yml`，一共七步：拉代码 → 装 Node 24 → `npm ci` → `npm run check` → `npm test` → `npm run build` → `npm run check:secrets`。

```cmd
npm ci
npm run check
npm test

```

## 8. 部署

|方式|适用|说明|
|---|---|---|
|Ubuntu 前后端同源部署|课堂主线，每课可体验|Nginx 同时反代 `/api/` 和 `/c/`，卡片存入持久目录；未完成安全任务时用 SSH 隧道访问。步骤见 `Ubuntu部署实操.md`|
|GitHub Pages / Surge|可选静态展示|只上传 dist 无后端；可用前端兜底生成文案，但不能保存服务端分享链接|
|Netlify Functions + Blobs|选学完整部署|不是“只上传静态页”；需要函数和存储环境，本地文件不会自动同步到 Blobs|

只做静态部署时，远程生成请求失败后使用本地文案兜底，不能把生成出文字当成“模型调用成功”。分享保存需要后端。第1、2课的完整基线检查可能因后续占位而失败，应以本课逐项验收为准；第3课全部完成后再要求完整检查通过。

## 10. 通用排错

|现象|原因|处理|
|---|---|---|
|`node -v` 不是 v24|装了别的版本|重装 Node 24 LTS，关掉所有终端重开|
|端口被占用|上次的进程还在|`netstat -ano \| findstr :3030` 找到 PID，`taskkill /F /PID <PID>`|
|改了代码页面不更新|文件没保存，或改的不是当前工程|Ctrl+S；确认 Trae 打开的是自己的工程目录|
|页面白屏|代码有语法错误|看终端**第一条**报错，从第一条开始改|
|`npm install` 很慢|网络问题|换网络或配置镜像源|
|依赖树坏了|各种奇怪报错|删掉 `node_modules` 后重新 `npm install`|
