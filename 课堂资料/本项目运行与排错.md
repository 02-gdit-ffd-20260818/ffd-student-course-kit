## 先选最简单的运行方法

本包主线使用本地相对路径和普通脚本。**统一用本地服务器打开页面，不要双击 HTML**：

**Windows CMD**

```bat
REM 在自己的工程目录下执行，先确认看得到 index.html
dir index.html
npx live-server --port=7000 --host=0.0.0.0
```

**Windows PowerShell**

```powershell
Get-ChildItem index.html
npx live-server --port=7000 --host=0.0.0.0
```

看到 `Ready for changes` 才算起来了，浏览器访问 <http://localhost:7000>。
**保存代码后页面自动刷新**，不用手动按。停止服务在该终端按 `Ctrl + C`。

每课手册第 3 节有完整说明（含参数含义、局域网访问、启动失败怎么办）。

不要双击 `.js`，也不要把网页代码粘贴到命令行。

只有需要模拟网站地址时，才用下面的 Node 服务。安装 Node 后重开终端。该服务不依赖 npm 包。

## 终端 A：只运行网页服务

平台：Windows CMD / PowerShell 通用。位置：自己的 p1-homepage。

```text
node --version
npx live-server --port=7000 --host=0.0.0.0
```

第一行检查 Node 是否可用；第二行通过 npx 临时运行 live-server，不需要项目携带 tools 或 node_modules。命令不会立刻返回提示符，这是正常的。浏览器输入 http://127.0.0.1:7000/。终端 A 保持运行，停止时按 Ctrl+C。

进入目录的 CMD 版（在 CMD 任意目录运行）：

```bat
rem /d 允许同时改变盘符；引号保护带空格的用户名。
cd /d "%USERPROFILE%\Desktop\web-work\p1-homepage"
```

进入目录的 PowerShell 版（任意目录运行）：

```powershell

# 按当前用户目录拼出个人工程路径。
Set-Location -LiteralPath (Join-Path $env:USERPROFILE 'Desktop/web-work/p1-homepage')
```

## 终端 B：编辑时查看 Git

重新按 Windows 键搜索 cmd，或在 VS Code 的终端右上角点“+”。新窗口再次进入上面的个人工程目录。

平台：CMD / PowerShell 通用。

```text
git status
git diff
```

status 看哪些文件变了；diff 看已被 Git 跟踪的文件内容变化，新文件还未暂存时不会出现在普通 diff 中。确认无误后按课件 add、commit、push。不要把 Git 命令输入到还在运行 Node 的终端 A。

## 两条路线是怎么设计的（六次课通用，先读这一节）

每次课都有两条路线，最后做同一组任务、交同一组证据：

- **路线 A：带着自己上一课的作品继续做。** 适合正常跟得上的同学，你的个人风格会一直累积下去。
- **路线 B：直接克隆本课模板从零开始。** 适合缺课、没有个人作品或者工程弄坏了的同学。

### 路线 A 每次课都要先做一件事：领取本课新增的文件

本课模板里常常会多出一两个上一课**根本不存在**的文件，比如第 4 课的 `app.js`、
第 5 课的 `works-data.js`。路线 B 的模板里已经有了；**路线 A 的你没有，必须先领**。

各课手册里都有一节叫「路线 A 领取本课文件」，命令长这样：

```text
git remote add course https://github.com/02-gdit-ffd-20260818/ffd-student-course-kit.git
git fetch course p1-lXX-standalone-v3.0
git checkout course/p1-lXX-standalone-v3.0 -- 本课新增的文件名
```

三条命令分别是：记下教师模板仓库的位置、把本课分支取下来、**只把列出的那几个文件**签出到自己的工程里。
最后一条不会覆盖你自己改过的其它文件。

`git remote add course ...` 只在第一次需要；提示 `remote course already exists` 就跳过这一条。

### 顺序很重要：先领文件，确认到手，再加引用

三步一步都不能跳：

```text
1. 领文件   git checkout course/分支 -- 文件名
2. 确认到手  dir 文件名        ← 看到文件名和大小才算领到
3. 加引用    在 index.html 里加上对应的 <link> 或 <script>
```

**跳过第 2 步是最常见的坑**：领取命令看起来跑完了，其实失败了（网络不通、分支名打错、
不在工程根目录），你却已经在 `index.html` 里加好了 `<script src="app.js"></script>`。
结果是页面上那个功能完全不工作，控制台报 `404` 或 `Uncaught ReferenceError`，
而你会以为是自己代码写错了。

**判断方法：** 浏览器 F12 → Network，刷新页面。引用的文件如果是红色 404，
说明文件根本不在，不是代码问题。

新领到的 `.css` 和 `.js` **不会自动生效**，`index.html` 里必须有对应的引用行。
模板里那一行是写好的，你自己的 `index.html` 里没有，需要手动加。各课手册都写明了加哪一行、加在哪个位置。

### 第 6 课的自检脚本能一次查出这类问题

```text
node tools/check-page.mjs
```

它会把 `index.html` 里每一个本地引用都对着文件系统核一遍，缺哪个直接报文件名：

```text
  [X]  引用了不存在的文件：app.js
```

第 6 课才领到这个脚本，但**前面几课积累的引用错误它都能查出来**。
第 6 课第一次跑不通是正常的，正好在那一课把前面的问题一次清掉。

### 任务文件用完要收尾

第 2、3 课会用到 `lesson-0X-task.css` 这类**本课专用练习文件**。
完成任务后要把规则并进 `styles.css`，删掉文件和那一行引用——教师答案里没有这个文件。
不收尾的话，你的工程会一课比一课偏离标准答案，后面排错会很难说清问题出在哪。

### 什么时候该果断改走路线 B

出现下面任何一种情况，不要硬撑，直接用本课模板重新开始：

- 上一课的工程打不开、或者页面整个崩了
- 领取文件的命令反复失败，十分钟内解决不了
- 自己也说不清工程现在和标准答案差在哪

**课程设计上任何一课都能独立开始，走路线 B 不扣分。** 卡在环境问题上耗掉一整节课才是真损失。

## 快速排错

| 现象 | 检查与操作 |
|---|---|
| 找不到 git / node | 软件安装后关闭并重新打开终端，重新执行 --version |
| 浏览器显示源代码或 txt | 打开文件资源管理器“查看 → 显示 → 文件扩展名”，确认真正文件名为 index.html |
| 文件保存后没变化 | 确认编辑与打开的是同一个工程目录；确认 live-server 的终端还开着（显示 `Ready for changes`）；仍不变按 Ctrl+F5 |
| EADDRINUSE | 另一个窗口已经运行服务；使用已有网址或先在旧窗口 Ctrl+C |
| 图片本地有、上线没了 | 检查文件是否 git add 并 push；核对大小写；不用 C:\ 开头的路径 |
| 网页能开但 JS 没效果 | F12 → Console 看第一条错误；检查 defer、脚本文件名和加载顺序 |
| Git 不知道是谁 | 在个人工程中按第一课身份配置页配置 user.name 和 user.email |
| 无法推送 | git remote -v 看是否自己的仓库；记录错误，不执行强推 |
| GitHub 无法访问 | 提前取得学生 ZIP，先本地运行和 commit，恢复联网后 push；没有虚构 Gitee 镜像地址 |

## 其他操作环境

Git Bash 可作为第三种环境；本包不混用其 `cp`、`$HOME` 和 Windows 指令。Ubuntu Bash 专用命令在 Ubuntu 附录。VS Code 内置终端只是窗口，先看右上角是 cmd 还是 PowerShell，再选对应命令。学生本轮统一一种即可。
