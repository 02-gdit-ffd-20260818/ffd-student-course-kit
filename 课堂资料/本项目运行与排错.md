# 期末三课：集成发布与两次答辩

第 16—18 课不再做新功能，而是把一学期的成果**集成、上线、讲清楚**。

|课次|手册|这一课做什么|
|---|---|---|
|第 16 课|[集成发布](<第16课_集成发布_操作手册.md>)|把各项目的最终版本整理好、打标签、上线，并逐项验收线上地址|
|第 17 课|[产品答辩](<第17课_产品答辩_操作手册.md>)（考核一）|**当场打开真实网址**演示：给谁用、解决什么问题、收到了什么反馈|
|第 18 课|[工程答辩](<第18课_工程答辩_操作手册.md>)（考核二）|讲清 Git 历史、测试、部署与恢复；**现场改一处并通过测试**；解释关键代码|

## 评分标准在哪里

两次答辩的评分量规、每周完成定义（DoD）、版权隐私安全清单，统一在
[评分量规与通用清单](<通用/07_评分量规与通用清单.md>)。
**第 16 课就把评分量规发给学生**，让他们知道按什么标准准备，而不是答辩当天才看见。

## 三课共同的底线

- 线上地址**必须能匿名打开**；打不开时要拿得出故障证据和处理记录。
- Git 历史要**可核验**：有意义的提交，而不是最后一天一次性上传。
- **用 AI 写代码不扣分，用了却讲不清楚才扣分**——所以平时的 Agent 日志要坚持写，
  尤其是"拒绝的建议及理由"那一栏。

[小白从空文件夹到公网](<通用/02_小白从空文件夹到公网_完整操作手册.md>)。
