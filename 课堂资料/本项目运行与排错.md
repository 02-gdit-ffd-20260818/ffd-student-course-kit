## 1. 统一约定

|项目|约定|
|---|---|
|Node 版本|24 LTS|
|IDE|Trae|
|工作区|`C:\Users\<用户名>\Desktop\web-work\p4-card\`|
|前端端口|5173（Vite 默认）|
|后端端口|3030|
|数据库|**没有**。贺卡不落库，分享靠 URL 片段|

每节课第一条命令都是 `node -v`，必须是 `v24.` 开头。

## 2. 常用命令

```cmd
npm install          REM 安装依赖（本地开发）
npm ci               REM 严格按 lock 文件安装（CI 和服务器用）

npm run dev          REM 启动前端，5173
npm run dev:api      REM 启动后端，3030

npm run check        REM 项目自检：关键功能是否都还在
npm run check:secrets REM 扫描仓库里有没有疑似密钥
npm test             REM 跑全部测试
npm run build        REM 构建静态产物到 dist/
```

后端改了 `.env` 必须重启才生效（`.env` 只在启动时读一次）。

## 4. 用 curl 测接口时的中文坑

Windows 终端里把中文直接写进 `curl -d "…"`，中文常常被终端编码弄坏，服务端会误报"请选择有效场景"。

**把请求体写进一个 UTF-8 文件再发：**

```cmd
curl -X POST http://127.0.0.1:3030/api/greetings/generate -H "Content-Type: application/json" --data-binary @req.json
```

`req.json` 是本机调试用的临时文件，测完删掉，不要提交。

## 5. HTTP 状态码速查

|状态码|含义|本项目里什么时候出现|
|---|---|---|
|200|成功|正常生成文案|
|400|请求格式或内容不合格|没填称呼、场景不在白名单、补充信息超长|
|413|请求体过大|有人塞了超过 20KB 的内容|
|422|格式没问题但内容不予处理|输入命中了不适合做贺卡的词|
|429|请求过于频繁|一分钟内超过 12 次|
|500|服务端内部错误|后端代码抛异常，去看后端终端|

## 6. Git 标准流程

```cmd
git status                     REM 先看改了什么
REM 确认 .env、node_modules、dist、req.json 都不在列表里
git add .
git commit -m "P4第X课：一句话说明本次改动"
git push origin main
```

第一次推到个人仓库：

```cmd
git remote add origin <你的仓库地址>
git branch -M main
git push -u origin main
```

### 绝对不能提交的东西

```text
node_modules/   依赖，npm install 能装回来
dist/           构建产物，npm run build 能生成
.env            含真实密钥
req.json        本机调试临时文件
```

**`.env` 一旦提交过，仅仅删文件没用**——Git 历史里还在。必须去平台后台**作废这个密钥重新生成**。

## 7. CI/CD

GitHub Actions 的完整入门见 `../../01_入门与通用规范/05_CI-CD与部署配置.md`。

本项目的工作流在 `.github/workflows/ci.yml`，一共七步：拉代码 → 装 Node 24 → `npm ci` → `npm run check` → `npm test` → `npm run build` → `npm run check:secrets`。

推送前先在本地把这五条跑一遍，本地都过不了，推上去一定失败：

```cmd
npm ci
npm run check
npm test
npm run build
npm run check:secrets
```

## 8. 部署

|方式|适用|说明|
|---|---|---|
|Netlify 静态部署|课堂默认|只有前端，生成功能不可用，其余功能正常。配置已在 `netlify.toml`|
|Ubuntu 前后端同源部署|进阶/选做|前端构建产物交给 Nginx，`/api` 反代到 3030 的 Node 进程。步骤见 `../Ubuntu部署实操.md`|

只做静态部署时，"生成祝福"会失败但页面不崩——**这是本项目有意设计的降级，课上要说清楚，不要当成 bug。**

## 10. 通用排错

|现象|原因|处理|
|---|---|---|
|`node -v` 不是 v24|装了别的版本|重装 Node 24 LTS，关掉所有终端重开|
|端口被占用|上次的进程还在|`netstat -ano \| findstr :3030` 找到 PID，`taskkill /F /PID <PID>`|
|改了代码页面不更新|文件没保存，或改的不是当前工程|Ctrl+S；确认 Trae 打开的是自己的工程目录|
|页面白屏|代码有语法错误|看终端**第一条**报错，从第一条开始改|
|`npm install` 很慢|网络问题|换网络或配置镜像源|
|依赖树坏了|各种奇怪报错|删掉 `node_modules` 后重新 `npm install`|
