# 环境准备与软件工具安装指南

> 第一次接触命令行、GitHub 或部署？安装完成后不要自己猜下一步，直接打开 [小白从空文件夹到公网：完整操作手册](<02_小白从空文件夹到公网_完整操作手册.md>)，照着“点哪里、输什么、看到什么”完成第一次仓库。

> 适用课程：《前端框架应用开发》V4.0  
> 建议统一环境：Windows 10/11 64 位、Node.js 24 LTS、npm 11、Git、VS Code、Chrome 或 Edge。  
> 更新日期：2026-09-02

本文档把工具分成“必须”、“推荐”和“按需”三类。学生完成前 10 次课只需必须项；Docker、WSL、Nginx 和云服务仅在全栈部署阶段使用。

## 2. Windows 一键准备（推荐）

1. 在资源包根目录打开 PowerShell。
2. 先检查，再安装：

```powershell

# 检查 Git、Node、npm、GitHub CLI 和 SQLite 等课程工具。

# 通过课程脚本安装或补齐 Windows 工具；请阅读提示后确认安装项。
.\01_入门与通用规范\环境脚本\setup-windows.ps1 -Install
```

3. 关闭并重新打开终端，再执行：


`setup-windows.ps1` 默认处理课程必须工具、VS Code 扩展和项目内 SQLite CLI。使用 `-IncludeOptional` 时只会尝试安装 GitHub CLI、DB Browser for SQLite；Docker 因涉及虚拟化、授权条款和重启，仍需按第 7 节单独确认。

## 3. Windows 手动安装

### 3.1 VS Code

1. 打开 <https://code.visualstudio.com/download>。
2. 选择 Windows x64 `User Installer`；机房统一管理时才选 `System Installer`。
3. 安装时勾选“添加到 PATH”、“添加到右键菜单”。
4. 新开 PowerShell，运行 `code --version`。

扩展可在 VS Code 扩展面板中安装，也可批量执行：

```powershell
# 逐行读取扩展 ID，并调用 VS Code 命令安装课程推荐扩展。
Get-Content .\01_入门与通用规范\环境脚本\vscode-extensions.txt | ForEach-Object { code --install-extension $_ }
```

必需扩展：Vue - Official (Volar)、ESLint、Prettier、Live Server、REST Client、SQLite Viewer、GitHub Pull Requests。中文语言包可选。不要同时启用 Vetur 和 Vue - Official。

### 3.2 Node.js 24 LTS 与 npm

1. 打开 <https://nodejs.org/en/download>。
2. 选 LTS、Windows x64 `.msi`，保留“Add to PATH”和 npm 默认选项。
3. 重开终端并检查：

```powershell
# 显示 Node.js 版本。
node --version
# 显示 npm 版本。
npm --version
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`node` 在终端运行 JavaScript；后接文件路径就是执行该文件；`-v` 只显示版本；`-e` 执行后面引号内的代码；`--check` 只检查语法；`--watch` 监测文件变化并重启。`console.log(...)` 把括号内的结果打印出来，函数调用的参数写在括号里，多个参数用逗号分开。
<!-- COMMAND_HELP:END -->


课程锁定 Node 24（根目录 `.nvmrc`）。已使用 nvm-windows 的开发者可执行 `nvm install 24` 和 `nvm use 24`；初学者不必另装 nvm。

### 3.3 Git 与 GitHub

1. 从 <https://git-scm.com/install/windows> 安装 Git for Windows。
2. 默认分支选 `main`，编辑器选 VS Code，其余初学者保留默认。
3. 配置真实姓名/学号邮箱：

```powershell
# 交互读取姓名和 GitHub 已验证邮箱。
$gitUserName = Read-Host '请输入你的姓名'
# 读取 GitHub 已验证邮箱。
$gitUserEmail = Read-Host '请输入你的 GitHub 已验证邮箱'
# 设置 commit 作者姓名。
git config --global user.name $gitUserName
# 设置 commit 作者邮箱。
git config --global user.email $gitUserEmail
# 把新仓库默认分支统一为 main。
git config --global init.defaultBranch main
# 在 Windows 上签出 CRLF、提交 LF，减少跨平台换行差异。
git config --global core.autocrlf true
# 显示 Git 版本。
git --version
# 显示全局 Git 配置；检查输出中不要包含凭据或 token。
git config --global --list
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`git` 管理版本；`status` 查看改动；`diff` 查看逐行差异；`add` 选择待提交文件；`commit -m` 创建本地版本并写说明；`push` 发到远端；`clone` 下载仓库，`--branch` 选择分支，`--single-branch` 只取该分支历史；`remote` 管理远端别名，`fetch` 只取回记录。命令中的 `.` 表示当前目录，`--` 后面是文件路径。推送前用 `git remote -v` 核实 origin 是自己的仓库。
<!-- COMMAND_HELP:END -->


在 <https://github.com/> 注册账号、验证邮箱并开启两步验证。如使用 GitHub CLI：

```powershell
# 启动 GitHub CLI 登录向导，依次选择 GitHub.com、HTTPS 和浏览器登录。
gh auth login
# 显示当前 GitHub CLI 登录账号和权限范围，不显示 token 值。
gh auth status
```

选择 `GitHub.com` → `HTTPS` → 浏览器登录。不要在聊天、截图、仓库或课堂投影中暴露 Token。

### 3.4 SQLite

项目脚本会从 <https://sqlite.org/download.html> 下载官方 Windows x64 CLI 到 `.tools/sqlite`。也可手动下载 `sqlite-tools-win-x64-*.zip`，解压后把 `sqlite3.exe` 所在目录添加到 PATH。

```powershell
# 仅在当前 PowerShell 会话把课程自带 sqlite3 加入命令搜索路径。
$env:Path = "$PWD\.tools\sqlite;$env:Path"
# 显示 SQLite 版本，确认命令可用。
sqlite3 --version
# 建一张最简单的表，确认 sqlite3 能创建数据库。
sqlite3 demo.db "CREATE TABLE IF NOT EXISTS demo(id INTEGER PRIMARY KEY, name TEXT);"
# 列出 demo.db 中的表，确认初始化成功。
sqlite3 demo.db ".tables"
```

`demo.db` 仅用于本地练习，已被 `.gitignore` 忽略。

## 4. macOS 安装

有 Homebrew 时：

```bash
# 使用 Homebrew 安装 Visual Studio Code。
brew install --cask visual-studio-code
# 安装 Node.js 24、Git、GitHub CLI 和 SQLite。
brew install node@24 git gh sqlite
# 把 Node.js 24 路径追加到当前用户 zsh 配置；重复执行前先检查是否已有同一行。
echo 'export PATH="/opt/homebrew/opt/node@24/bin:$PATH"' >> ~/.zshrc
# 重新加载 zsh 配置，让当前终端立即识别 Node.js。
source ~/.zshrc
# 分别显示四个工具版本。
node -v
# 显示 npm 版本。
npm -v
# 显示 Git 版本。
git --version
# 显示 SQLite 版本。
sqlite3 --version
# 启动 GitHub CLI 登录向导。
gh auth login
```

Intel Mac 的 Homebrew 路径通常是 `/usr/local`。如不使用 Homebrew，请从 Node.js、Git 和 VS Code 官网安装。

## 5. Ubuntu/Debian 安装

Node.js 建议用 nvm 安装，避免系统仓库版本过旧；安装 nvm 前先核对 <https://github.com/nvm-sh/nvm> 的最新发布与安装脚本。

```bash
# 刷新 Ubuntu 软件包索引，不安装软件。
sudo apt update
# 安装 Git、SQLite、curl 和证书包。
sudo apt install -y git sqlite3 curl ca-certificates
# 按 nvm 官方 README 安装 nvm 后：
# 安装 Node.js 24。
nvm install 24
# 让当前终端使用 Node.js 24。
nvm use 24
# 分别显示四个工具版本。
node -v
# 显示 npm 版本。
npm -v
# 显示 Git 版本。
git --version
# 显示 SQLite 版本。
sqlite3 --version
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`curl.exe` 是发送 HTTP 请求的程序，在终端运行，不在浏览器地址栏输入。`-i` 同时显示状态行和响应头；`-X` 指定请求方法（GET 读取、POST 提交、DELETE 删除）；`-H` 添加请求头；`-d` 发送请求体；`--data-binary @文件名` 原样发送文件内容。`Content-Type: application/json` 告诉后端内容是 JSON；`Authorization: Bearer 令牌` 携带当前用户身份。`-f` 遇到 HTTP 错误返回失败退出码，`-sS` 隐藏进度但保留错误，`-L` 跟随跳转，`-o` 指定下载文件。示例里的中文编号/令牌必须替换成自己的值。CMD 的行尾 `^` 表示下一行仍是同一条命令，符号后不能有空格；PowerShell 不使用这种续行符。
<!-- COMMAND_HELP:END -->


VS Code 请使用 <https://code.visualstudio.com/docs/setup/linux> 的官方 `.deb` 或软件源方法。

克隆或解压仓库后，先进入资源包根目录。只使用仓库选定的 npm，不要混用 npm/pnpm/yarn，不要全局安装 Vue/Vite。

```powershell
# 扫描课程项目并根据各自 package-lock.json 安装依赖。
.\01_入门与通用规范\环境脚本\install-project-dependencies.ps1
```

手动方式：

```powershell
# 进入项目 5 的工程基线（一个标准的 Vite + Vue 工程）。
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`cd` / `Set-Location` 切换终端当前目录；含空格的路径用引号包起来。CMD 的 `/d` 同时切换盘符；PowerShell 用 `Set-Location "路径"`，不加 `/d`。

安装新项目常用依赖（只在相应项目目录中执行）：

```powershell
# 安装课堂主线需要的 Router、Pinia、Axios 和 ECharts 运行依赖。
npm install vue-router@latest pinia@latest axios@latest echarts@latest
# 安装 ESLint、Prettier、Vitest 和 Vue Test Utils 开发依赖。
npm install -D eslint@latest prettier@latest vitest@latest @vue/test-utils@latest
```

创建新 Vue 项目：

```powershell
# 用 Vite 官方脚手架创建名为 my-app 的 Vue 项目。
npm create vite@latest my-app -- --template vue
# 进入新项目目录。
cd my-app
# 首次生成并安装项目依赖。
npm install
# 启动本地开发服务器。
npm run dev
```

不执行来源不明的 `curl ... | bash`、PowerShell 一键脚本或 npm 包。安装前检查官方域名、维护者、许可证和最近更新。

## 7. 部署阶段按需工具

### Docker Desktop / WSL 2

只在课程要求容器或本地 Linux 生产环境时安装。安装前确认 Windows 版本、BIOS/UEFI 虚拟化、至少 8 GB 内存以及学校机房管理策略。

```powershell
# 管理员 PowerShell，首次启用可能要求重启
# 安装 Windows Subsystem for Linux 及默认发行版。
wsl --install
# 更新 WSL 组件。
wsl --update
# 显示 WSL 版本和内核信息。
wsl --version
```

重启后从 <https://docs.docker.com/desktop/setup/install/windows-install/> 安装 Docker Desktop，选 WSL 2 后端。教育用途仍应阅读 Docker Desktop 当期授权条款。

```powershell
# 显示 Docker 客户端和服务端版本；服务端不可用时先启动 Docker Desktop。
docker version
# 运行官方最小容器测试，结束后自动删除测试容器。
docker run --rm hello-world
```

<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

`docker compose` 读取当前工程的 Compose 配置；`up` 创建并启动服务；`-d` 后台运行；`--build` 启动前构建；`ps` 看状态；`logs -f` 跟随日志；`exec 服务名 命令` 在运行容器内执行；`down` 停止并删除容器但保留命名卷；`down -v` 还会删除数据卷；`-f 文件` 选择配置文件，多个 `-f` 按顺序合并。
<!-- COMMAND_HELP:END -->


### Nginx 与 HTTPS

Nginx 建议安装在 Ubuntu 服务器/容器，不在学生 Windows 开发机上强制安装。参考 [CI-CD 与部署配置](<05_CI-CD与部署配置.md>) 第 9.4 节的 Nginx 反向代理配置，部署前必须替换域名、根目录和 API 端口，并配置 HTTPS、防火墙、日志轮转和回滚。

### 云平台

- 纯前端：GitHub Pages、Vercel、Netlify、Cloudflare Pages 或 EdgeOne Pages 选一。
- Node API：选学校批准的 Node 托管服务或 Linux 服务器。
- 数据库：本地 SQLite 不等于多实例云数据库；上云前设计备份、恢复、最小权限和数据保留策略。
- AI API：只用学校批准的模型服务；密钥只放服务器端 Secret/环境变量。

```powershell
# 运行课程环境总检查。
```


<!-- COMMAND_HELP:BEGIN -->
**本段命令怎么读**

- Chrome 或 Edge 可打开 DevTools。
- Vue 案例构建成功并生成 `dist`。

- Git 用户名和邮箱已配置，GitHub 已开启 2FA。

## 10. 常见问题

- **`node`/`code` 不是命令**：关闭所有终端和 VS Code 后重开；仍失败则重新安装并勾选 PATH。
- **PowerShell 禁止脚本**：只对当前窗口执行 `Set-ExecutionPolicy -Scope Process Bypass`，不要全局关闭安全策略。
- **`npm.ps1 cannot be loaded`**：同上，或在当前命令中使用 `npm.cmd`。
- **`npm install` 网络失败**：先检查校园网/代理/时钟，不要随意改成未受信任镜像或禁用 TLS校验。
- **5173/3000 端口占用**：用 `Get-NetTCPConnection -LocalPort 5173,3000` 查找进程，关闭自己启动的旧服务，或显式更换端口。
- **Vue 页面空白**：查看 DevTools Console 和 Network，确认在案例目录运行 `npm run dev`，不要直接双击 SFC/HTML。
- **Git 换行符大量变更**：Windows 统一使用 `core.autocrlf=true`，并保留项目 VS Code 的 LF 设置。
- **SQLite 锁定**：关闭同时打开数据库的 GUI/CLI；写操作使用事务并设置合理超时。
- **Docker 无法启动**：检查 `wsl --version`、Windows 可选功能、BIOS 虚拟化与内存；机房设备请联系管理员，不要自行修改 BIOS。
