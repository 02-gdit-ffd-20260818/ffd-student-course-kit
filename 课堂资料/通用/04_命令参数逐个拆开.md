# 命令参数逐个拆开（全课程共用）

课堂上敲的每一条命令，这里把**每个单词、每个参数**分别解释一遍，并写清楚
「这条命令到底改了什么、哪些东西它不会动」。看不懂某个参数就回来查这一份。

> 读法：命令里尖括号 `<像这样>` 的部分是**要你替换成自己的值**，替换时连尖括号一起删掉。

---

## 一、Git：把文件弄到自己电脑上

### `git clone --branch <分支> --single-branch <网址> <目录名>`

课堂上路线 B 的第一条命令。

|部分|意思|
|---|---|
|`clone`|克隆：把远程仓库完整复制一份到本地，并自动建好 `.git`|
|`--branch <分支>`|只要这一个分支，并且克隆完就停在它上面。不写的话会停在仓库的默认分支（`main`）|
|`--single-branch`|**只下载这一个分支的历史**。不写的话会把仓库里几十个分支全下下来，又慢又占空间|
|`<网址>`|要克隆哪个仓库|
|`<目录名>`|在当前位置新建这个文件夹装进去。不写的话会用仓库名当文件夹名|

执行后你会多出一个文件夹，里面就是本课的完整起点。**它是一个独立的 Git 仓库**，
和你原来的工程互不影响。

### `git remote rename origin template`

克隆之后紧接着的一条，**每次路线 B 都要做**。

|部分|意思|
|---|---|
|`remote`|远程仓库列表|
|`rename`|改名|
|`origin`|克隆时 git 自动给来源仓库起的默认代号|
|`template`|改成这个新代号|

**为什么非改不可**：`git push` 不写目标时默认推给 `origin`。克隆下来的 `origin`
指的是**全班共用的教师模板仓库**，一不小心就会把自己的作业推到公共仓库里去。
改名成 `template`（意思是"这只是模板"）之后，`git push origin main` 会直接报
"没有 origin"，反而是好事——它逼你先把 `origin` 指向自己的仓库。

用 `git remote -v` 随时确认：`template` 指公共模板，`origin` 指你自己的仓库。

### 领取本课新增的文件（路线 A 用，三条）

```text
git remote add course <教师模板仓库网址>
git fetch course <本课分支>
git checkout course/<本课分支> -- <文件名>
```

**① `git remote add course <网址>`——起个代号，不下载任何东西。**

|部分|意思|
|---|---|
|`remote` / `add`|远程仓库列表 / 新增一个|
|`course`|**你给它起的代号**，随便起都行，本课程统一叫 `course`|
|`<网址>`|教师模板仓库地址|

只往 `.git/config` 写一行配置，**不联网、不下载、一个文件都不变**。整个项目做一次就够。
提示 `remote course already exists` 就是做过了，跳过。

**② `git fetch course <本课分支>`——下载进 `.git`，工作目录还是看不到。**

|部分|意思|
|---|---|
|`fetch`|取回|
|`course`|从哪个仓库取（①起的代号）|
|`<本课分支>`|只取这一个分支，仓库里其它分支不碰|

**最容易被误解的一步**：跑完之后 `dir` 会发现新文件**还是不存在**。这不是失败——
`fetch` 只把内容存进 `.git` 这个"仓库数据库"，**没有写到你看得见的工作目录**。
取回来的东西在本地叫 `course/<本课分支>`。

**③ `git checkout course/<本课分支> -- <文件名>`——真正把文件写出来。**

|部分|意思|
|---|---|
|`checkout`|这里是"从某个版本里取出文件，写进工作目录"|
|`course/<本课分支>`|从哪个版本取|
|`--`|分隔符：**后面全是文件名，不是分支名**。不写它的话，万一有分支跟文件重名，git 就分不清了|
|`<文件名>`|要取的文件，空格并列写几个就取几个|

**只会拿到你点名的文件。** ②确实把整个分支下载到了 `.git`，但③只写出 `--` 后面列的文件，
其它文件一个都不会冒出来，**你自己改过的文件也不会被覆盖**。
取出来的文件自动进暂存区（相当于已 `git add`），直接 `git commit` 就能提交。

### `git pull --ff-only`

|部分|意思|
|---|---|
|`pull`|从远程取回**并合并**到当前分支（= `fetch` + `merge`）|
|`--ff-only`|只允许"快进"式合并：远程比本地多出来的提交直接接在后面。一旦需要真正合并（两边都有新提交）就**拒绝执行**|

加 `--ff-only` 是为了安全：初学阶段最怕自动合并产生冲突文件，宁可它报错停下来。

常见两种报错都不是你的错：

- `There is no tracking information` / `No remote repository specified`——
  这个工程只在你电脑上，还没推到 GitHub。**跳过这条命令**即可。
- `Not possible to fast-forward`——你本机有还没推上去的提交。先
  `git log --oneline origin/main..HEAD` 看看是什么，再请教师处理，**不要强行合并**。

## 二、Git：把自己的改动存起来、发出去

```cmd
git status                  REM 现在有哪些文件改了/新增了，什么都不改，随时可以跑
git add .                   REM 把当前目录下所有改动放进"暂存区"，. 就是"当前目录全部"
git commit -m "说明"         REM 把暂存区的内容存成一个版本；-m 后面是这次改了什么
git push origin main        REM 把本地 main 分支推到 origin 这个远程仓库
```

|部分|意思|
|---|---|
|暂存区|提交前的中转站。`add` 进去、`commit` 才真正存成版本。这样你可以只提交一部分改动|
|`-m`|message，提交说明。不写 `-m` 会弹出编辑器，初学阶段很容易卡在里面出不来|
|`origin`|推给哪个远程仓库（代号）|
|`main`|推本地的哪个分支|

**第一次推自己的仓库**，要先在 GitHub 上新建一个空仓库，然后：

```cmd
git remote add origin <你自己的仓库地址>   REM 告诉 git "我的仓库在这儿"
git branch -M main                        REM -M：把当前分支强制改名成 main
git push -u origin main                   REM -u：记住这次的目标，以后 git push 就够了
```

## 三、npm：装依赖、跑脚本

### 先分清 `node` 与 `npm`

- `node 文件名.js`：让 **Node.js 运行时**直接执行一个 JavaScript 文件。Node.js 让 JavaScript 不用浏览器也能在终端运行。
- `node -e "一段代码"`：不读取文件，直接执行引号里的 JavaScript；`-e` 是 `evaluate`（立即求值/执行）的缩写。
- `npm`：Node.js 配套的包与脚本管理工具。它负责安装依赖和读取 `package.json`，本身不是 JavaScript 运行时。
- `npm run dev:api`：在当前目录的 `package.json` → `scripts` 中找到 `dev:api`，再执行它右边定义的命令。脚本名不是系统自带命令。

### 随机密钥命令逐段读懂

```cmd
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

|部分|意思|
|---|---|
|`node`|启动 Node.js，准备执行 JavaScript|
|`-e`|直接执行后面引号中的一小段代码，不需要另建 `.js` 文件|
|`require('node:crypto')`|加载 Node.js 自带的密码学模块；这里没有安装第三方包|
|`.randomBytes(32)`|向操作系统申请 32 字节的密码学安全随机数据；不是固定示例，也不是普通随机数|
|`.toString('base64url')`|把二进制数据变成约 43 个可复制字符，并避开网址中容易出问题的字符|
|`console.log(...)`|把最终字符串打印到终端；最外层括号表示把里面的结果交给这个函数|

整条命令只会**生成并打印**一个新值，不会自动修改 `.env`。每执行一次结果都应不同；复制其中一行结果，
填到自己 `.env` 的 `SESSION_SECRET=` 后面即可。不要把真实值写回 `.env.example`，也不要提交到 Git。

```cmd
npm install         REM 按 package.json 装依赖，允许小版本升级；平时本地开发用
npm ci              REM 严格按 package-lock.json 装，装前先清空 node_modules；CI 和服务器用
npm run <脚本名>     REM 执行 package.json 里 scripts 段落定义的那条命令
npm test            REM npm run test 的简写，唯一可以省略 run 的几个之一
```

|为什么有两个安装命令|
|---|
|`install` 会在允许的范围内升到更新的小版本，所以两个人装出来的依赖可能不完全一样。`ci` 完全照 lock 文件，**装出来一定一模一样**——这正是 CI 和服务器需要的。代价是它不能只装一个包，也不会更新 lock 文件。|

常用参数：

|参数|意思|
|---|---|
|`--omit=dev`|不装开发依赖（测试、构建工具）。生产镜像和服务器上用，能小很多|
|`--workspace <名字>`|只对工作区里的某个子项目操作（本课程的项目 4、5 用到）|
|`--no-audit --no-fund`|不做安全审计、不打印赞助信息。纯粹为了输出干净、装得快些|

## 四、Windows 命令行

```cmd
cd /d "D:\某个目录"     REM /d 表示"连盘符一起切"。不加 /d 时从 C: 跳不到 D:
dir 文件名              REM 列出文件；能看到文件名和大小才说明文件真的在
dir /s /b "路径\文件名"  REM /s 连子目录一起找，/b 只打印完整路径不打印表头
copy 源 目标            REM 复制；成功会打印"已复制 1 个文件。"
type 文件名             REM 把文本文件内容打印出来，用来确认文件有内容
del 文件名              REM 删除文件
```

**为什么课堂上老让你 `dir` 或 `type` 一下**：上一条命令失败时往往只打印一行提示，
后面的步骤照样能执行，错误要到很久以后才暴露，那时已经很难回想是哪一步出的问题。
花两秒确认一下，能省掉半节课的排查。

## 五、Docker（项目 3 第 15 课）

```cmd
docker compose build            REM 按 compose.yaml 里的 build 段落构建镜像
docker compose up -d            REM 启动所有服务；-d 表示后台运行，不占着终端
docker compose up -d --build    REM 启动前先重新构建，改了代码要加 --build
docker compose ps               REM 看容器状态和健康检查结果
docker compose logs -f 服务名    REM 看日志；-f 表示持续跟着输出，Ctrl+C 退出
docker compose down             REM 停止并删除容器，**数据卷保留**
docker compose down -v          REM 连数据卷一起删，-v = volumes，数据会真的没了
docker compose exec 服务名 命令   REM 在正在运行的容器里执行一条命令
```

`down` 和 `down -v` 的区别正是这一课的核心结论：**容器可以随时扔掉重建，数据在卷里**。
加了 `-v` 就把卷也删了，下次启动会当成全新数据库重新初始化种子数据。

## 六、这些命令改了什么、没改什么

|命令|会改工作目录里的文件吗|会联网吗|
|---|---|---|
|`git remote add` / `rename`|不会|不会|
|`git fetch`|**不会**（只写 `.git`）|会|
|`git checkout <版本> -- <文件>`|会，但只改你点名的文件|不会|
|`git clone`|会，新建整个目录|会|
|`git add` / `commit`|不会（只动 `.git` 和暂存区）|不会|
|`git push`|不会|会|
|`git pull --ff-only`|可能会（把远程的新提交合进来）|会|
|`npm install` / `ci`|会改 `node_modules/`，不动你的源码|会|
