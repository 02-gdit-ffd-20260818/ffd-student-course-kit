# 评分量规与通用清单

> 三份表：**一份学生每次课自查**、**一份公开前必查**、**一份教师答辩打分**。
> 它们都是**跨课通用**的，不属于任何一个项目。
>
> 每一课的《课堂操作手册》末尾还有一张「本课交付清单」，那是**单次课**的要求；
> 这一页是**跨课通用**的底线。两者都要满足。

## 怎么配合课堂使用

|这一页的哪一节|给谁用|什么时候用|
|---|---|---|
|一、每周 DoD 清单|学生|**每次课最后 15 分钟**对照勾选|
|二、版权隐私安全清单|学生 + 教师|**任何作品要公开展示或上线之前**|
|三、双答辩评分量规|教师（**第 16 课就发给学生**）|第 17 课产品答辩、第 18 课工程答辩|

三个说明：

- **DoD 清单贴在每次课的最后 15 分钟。** 学生对照勾选，
  勾不满就说明这次课**没做完**，而不是"差不多了"。
- **版权隐私清单在三个时间点必查**：项目 1 第 6 课首次发布、
  项目 3 第 15 课上线、项目 5 涉及音源时。
  项目 5 的音源规则最严，详见
  [项目 5 总入口](../关联资料/02_教学资源包/06_项目5_星声音乐站_完整课堂包/README_项目5总入口.md) 的「版权边界」。
- **评分量规在第 16 课就发给学生**，让他们知道按什么标准准备，
  而不是答辩当天才第一次看见。

## 一、每周完成定义（DoD）

一次课结束前逐条对照。**勾不满就是没做完。**

- [ ] User Story、Issue、验收标准清楚。
- [ ] 页面/组件/数据/API 设计与本次范围匹配。
- [ ] **核心代码可解释**，Agent 记录完整。
- [ ] 正常、边界、失败测试均有结果。
- [ ] PR/commit 可追溯，CI 绿色，制品可下载。
- [ ] 线上 URL 可访问，部署后 smoke test 通过。
- [ ] README/CHANGELOG/Release 已更新。
- [ ] **重要数据有备份，知道怎样回滚或恢复。**
- [ ] 至少 1 条反馈进入下一版 Backlog。

> **第 3 条和第 8 条是最容易糊弄过去的两条，也是答辩时最容易被问倒的两条。**
> 「核心代码可解释」的标准是：能说清**为什么这么写**，不是能念出代码在做什么。

## 二、版权、隐私与密钥检查

**任何作品公开展示或上线之前，逐条确认。**

- [ ] 图片、字体、音乐、代码和数据来源已记录，**许可证允许当前用途**。
- [ ] 音乐项目只保存合法链接和业务状态，**不传播未授权音源**。
- [ ] 成员画像获得知情同意，**只采集完成任务所需字段**。
- [ ] `.env`、Token、数据库口令、真实个人数据
      **未进入仓库 / Prompt / 截图**。
- [ ] AI 输出已人工确认；有超时、失败回退和不当内容处理。
- [ ] 上传校验类型/大小/权限；接口验证输入与身份。

三条要特别强调的：

|条目|为什么它排在最前面|
|---|---|
|**许可证允许当前用途**|"网上能搜到"不等于"可以用"。免费预览和允许商用是两回事|
|**只采集必需字段**|**能不收集的数据就不收集**——这是隐私保护最有效的一条，比事后加一堆加密管用得多|
|**截图里也不能有密钥**|作业截图会发到群里、传到公开仓库。密钥泄露事故里有相当一部分是截图泄露的|

> **密钥一旦进了 Git 历史，删掉文件也没用**——历史里还在。
> 唯一的补救是**去控制台作废这把密钥重新签发**，而且要先做这一步再做别的。

## 三、双答辩评分量规

### 产品答辩（15 分）

|维度|分值|看什么|
|---|---|---|
|用户与问题|4|说得清给谁用、解决什么问题，不是"我做了一个网站"|
|线上演示|4|**当场打开真实 URL**，不是放录屏或截图|
|真实反馈与迭代|3|有真实用户用过，并且**至少一条反馈变成了改动**|
|表达与个人贡献|4|讲清楚哪些是你做的|

### 工程答辩（15 分）

|维度|分值|看什么|
|---|---|---|
|Git/CI/测试/部署/恢复证据|5|历史、CI 记录、测试结果、部署与恢复演练都拿得出来|
|**现场修改并通过测试与 CI**|5|当场改一处，跑通测试和 CI|
|关键代码与 AI 决策解释|5|能解释为什么这么写、哪些 AI 建议没采纳、为什么|

### 硬条件

**下面三条任何一条不满足，按教学计划中的硬性规则处理：**

1. 无可核验的 Git 历史；
2. 无可访问的 URL，且拿不出故障证据；
3. **不能解释 AI 生成的关键代码。**

> 第 3 条是这门课最重要的一条底线。
> 用 AI 写代码不扣分，**用了却讲不清楚才扣分**——
> 所以[工程文档模板](<06_工程文档模板与AI协作提示词.md>)里的 Agent 日志要坚持写，
> 尤其是「拒绝的建议及理由」那一栏。
